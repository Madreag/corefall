### M4A PR review hardening — settings source truth and manifest remap evidence

The latest PR review found two remaining source-truth gaps in the M4A closure surface. `act.settings.set` now clamps `ui_scale` at the shared settings mutation boundary (`0.5..4.0`), so `observe.settings`, `observe.accessibility.ui_scale_applied`, `run_manifest.json.settings.ui_scale`, and cf-ui's rendered `UiScale` agree instead of reporting a raw out-of-range value while rendering a clamped one. `cf-replay::SettingsBlock` and the run-manifest writer now persist `settings.key_bindings`, so M4A bundles record the actual remap table used by the cfctl script (`aim_up=Numpad8`, `fire=KeyF`, etc.) rather than only the `key_remap_enabled` flag.

### M4A audit closure round 6 — root-cause hardening for closure truth, ports, remap validation, and HUD readability

Round 5 still left five root-cause risks: dirty same-commit bundles could satisfy the close loop without proving they came from the current worktree, `cf-e2e` defaulted every spawned `cf-app` to fixed port 17900 (causing stale-listener/self-play failures), `act.settings.set` accepted unsupported remap actions/keys that cf-app would silently fall back from, the 8x8 capture sheet was too dense for fast human/agent readability review, and 200% HUD status/banners/captions could crowd the playable area instead of reflowing around it. The fixes landed in the shared paths:

1. **Closure evidence now binds to the current source state.** Run manifests include `build.worktree_dirty`, `build.worktree_fingerprint`, and `build.worktree_dirty_files`; the fingerprint covers tracked diffs plus untracked file contents. `bp_close_loop.sh` computes the current fingerprint, rejects dirty bundles without a matching fingerprint, and treats `SKIP_SWEEP` / `SKIP_GRADE` as non-closing diagnostic shortcuts. Fresh deterministic duplicates may reuse a filled current-source equivalent, but the loop never clones grading prose and never accepts stale same-commit dirty evidence.
2. **cf-e2e no longer collides on fixed ports.** `--control-port` now defaults to `0`, chooses an ephemeral local port, launches cf-app with that port, and connects to the same resolved endpoint. Explicit ports are still supported for manual debugging.
3. **ACC-A remap settings reject fake success.** `cf-control` now owns the supported 18 action names and supported key names, including Numpad0..9. `act.settings.set` and `cfctl act settings-set --key-binding` validate unknown actions/keys before dispatch; cf-app accepts Numpad key names so `aim_up=Numpad8` is real behavior, not a fallback.
4. **HUD readability now protects the play area at 200%.** `cf-ui` keeps the core status strip compact and content-sized, moves urgent banners/captions to the upper-right lane, hides empty banner/caption roots instead of reserving space, and sanitizes non-ASCII HUD text so captures do not show missing-glyph boxes. The M4A proof bundle `prototype_runs/native/m4a_2026-05-10T18-19-43Z_5d1a46cc/` shows the 200% high-contrast HUD with the bottom action lane clear.
5. **Capture evidence has a review-sized contact sheet.** `game/tools/capture_grid.py` still emits the machine-oriented `summary_grid.png`, but now also emits `review_grid.png` / `review_grid.json` capped at 16 frames with monitor-shaped columns (4x4 for 16 frames) so agents can judge readability without squinting through an 8x8 proof mosaic.
6. **Agent review enforcement tightened.** `AGENTS.md` and the repo-local `corefall-review` skill now require a non-waived all-PASS close-loop verdict, current-source bundle paths, and matching dirty worktree fingerprint before any agent may claim a BP/milestone is closed.

### M4A audit closure round 5 — 1 BLOCKER + 1 HIGH + 2 MEDIUM findings fixed in-pass

The round-4 closure was rejected: the loop's "skip sweep replicas" Phase 4 logic still let stale graded bundles satisfy Phase 6 because Phase 6 scanned the entire `prototype_runs/native/*` history; ACC-A remap covered only 10 discrete actions (movement + aim still hard-coded WASD/arrow); cfctl `act settings-set` CLI exposed only 6 settings (missing the 4 round-2 flags); DR-012 docs claim Esc clears focus but the binary exits on Esc; gamepad analog focus debouncing used a single global `Local<f32>` shared across all connected pads (multi-pad scenario races). Every finding fixed:

1. **BLOCKER — Phase 4/6 grading verification now binds to the CURRENT loop's fresh bundle, not historical evidence.** `bp_close_loop.sh` now captures `LOOP_START_EPOCH = $(date -u +%s)` at the start of every loop iteration, then writes `LOOP_DIR/fresh_bundles.txt` listing every bundle whose `run_manifest.json` mtime is `>= LOOP_START_EPOCH`. Phase 4 scaffolds ONLY for the fresh-bundle list (no historical bundles get scaffolded). Phase 5 inspects ONLY fresh bundles + reports PENDING_AGENT when any one's grading is unfilled or invalid. Phase 6 first scans the fresh-bundle list; if no fresh bundle has a passing grading, it falls back to a `commit_sha`-based "current code state" check: any bundle whose `run_manifest.json.build.commit_sha` (12-char prefix, sans `-dirty`) matches `git rev-parse HEAD` AND whose grading.json is filled + validates is accepted as proof of THE CURRENT COMMIT. Any older commit_sha is rejected as stale. This closes the reviewer's exact failure mode: "the grading used to pass is from 07:02, explicitly 'audit-closure round 2'" — a round-2 grading would now ONLY satisfy Phase 6 if the round-2 commit were still HEAD, which it is not after subsequent fixes. The replica-skip helper from round 4 (`game/tools/check_bundle_replica.py`) was DELETED — the loop no longer skips bundles based on settings-equality; every fresh bundle gets scaffolded + the agent must hand-grade it from THIS bundle's actual events/captures/summary.

2. **HIGH — ACC-A remap surface extended to movement + aim; cfctl CLI exposes the full surface.** `cf-control::default_key_bindings()` now returns 18 actions: the 10 prior discrete (jump/fire/fire_alt/reload/dig/reset/select_slot_0..3) plus 8 continuous (move_left/move_right/move_up/move_down + aim_left/aim_right/aim_up/aim_down). `cf-app::ingest_player_input` consults `key_for_action(settings, "move_left"/"move_right"/etc.)` every frame instead of hardcoding `KeyCode::KeyA/KeyD/KeyW/KeyS/ArrowLeft/ArrowRight/ArrowUp/ArrowDown`. Defaults preserve the historical WASD-move + Arrow-aim feel; `key_for_action` falls back to those defaults when remap is disabled or the binding name is unknown. Two new unit tests added: `settings_default_key_bindings_includes_movement_and_aim_actions` (locks the 8 new bindings) + `key_for_action_honors_movement_remap_when_enabled` (rebinds move_left -> KeyH, move_right -> KeyL, aim_up -> Numpad8 unknown -> falls back to ArrowUp). `cfctl act settings-set` CLI now accepts `--hold-to-confirm`, `--hold-threshold-ms`, `--key-remap-enabled`, repeatable `--key-binding action=KeyName`, and `--clear-key-bindings` flags via a new `parse_key_binding_kv` value-parser. The dispatch path builds the JSON-RPC `act.settings.set` params dictionary including a `key_bindings: { ... }` map when `--key-binding` flags are given, or `key_bindings: {}` when `--clear-key-bindings` is set.

3. **MEDIUM — Escape clears focus when active, exits when no focus is set.** `cf-app::esc_or_close_to_exit` now reads the engine's current focus state via `holder.0.hud_caches_snapshot().focused_node`. If a focus node is set, Escape dispatches `ControlCommand::ActInputFocus { direction: Clear }` through the same code path keyboard/cfctl/cf-e2e/gamepad already use AND does NOT exit. If no focus node is set, Escape behaves as before (writes `AppExit::Success`). F1 is preserved as a fast-clear shortcut. This honors DR-012 ACC-A-04's "Esc clears focus" claim with the standard "Esc closes the active overlay; Esc on the root exits" pattern from desktop UI guidelines. DR-012 closure note updated to articulate the dual semantic.

4. **MEDIUM — Per-gamepad analog stick debounce; multi-gamepad regression test.** `cf-app::ingest_focus_input` now takes `gamepads: Query<(Entity, &Gamepad)>` + `last_stick_y: Local<HashMap<Entity, f32>>`. Each connected gamepad's previous-frame stick Y is keyed by Bevy `Entity`, so an idle pad's zero-Y can NEVER overwrite an active pad's debounce state. New test `gamepad_focus_input_per_gamepad_debounce_isolates_idle_pad_from_active_pad` is the regression catch: pad A holds stick down at -0.8 (rising-edge fires `Next`); pad B is idle. Frame 2: pad A still held, no rising-edge -> no refire (per-pad history preserved). The previous global-`Local<f32>` would have wiped pad A's history with pad B's idle 0.0 + caused pad A to refire on every frame.

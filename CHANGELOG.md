### BP2 follow-up — Source-Truthful Bundle Metadata + AI-Agent-Primary Self-Test Contract

Post-merge of PR #11 (BP2 — Terrain & Replay Build, commit `4d8abc7`), an AI-driven `/corefall-review BP2` audit surfaced four contract gaps that were present pre-merge but not caught by Bugbot/Devin commit-diff review or by the `self_play_sweep.sh` (sweep was 13/13 PASS but does not check bundle-content semantics). This entry covers the follow-up branch + re-tag of `v0.1.0-bp1` and `v0.2.0-bp2` against the post-fix commit.

**Findings fixed in this entry:**

1. **Source-Truthful Evidence violation in run-bundle metadata.** `cf-control::M0Engine::write_run_bundle` hardcoded M0-era boilerplate into every bundle's `summary.json` and `notes.md` regardless of milestone: `next_actions = ["Proceed to M1 task cards in spec/native-implementation-backlog."]`, `tests = [{id: "M0-SMOKE-01", notes: "Fixed-tick smoke + run bundle parity per M0 done-criteria."}]`, `artifacts.items = []`, `evidence_links = ["events.jsonl", "summary.json", "run_manifest.json"]` (no `captures/`), `notes_extra = m0_notes_addendum()` (DR-002 v1 + DR-012 floor lock M0 prose with stale "M2/M3 will append terrain bytes" wording), `good = ["Fixed-tick scheduler stable; cfctl/control envelope serializes per DR-002 v1 lock."]`, and `manifest.prototype_slice = "M0"`. M2 / M2.5 / M3A bundles all carried this M0 boilerplate even though the engine's `cfg.milestone` field was already correctly bumped to `m2` / `m2.5`. Direct violation of the **Contract Integrity Gate "Evidence must be source-truthful"** rule. **Fix:** added `prototype_slice_for_milestone()`, `next_actions_for_milestone()`, `notes_addendum_for_milestone()`, `build_test_records()`, and `discover_run_artifacts()` helpers to `engine.rs` so every bundle's metadata reflects the loaded scenario's milestone instead of hardcoded M0 strings. Test ids now come from the scenario's `expected_tests` field (e.g. `M2.5-WIN-01`, `M2.5-LOSS-01`); `next_actions` reflects the next roadmap milestone; `notes_extra` includes the up-to-date DR-002 + DR-012 lock prose plus DR-007 launch-material-set addendum for M2+ bundles; `evidence_links` includes `captures/` when capture artifacts are present; `good` is empty (boilerplate is wrong; that section is for owner-authored notes).

2. **T-CAPTURE evidence not recorded in `summary.json.artifacts.items[]`.** AGENTS.md BP closure gate text states "every fun-proof scenario must emit a `summary_grid.png` + `capture_manifest.json` (recorded in `summary.json.artifacts`)". The captures were on disk (`captures/summary_grid.png` 165 KB + `capture_manifest.json` + 113-443 frame_*.png per bundle) but the artifacts array was empty. **Fix:** `discover_run_artifacts()` in `cf-control` populates `summary.json.artifacts.items[]` from `<run>/captures/` at write_run_bundle time (capture_manifest + frames count); `capture_grid.py::patch_run_bundle_summary()` post-hoc patches the same array to add the composer's outputs (`summary_grid.png`, `summary_grid.json`, every `grid_NNN.png`) and writes a `summary.json.capture.summary_grid` block with frame_count + non_blank_ratio + tick_first/last for offline review without re-running the composer. Idempotent on the in-process side — the post-hoc patcher de-dupes by `path`.

3. **Stale headless-smoke bundles shadow fun-proof evidence in release-notes lookup.** `generate_release_notes.py::find_bp_run_bundle()` used `sorted(bundles_root.glob(f"{prefix}_*"))` which returned the most-recent bundle by ISO timestamp regardless of `run_mode`. A developer's later `cf-app --headless-smoke` smoke run with M0-era prototype_slice + no captures was being picked as the "BP2 exemplar" by the release archive. **Fix:** new `_bundle_is_fun_proof()` helper filters out bundles where `run_manifest.json.run_mode == "headless-smoke"` AND filters out bundles whose `scene.id` matches a different BP's headline scenario per `BP_SMOKE_SCENARIOS`. The release archive now ships the actual fun-proof evidence.

4. **Per-BP human-playtest survey was treated as a hard closure gate, blocking BP closure on owner availability.** AGENTS.md previously stated "the survey is mandatory; a green Acceptance Matrix without a recorded playtest answer is not a closed BP." This created an unnecessary dependency on synchronous human playtest when the AI agent IS the playtest mechanism. **Fix:** the per-BP human-playtest survey is now **OPTIONAL confirmation**, NOT a Blocker. The closure gate is the new **AI-Agent Self-Test Report** (Q1..Q7 with concrete evidence + agent identity + timestamp) AND the new **BP Goal Coverage Report** (verbatim BP goals → cfctl actions → frames the agent personally read → events → observe fields → tests → agent prose articulating look + feel + juice). Both gates are agent-fillable end-to-end; human playtest sits below them as a non-gating row the project owner adds when they actually playtest. See `.claude/skills/corefall-review/SKILL.md` §AI-Agent Self-Test Report Gate + §BP Goal Coverage Gate + §Hands/Eyes/Ears Capability Floor.

### LLM-Graded Test Verdicts (BP2+ closure gate)

Pass/fail is no longer enough for fun-proof scenarios. A binary `PASS` cell hides the difference between "the test exited 0 because the assertion fired" and "the test exited 0 AND the simulation behavior is the right kind of fun". Bugbot/Devin commit-diff review does not catch this; cf-e2e `--expect` does not catch this. The fix is **dimensional LLM grading** by the AI agent driving the corefall-review session.

**New artifacts:**

- `game/content/scenarios/grading/<scenario>.grading.json` — per-scenario grading-criteria contract declaring 6-12 dimensions (look.\* / feel.\* / goal.\* / agent.\*) with: criterion prose, evidence_required pointers, weight, future_owners_if_blocked. Shipped for `micro_reactor_defense`, `micro_breach`, `m2_material_lane`.
- `game/tools/llm_grade_run.py` — three-subcommand harness: `scaffold` writes a grading.json skeleton inside a run bundle from the scenario's criteria; `validate` enforces every dimension has non-placeholder score + 30+-char prose + non-empty `evidence_read` audit trail + valid verdict, plus aggregate >= `minimum_aggregate_for_pass` (default 7.0/10) and per-dimension scores classified as PARTIAL/FUTURE_OWNED when below `minimum_per_dimension_for_pass`; `report` prints a Markdown summary suitable for embedding in the AI-Agent Self-Test Report or BP closure note.
- `prototype_runs/native/<bundle>/grading.json` — durable LLM-graded verdict artifact, force-included in git via `.gitignore` exception for `m[0-9]*_*/grading.json` and `bp[0-9]*_*/grading.json` so reviewers can audit the grades offline without re-running the scenario.
- `game/tools/self_play_sweep.sh` — auto-scaffolds grading.json for fun-proof bundles produced this hour.
- `game/tools/prototype_run_check.py` — validates `grading.json` shape when present (schema_version, required fields, dimensions[].score type) so a malformed grading file is caught at run-bundle time, not at review time.

**New review-skill enforcement:**

- `.claude/skills/corefall-review/SKILL.md` adds **§LLM-Graded Test Verdicts Gate** with the workflow (scaffold → fill → validate → report), reviewer enforcement rules (aggregate >= 7.0; below-min dims must be FUTURE_OWNED with owning milestone OR flagged NEEDS_FIXES; agent identity + timestamp recorded), and CI vs review enforcement boundary (CI keeps mechanical tests; corefall-review enforces LLM grading).
- `.claude/skills/corefall-review/SKILL.md` adds **\"LLM-Graded Test Verdict missing or invalid\"** to the Important Findings (Blocker-level) list.
- `corefall/AGENTS.md` Build Point Closure Gate adds the **LLM-Graded Test Verdict** as a mandatory closure artifact (alongside the AI-Agent Self-Test Report).

The grading is not theater; it is the difference between mechanically-correct tests and gameplay-correct tests.

### Per-BP Test Suite + AI-Agent Test-Improvement Loop

The test suite is now CUSTOMIZED PER BP and a self-correcting AI-agent loop drives BP closure. Each BP ships a declarative test contract; coverage analysis cross-references the contract against actual artifacts; the loop driver orchestrates iteration until every gate passes.

**New artifacts:**

- `game/content/build_points/bp<N>.test_manifest.json` — declarative test contract per BP. Schema `cf-bp-test-manifest.v1`. Declares fun-proof scenarios + supporting scenarios + regression scenarios from prior BPs + negative/adversarial scenarios + required sweep rows + required grading dimensions per scenario + required events emitted (with `_win`/`_loss` outcome suffix) + required observe fields + required cargo test modules + perf gates per Steam Deck/1080p/4K tier + universal-enhancement (DR-056) row statuses + loop thresholds. Shipped for BP2; bp1.test_manifest.json + bp3+ will be authored when their respective scopes are reviewed.
- `game/tools/bp_test_coverage.py` — gap analyzer. Cross-references the manifest's declared requirements against the actual artifacts on disk + the latest run-bundle evidence. Detects 9 gap categories: scenario_missing, script_missing, grading_contract_missing, sweep_row_missing, cargo_module_missing, grading_dimension_missing, events_not_emitted (with win/loss-aware bundle selection), events_bundle_missing, observe_fields_missing. Emits structured JSON for the loop driver + human-readable text for the agent.
- `game/tools/bp_close_loop.sh` — AI-improvement loop orchestrator. 6 phases: (1) coverage check, (2) cargo build + clippy + workspace tests, (3) self_play_sweep, (4) auto-scaffold grading.json for fresh fun-proof bundles, (5) PENDING_AGENT (agent fills grading prose), (6) validate at-least-one-grading-per-fun-proof-scenario. Halt conditions per the canonical Loop Semantics (Accept verdict, max iterations, gap-set unchanged, only out-of-scope remain). Output: `prototype_runs/native/<bp>_loop_<UTC>_<hash>/{loop.log,verdict.json}`.

**Real bugs the loop caught + fixed in this entry:**

The bp2 loop ran end-to-end + surfaced 4 real BP2 contract gaps that 7 rounds of Bugbot + Devin review on PR #11 missed:

1. **`cf-replay::tests::expected_outcome_*` did not exist** — the M3A `ExpectedOutcome` enum (Clean/Panic/Abort) had no direct unit tests; it was tested implicitly by the run-bundle checker but not at the type level. Fix: 6 new cf-replay unit tests covering default, as_str, snake_case serde round-trip, unknown-string rejection, and missing-field deserialize-to-Clean default. **+6 tests landed in cf-replay.**

2. **`cf-headless::tests::replay_*` did not exist** — the M3A replay verifier was tested via self_play_sweep end-to-end but had no direct unit tests. Fix: 2 new cf-headless unit tests `replay_parser_accepts_every_bp2_method` (positive proof: 15 cfctl methods parse correctly) + `replay_parser_rejects_unknown_method` (negative proof: 4 invalid payloads reject). **+2 tests landed in cf-headless.**

3. **`mission.objective_started` event was NEVER emitted for the first objective.** `MissionState::new()` and `reset()` directly transitioned the first objective Pending → Active without going through `step()`, so the engine's `mission.objective_started` emission code path (which only fires when `step()` returns a non-empty `objective_started` list) never saw the first objective's transition. M2.5 + M1.5 + every prior fun-proof bundle had this hole. Fix: removed the new()/reset() auto-activation; added a "Phase 0" guard in `step()` that activates the first Pending objective AND pushes to `report.objective_started` so the event fires through the same path as subsequent objectives. **5 cf-mission tests updated to reflect the new contract; 3 of them now drive a step() to assert the first-objective-started path; +1 cf-mission test for the started-event firing on first step.**

4. **The bp_test_coverage analyzer initially reported false-positive `events_not_emitted` for the WIN bundle because it picked the LATEST `m2.5_*` bundle by ISO timestamp — which happened to be a LOSS path bundle (sweep ran loss after win).** Fix: `latest_bundle_for_scenario(scene_id, outcome=)` filter — for `<scene>_win` keys it requires `mission_resolved>=1 AND objective_completed>=1 AND objective_failed==0`; for `<scene>_loss` keys it requires `mission_resolved>=1 AND objective_failed>=1`. **The analyzer is now win/loss-aware.**

The loop's exit condition was met after 4 iterations (coverage gap → fix code → coverage gap → fix tests → coverage gap → fix mission state machine → CLEAN). Final state: 245 tests pass workspace-wide (+8 from the BP2 follow-up baseline of 237); `bp_test_coverage.py bp2` reports `verdict: CLEAN, total gaps: 0`; `bp_close_loop.sh bp2` exits 0 with all phases PASS.

**Why this matters:** the loop is the difference between "I shipped what the task card said" and "I shipped what the task card said AND the test suite would have caught the regression I just introduced AND the rubric for grading the gameplay quality is locked AND a fresh AI agent reviewing this BP six months from now has the same machinery to catch the same class of bugs." Without the per-BP manifest + coverage analyzer + loop driver, the AI agent re-derives the closure-gate from prose every time. With them, the contract is machine-checkable.

**M2.5 — Micro Reactor Defense Fun Slice**

- **`cf-mission::Reactor` + `ReactorWorld`**: damageable static actor with hp/max_hp/destroyed/AABB; `apply_damage` is no-op once destroyed (no double-kill); `aabb_contains` for projectile hit tests; layout-stable `checksum_bytes`. `ReactorWorld::destroyed_map` feeds the mission tick inputs.

**M3A — Event Recorder Core**

- **Snapshot events at scenario start** (`M0Engine::emit_initial_snapshots`): `snapshot_actor` (one per actor, plus one per reactor), `snapshot_inventory` (one per actor with selected_slot + items[]), `snapshot_terrain_chunk` (one per allocated chunk with cx / cy / blake3-hash of pixels), and `snapshot_terrain_summary` (width_px / height_px / default_material / carve_count / refusal_count / material_counts / allocated_chunks). All parent-linked to the `system.run_started` event so cause-chains point back to a single root.

Append-only: existing M0 / M1 / M1.5 bundles checksum identically (no migration required).
- **`cf_replay::ExpectedOutcome`** enum (`Clean`, `Panic`, `Abort`) added to `RunManifest` with default `Clean`. `cf-app --debug-inject-panic-at-tick` flips the manifest to `Panic`. The canonical run-bundle checker (`game/tools/prototype_run_check.py`) now enforces:
  - `clean` → exactly one `system.run_finished` event + zero `system.panic` + zero `event_counts.by_severity.error`.
  - `panic` → at least one `system.panic`.
  - `abort` → at least one of `system.run_finished` or `system.panic`.
- **`cf-headless replay <bundle> --scenario-path <path>`** is the M3A replay verifier: builds a fresh `M0Engine` from the bundle's manifest (same scenario + seed + tick_rate_hz), parses every recorded `control.command_accepted` event payload back into a `ControlCommand` variant (15 method types: scenario.reset, scenario.load, sim.pause, sim.resume, sim.step, sim.run_for_ticks, act.player.{move,aim,fire,reload,jump,dig,select_item,reset}, act.settings.set), dispatches commands at the engine's current tick, drives one tick forward, then compares the engine's per-tick `final_checksum_hex` against the recorded cadence checksum at that tick. On match exits 0 with `{result: ok, replayed_ticks, checksums_verified, commands_replayed}`. On mismatch exits 1 with `{result: divergence, first_divergence: {tick, recorded, live}, total_divergences}`. M2.5 win bundle: 62 cadence checksums verified, 12 commands replayed, 0 divergences. M2.5 loss bundle: 58 checksums, 58 commands, 0 divergences. M1.5 micro_breach bundles: 7 checksums, 46 commands, 0 divergences. (Final-kind checksums emitted by `record_run_finished()` and `write_run_bundle()` are intentionally skipped because they are emitted outside the replay loop and a single tick can carry multiple final hashes.)
- **`cf-headless` Cargo manifest** upgraded from M0 stub to a real binary depending on `cf-control` + `cf-replay` + `cf-actor` + `tokio` for the JSON-RPC dispatch path.

**Side-track fixes that BP2 introduced**

- **`cf-app::WinitSettings { focused_mode: Continuous, unfocused_mode: Continuous }`** — Bevy 0.18 defaults `unfocused_mode` to `ReactiveLowPower` (~60s/frame). cf-e2e launches cf-app windowed, but on macOS the foreground terminal keeps focus, so cf-app runs unfocused and the JSON-RPC schedule was nearly stalled. Pinning both modes to `Continuous` keeps the engine ticking at the configured tick rate regardless of focus state. Without this, the M2.5 capture-grid run hung indefinitely.

### Fixed (T-CAPTURE Bugbot loop)

The T-CAPTURE PR #6 cycled through three Bugbot autofix iterations PLUS two of my own follow-up commits to address findings the Bugbot 3-iteration cap left unresolved:

- **`baseline_interval_ticks` NaN/Infinity bypass** (cf-capture, Bugbot ID 4dec59f3): `frames_hz <= 0.0` is `false` for NaN under IEEE 754, and Inf would saturate the float-to-int cast to 0 then `.max(1) = 1` → capture every sim tick → disk-fill bug. Fixed via `!self.frames_hz.is_finite() || self.frames_hz <= 0.0`. Four regression tests cover NaN, +Inf, -Inf, negative.
- **Guard `alert_dwell` + `burst_pause` off-by-one** (cf-ai, Bugbot ID cf33d096): step() decremented timers BEFORE the state-machine + scoring/firing checks read them, so D ticks of configured duration produced D-1 effective ticks. Fixed via pre-decrement capture (`prev_alert_dwell_remaining_ticks`, `prev_burst_pause_remaining_ticks`) threaded through `score_tactics` + `try_fire`. Two regression tests prove full-duration behavior.
- **`seconds_to_ticks(0.0) = 1` silent delay** (cf-ai, Cursor Agent autofix `74deb29`): the function clamped every input to ≥ 1 tick, so callers passing `aim_settle_seconds = 0.0` got a 1-tick delay instead of instant fire. Fixed: explicit `0.0` returns 0; positive sub-tick still rounds up to 1.

- **HudBreach material wired through render projection** (Cursor Agent autofix `fe7804e`): `BreachRenderView` gained a `material` field; cf-app HUD reads strip material directly instead of misusing `refusal_reason` (which was `None` for diggable strips, yielding empty string).

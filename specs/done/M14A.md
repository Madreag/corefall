## License — pragmatic stance (READ FIRST, but don't worry about it)

**CCCP is AGPLv3. Corefall is its own game in its own language with its own simulation layers.** The license is not the bottleneck here — engineering practice is.

The line the project owner cares about: **the license is not allowed to stop us from building what we want.** It doesn't have to, and the rules below make sure of that.

**What the law actually protects (and what it doesn't):**

- Copyright protects **literal expression**: the specific lines of C++ in CCCP's `.cpp` and `.h` files.
- Copyright does NOT protect: facts, mathematical formulas, physics equations, magic numbers (those are facts about how the game feels), algorithmic ideas, behavioral contracts, structural decisions, gameplay feel, the *concept* of "walking by alternating feet along authored paths."
- A new Rust game that achieves the same player-observable behavior by independently implementing the same equations is original work.

**The one engineering rule the worker follows (it covers everything):**

> Read CCCP source freely. Understand the algorithm. Then write Rust from scratch using your understanding. Don't paste C++ into our repo and translate token-by-token — that's lazy engineering and it's also the only thing the license actually forbids.

Everything else — magic numbers, equations, the *shape* of the algorithm, the *names* of variables when they describe game-physics concepts (`m_AngularVel`, `WalkRotAngleTarget`), the per-stance lean targets, the 333ms PRONE transition — is the **feel calibration of the game** and is the worker's tool to use.

**What this gives the worker:**

**Beyond the forbidden zone, the worker is unblocked.** AGPL doesn't reach behavioral parity, doesn't reach physics math, doesn't reach magic-number calibration, doesn't reach algorithm shape. Build what the user wants.

## Intent

**M14A is the limb-driven walking simulation milestone + the Cortex-Command feel-parity contract + the Corefall simulation-overlay integration layer.** It's the missing piece that turns Corefall's "static sliding pawn" into a CC-style biped/quadruped/drone that **walks on its feet**, **wobbles on its torso**, **falls when balance is lost**, **aggregates mass from every attached part + held device + jetpack fuel**, **fires its jetpack realistically against that aggregated mass**, **carries a tank-grade heavy-armor archetype that small-arms fire can barely scratch**, presents a **sub-100ms quick-action UX** that's faster than CC's pie menu — AND **honors every active Corefall simulation layer** (atmospherics, per-pixel materials, fluid hazards, gravity fields, temperature, radiation, comms blackouts, environment hazards, per-origin survival resources) the moment the actor's foot touches a tile.

After M14A, the player presses A/D and the actor's feet alternate along authored waypoint paths, each foot's atom group collides with terrain pixels, body mass falls into whichever foot is currently planted, the chassis spring-corrects its rotation toward a per-stance lean target, holding a heavy weapon makes the actor visibly slower because mass-aggregation adds it to chassis kg, jetpack thrust scales inversely with aggregated mass AND inversely with local atmospheric density (loaded soldier in thick atmosphere = double-sluggish jet; light scout in vacuum = nimble jet), heavy-armor enemies eat rifle fire and shrug, the quick-action wheel opens in under 80ms with sim time-sliced to 25%, **wet tiles make feet slip, snow slows the gait, lava burns feet, wind pushes the chassis sideways, smoke obscures the silhouette, acid pools etch the heavy armor, radiation zones drop afflictions per stride, low-g extends jump arcs, comms blackouts disable the squad QAB, and per-origin resource depletion (caloric for humans, power for robots, oil + blood for androids) ticks every step the actor takes**.

M14A's player-facing promise: **"feet, not slide. Mass matters. Every tile under your foot matters. Every breath of atmosphere matters. Jetpacks struggle with payload AND with thick air. Heavy armor is heavy AND it gets scratched by acid AND it cooks in lava. Cortex Command players feel at home in the first 3 seconds, and then Corefall's simulation overlay starts teaching them things CC never knew."**

This is the "Cortex feel + everything Cortex doesn't simulate." Cortex Command's `AHuman::Update` is a beautifully calibrated rigid-body walking loop on a terrain bitmap with `m_AirResistance` drag. Corefall takes that exact rigid-body walking loop, ports it cleanly in Rust, and then **plugs it into a sim stack that simulates per-pixel material chemistry (cf-material / M15), per-cell atmospheric pressure + wind + temperature (cf-atmos / M19), per-tile hazards + 22 afflictions (cf-environment + M16), per-origin survival resources (M17), per-chunk active material kernel, swept-volume collision with War-Thunder-style penetration ray (cf-physics / M14), and per-actor footstep audio via material lookup (cf-audio / M12A)**. The walking sim is the chassis; the overlay is everything that walks on, around, through, and into the chassis.

This was a P0 gap the project owner caught — M1's velocity-driven movement and M5/M13's stance enum were a "static sliding pawn" the M5 done-criteria explicitly forbid but never wired up. M18A ships sprite walk-cycle FRAMES (visual assets) but the underlying SIM still slides the body in a straight line. **M14A is the sim layer M18A's sprites should render on top of, AND the chassis-rotation spring that makes the rig feel alive, AND the mass-aggregation pipeline that makes equipment-weight matter, AND the jetpack-vs-mass-vs-atmosphere force balance, AND the heavy-armor damage-resist matrix, AND the quick-action UX that beats CC at its own game, AND the bridge that lets every Corefall sim layer (M14 / M15 / M16 / M17 / M19) actually affect the actor every tick.**

This spec aims at **near-1:1 feel parity with Cortex Command Community Project's `AHuman::Update` rotational + limb-driven movement loop** — every signature behavior listed in the "CC Feel Parity Contract" section below should be reproducible by a CC veteran within 30 seconds of picking up a Corefall actor and saying "yeah, that's CC" — AND **a Cortex veteran should immediately notice Corefall does things Cortex never did: 'wait, that tile actually changes how I walk? Wait, the wind is pushing me? Wait, my jetpack is more efficient in vacuum?'** That second half is Corefall's edge over CC, and M14A is where it's wired up.

### AtomGroup::push_as_limb — the heart of CC walking

**Source study:** `Entities/AtomGroup.cpp:1217-1287`. This is **why CC walking feels hard.**

**Algorithm (Corefall summary):**

```text
push_as_limb(joint_pos, joint_vel, walk_angle, path, dt, walk_path_offset) -> SweepOutcome:

  1. Adjust joint_pos for walking-backwards (h_flip parity check)
  2. Set path.joint_pos, joint_vel, rotation, frame_time
  3. Check if limb_pos strayed off path > chassis_radius:
       if strayed > chassis_diameter: path.terminate()
       else: pull limb_pos back toward path
  4. Loop while frame time remaining AND path not ended:
       if path.ended: try restart_free(limb_pos); if blocked, return false
       push_impulse += push_travel(limb_pos, path.current_vel,
                                    path.push_force, time_chunk)
       path.report_progress(limb_pos)
  5. Clamp push_impulse if absurdly large (> 10000 components)
  6. If pushing AGAINST player's intended travel direction:
       a. If NOT crouching: translate horizontal push → upward push
          (foot steps OVER obstacle instead of bouncing back)
       b. Halve horizontal push (against-intended-direction multiplier 0.5)
  7. Apply push_impulse to chassis via add_impulse_force
       (with angular component if affect_rotation == true)
  8. Return progress + restarted flags
```

**Why this feels hard:**
- Step 4: each iteration is a full atom-vs-pixel collision sweep — slow paths require multiple iterations per tick
- Step 5: prevents runaway impulse from a single absurd hit
- Step 6: the "step over instead of bounce" rule is what makes CC actors climb single-pixel bumps gracefully but still trip on 3-pixel ledges
- Step 7: angular impulse off-center → chassis rotates from foot push

### Stride alternation algorithm

**Source study:** `AHuman.cpp:2275-2294`. Pseudocode the worker writes from scratch in Rust:

```text
tick_walk_alternation(actor, dt):
  fg_progress = path[FG][WALK].regular_progress()
  bg_progress = path[BG][WALK].regular_progress()
  restarted = false

  if actor.velocity_magnitude < still_threshold:
      actor.stride_start = true

  # FG leg pushes when:
  fg_should_push = actor.has_fg_leg AND (
      NOT actor.has_bg_leg
      OR NOT (path[FG][WALK].ended() AND bg_progress < 0.5)
      OR actor.stride_start
  )
  if fg_should_push:
      if path[FG][WALK].ended() OR path[FG][WALK].at_start():
          actor.stride_timer_ms = 0
      foot_group_FG.push_as_limb(joint_pos_FG, vel, walk_angle[FG],
                                  path[FG][WALK], dt,

      NOT actor.has_fg_leg

          actor.stride_timer_ms = 0
      foot_group_BG.push_as_limb(joint_pos_BG, vel, walk_angle[BG],
                                  path[BG][WALK], dt,
                                  out restarted, ...)

      actor.stride_frame = true  # 1-tick flag
      emit_event("actor.on_stride", payload)
      stride_sound.play_at(foot_pos)
```

```rust
pub fn attitude_spring_tick_stable(state: &mut AttitudeState, ctx: &SpringContext) {
    let target = ctx.rot_angle_targets[ctx.move_state as usize] * ctx.facing_factor();
    let aim_dampen = if ctx.aim_angle > 0.0 {
        1.0 - ctx.aim_angle / std::f32::consts::FRAC_PI_2
    } else {
        1.0
    };
    let mut rot_target = target * aim_dampen;

    let crouch_adjust = if ctx.h_flipped {
        ctx.max_crouch_rotation
    } else {
        -ctx.max_crouch_rotation
    };
    rot_target += lerp(
        0.0, ctx.max_walkpath_crouch_shift,
        0.0, crouch_adjust,
        -ctx.walk_path_offset[1],
    );

    let rot_diff = state.rot - rot_target;
    let damping = 0.98 - 0.06 * (1.0 - ctx.health / ctx.max_health.max(1.0));
    state.angular_vel = state.angular_vel * damping - rot_diff * 0.5;
}
```

**Per-tick update flow (study `AEJetpack.cpp:116-194`):**

```text
update_burst_state(jetpack, actor, controller, dt):
  if actor.status == INACTIVE:
      recharge(jetpack, actor)
      return

  fuel_use_multiplier = 1.0
  if jetpack.adjusts_throttle_for_weight:
      thrust_adjustment = actor.total_mass / actor.base_mass
      jetpack.throttle = clamped_throttle(0.0, thrust_adjustment)
      fuel_use_multiplier = jetpack.throttle_factor()
  else:
      # Default mode: throttle scales with remaining fuel
      jet_time_ratio = jetpack.jet_time_left_ms / jetpack.jet_time_total_ms
      jetpack.throttle = jet_time_ratio * 2.0 - 1.0   # 0..1 → -1..+1

  was_emitting_last_frame = jetpack.is_emitting()
  min_fuel_to_begin = 250.0 * fuel_use_multiplier
  if jet_time_left > min_fuel_to_begin OR was_emitting OR fully_fueled:
      match jetpack.jetpack_type:
          Standard:
              if controller.body_jumpstart AND NOT out_of_fuel:
                  burst(jetpack, actor, fuel_use_multiplier)
              elif controller.body_jump AND NOT out_of_fuel AND
                   (fuel_ratio >= minimum_fuel_ratio OR was_emitting):
                  thrust(jetpack, actor, fuel_use_multiplier)
              else:
                  recharge(jetpack, actor)
          JumpPack:
              if was_emitting AND NOT out_of_fuel:
                  thrust(jetpack, actor, fuel_use_multiplier)
              elif controller.body_jumpstart AND fuel_ratio >= minimum_fuel_ratio:
                  burst(jetpack, actor, fuel_use_multiplier)
              else:
                  recharge(jetpack, actor)
  else:
      recharge(jetpack, actor)

  jet_time_left = clamp(jet_time_left, 0, jet_time_total)

  # Direct thrust angle
  can_adjust_angle = NOT pie_menu_active AND
                     (can_adjust_angle_while_firing OR NOT is_emitting)
  if can_adjust_angle:
      max_angle = HalfPI * jet_angle_range
      if controller.analog_move.magnitude > 0.1:
          jet_angle = clamp(controller.analog_move.angle - HalfPI, -max_angle, max_angle)
          jetpack.emit_angle = actor.facing_angle(jet_angle - HalfPI)
      else:
          aim_angle = actor.aim_angle
          # Halve jet angle if aiming down (don't force sideways)
          flip = (h_flipped AND moving_right) OR (!h_flipped AND moving_left) ? -1 : 1
          jet_angle = (aim_angle > 0 ? aim_angle * jet_angle_range :
                       -aim_angle * jet_angle_range * 0.5) - max_angle
          jetpack.emit_angle = jet_angle * flip - HalfPI
```

## Mass Aggregation System — every kg matters

**Source study:** `Entities/AHuman.h:178` (`GetMass() = MovableObject::GetMass() + m_AttachableAndWoundMass`) + `AHuman.cpp:1285-1290` (equipped mass accumulation in `IsCarryingDevice`).

### Algorithm summary

```rust
pub fn total_mass(actor: &ActorState) -> f32 {
    let chassis_base = actor.chassis.as_ref().map(|c| c.mass_kg).unwrap_or(actor.mass_kg);
    let limb_mass = aggregate_limb_mass(actor);              // sum of attached zones
    let held_mass = aggregate_held_devices_mass(actor);      // FG + BG arm devices
    let inventory_mass = actor.inventory_weight_kg;          // M6 already tracks
    let jetpack_dry = actor.jetpack.as_ref().map_or(0.0, |j| j.dry_mass_kg);
    let jetpack_fuel = actor.jetpack.as_ref().map_or(0.0, |j| {
        j.fuel_density_kg_per_ms * j.jet_time_left_ms as f32
    });
    let wound_mass = aggregate_wound_pixel_mass(actor);
    chassis_base + limb_mass + held_mass + inventory_mass + jetpack_dry + jetpack_fuel + wound_mass
}

pub fn mass_factor(actor: &ActorState) -> f32 {
    let baseline = 80.0;
    (baseline / total_mass(actor)).clamp(0.25, 1.2)
}
```

### Mass × everything matrix

| System | Mass effect |
|---|---|
| Walk speed | `path.travel_speed × mass_factor` (multiplicative) |
| Jump impulse | `jump_velocity = jump_impulse / total_mass` |
| Fall damage | `damage = 0.5 × total_mass × velocity²` (M14) |
| Knockback resistance | `Δvelocity = impulse / total_mass` |
| Jetpack throttle (if `adjusts_for_weight`) | `fuel_drain × (total_mass / baseline)` |
| Stagger threshold | impulse must exceed `mass × stagger_threshold_factor` to flip STABLE → UNSTABLE |

**Algorithm:**

```rust
pub fn evaluate_ricochet(
    incoming_dir: [f32; 2],
    surface_normal: [f32; 2],
    sharpness: f32,
    velocity_m_per_s: f32,
    armor_hardness: f32,
    chassis_armor_angle: f32,
) -> RicochetOutcome {
    let incoming_angle_from_normal = angle_between(incoming_dir, surface_normal).abs();
    let effective_angle = (incoming_angle_from_normal - chassis_armor_angle).abs();
    let cos_factor = effective_angle.cos();
    let penetration_energy = sharpness * velocity_m_per_s.powi(2) * 0.001 * cos_factor;
    if penetration_energy < armor_hardness * 4.0
        && effective_angle > std::f32::consts::FRAC_PI_3
    {
        RicochetOutcome::Bounce {
            outgoing_dir: reflect(incoming_dir, surface_normal),
            energy_loss_pct: 0.4,
        }
    } else if penetration_energy < armor_hardness {
        RicochetOutcome::Glance { damage_pct: 0.1 }
    } else {
        RicochetOutcome::Penetrate {
            remaining_energy: penetration_energy - armor_hardness,
        }
    }
}
```

### Stagger resistance (knockdown immunity for heavy)

```rust
pub fn evaluate_knockdown(
    incoming_impulse_magnitude: f32,
    actor_mass_kg: f32,
) -> KnockdownOutcome {
    let stagger_threshold = actor_mass_kg * 5.0;  // 5 N·s per kg of mass
    if incoming_impulse_magnitude > stagger_threshold {
        KnockdownOutcome::Knockdown
    } else if incoming_impulse_magnitude > stagger_threshold * 0.5 {
        KnockdownOutcome::Stagger
    } else {
        KnockdownOutcome::None
    }
}
```

### Hold-Q radial flow

```text
Press Q AT t=0:
  - QAB highlights radial mode
  - Sim time multiplier: 1.0 → 0.25 (lerp over 80ms)
  - Radial overlay fades in (80ms)
  - Mouse cursor decoupled from aim → drives slice selection

Hold Q from t=80 onward:
  - Cursor angle from radial center → highlighted slice
  - Number keys 1-8 lock to that slice

Release Q at t_release:
  - If outside center deadzone: invoke slot
  - If in deadzone: cancel
  - Sim time multiplier: 0.25 → 1.0 (lerp over 80ms)
```

End-to-end skilled-player time: 200-300ms. CCCP pie menu equivalent: 600-900ms. M14A is ~3× faster.

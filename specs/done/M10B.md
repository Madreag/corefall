## Intent

M10B ships the **deep video-output layer** sitting under M10 (offline review tooling) and M40A (streamer / spectator polish): an FFmpeg / libav pipeline that renders any run bundle into an MP4 (H.264 / H.265 / AV1) deterministically and headlessly, a per-overlay rendering stack that composes HUD widgets + cause-chain captions + War-Thunder-style kill-cam frames + custom commentary tracks over the rendered scene, chapter markers auto-derived from the M4 event taxonomy (mission objectives, deaths, breaches, reactor events, faction-war beats), a replay editor UX with frame-accurate timeline scrub + multi-camera angles + commentary overlay + clip-trim controls, and a per-scene camera director script format that lets a replay author author cinematic camera moves over a deterministic event stream. M10 made the bundle readable; M40A polished the live spectator HUD; M10B closes the loop by making any bundle exportable as a high-quality video artifact suitable for tournament broadcast, Let's-Play uploads, Discord clips, and bug-report attachments — with the same byte-identical determinism contract that anchors the rest of the engine.

## Canonical ownership

Owns the FFmpeg / libav export pipeline, the per-overlay composition graph, the chapter-marker derivation rules, the replay editor UX in `cf-tools-replay-viewer`, the per-scene camera director script format (`*.camera.ron`), and the deterministic frame-render path (`cf-render-2d --offline`). M10 keeps owning the bundle loader + cause-chain walker + debrief markdown emitter; M40A keeps owning live spectator HUD + streamer overlay templates; M10B binds them into an offline video export rail.

## Player-facing behavior

- **Any run bundle becomes an MP4.** `cf-tools-replay-viewer export <bundle> --format mp4 --out <path>` renders the run end-to-end into a playable MP4 without launching the game window; works on Linux / macOS / Windows from the same single binary.
- **Multiple resolution + codec presets ship.** `--preset {twitch_1080p60 | youtube_4k60 | discord_720p30 | clip_compact | archival_lossless}` selects sane defaults; advanced flags expose bitrate + codec + audio mix.
- **Chapter markers auto-generate.** Mission objectives (`mission.objective_started/completed/failed`), deaths (`actor_status_changed=killed`), reactor events (`reactor.armor_layer_destroyed`), breaches (`atmos.breach_detected`), commander beats (`mission.commander_*`) all become MP4 chapter markers visible in YouTube + VLC + QuickTime; player jumps directly to the moment of interest.
- **Replay editor UX ships.** `cf-tools-replay-viewer edit <bundle>` opens a frame-accurate timeline (egui front-end) with scrub bar, in/out trim points, multi-camera angle selector, commentary track overlay, and "export selection" button — no third-party video editor required for a clean 30-second highlight clip.
- **Multi-camera angles per replay.** Up to 4 camera tracks (`free_cam`, `follow_player`, `objective_cam`, `kill_cam`) can be cut between in the editor; each camera's per-tick pose is captured into a `*.camera.ron` script that survives editing sessions.
- **Commentary overlay.** Author records voice + caption text against tick offsets; export merges audio + caption into the output MP4 with deterministic timing (no drift over a 30-min replay).
- **Overlay composition is granular.** Author toggles HUD, kill-feed, mini-map, debug overlay, captions, accessibility ribbons, watermark, branded streamer template, and chapter timeline independently per-export; OBS-style scene compositor at offline frame cadence.
- **Cause-chain side-panel during export.** Optional `--overlay cause_chain` renders the M10 cause-chain walker output as a per-event sidebar (auto-scrolling) so the viewer can read "input → fire → projectile → wound → death" as the moment plays.
- **Export is deterministic within scope.** Same bundle + same export flags produce byte-identical results for: (a) chapter marker offsets, (b) overlay composition output (HUD / kill-feed / cause-chain / watermark per-frame RGBA buffers), (c) cause-chain frame timing, (d) audio mix waveform within ±1 LSB, (e) MP4 container metadata. **Cross-OS byte-identical MP4 codec output is NOT guaranteed** — H.264 / H.265 / AV1 encoders are not bit-deterministic across OS due to encoder implementation differences (SIMD path selection, threading non-determinism even at `-threads 1`, libav version skew, OS-level math library precision). This is an **accepted limitation** of the codec ecosystem, not a Corefall bug. For true byte-identical archival output, use the `--preset archival_lossless` (FFV1 intra-frame mathematically lossless codec) which is bit-deterministic. Per-frame YUV BLAKE3 hashes match across OS for ≥99% of frames in the production presets (within codec encoder tolerance).
- **Headless on dedicated servers.** A Linux VPS without a GPU can export an MP4 via the CPU encode path; `cf-render-2d` uses its software rasterizer fallback so the dedicated-server tier (M36) can serve replay-to-MP4 on demand.
- **Per-replay watermark.** Tournament + competitive modes embed run_id + ledger chain anchor + Corefall build version as a corner watermark, proving the clip's provenance for dispute resolution.

## Out of scope

- Live-streaming protocol output (RTMP push to Twitch / YouTube) — M40A handles live streaming; M10B is offline-export only.
- In-game video playback (watching an MP4 inside cf-app) — never; the game window is for live + replay viewing, not for playing arbitrary video.
- Audio editing UX beyond per-track mix volume + caption — full DAW-style audio editing is out of scope; users bring polished commentary tracks externally.
- Frame interpolation / slow-motion smoothing beyond integer slow-down (--slow-mo 2x / 4x integer multiplier ships; AI-frame-interp does not).
- GIF + WebM export — M10B is MP4-first; alternative containers land in a future M10C only if demand justifies.
- VR / 360° spherical export — never.
- Cloud / SaaS export queue — M40A may add server-side queueing for streamer convenience; M10B keeps the local-CLI contract.
- Per-camera-track recording during live play — `*.camera.ron` is an authoring artifact in the editor, not a passive recording during live play; live spectator angles are M40A's `cf-spectator::director`.

## Notes for the implementer

- Use the `ffmpeg-next` crate as the libav bridge. Pin the FFmpeg version range in `Cargo.toml`; deterministic-encoder rules require a known encoder build. The CI gate ships a hermetic FFmpeg binary alongside the export tests so the matrix is reproducible.
- Deterministic encoding rule: H.264 / H.265 reach byte-identical output only with single-threaded encode + locked GOP + locked encoder version + disabled psychovisual tuning (`-tune psnr` for x264). The deterministic-export matrix uses these flags by default; the `--preset archival_lossless` uses FFV1 (intra-frame, mathematically lossless) for true byte-identical output where the production presets only guarantee per-frame YUV BLAKE3 within 99% tolerance.
- The frame ticker walks the M4B baseline + delta chain to reconstruct per-tick state; it MUST NOT spin up a live sim. Reusing live sim would be a double-render and would defeat determinism guarantees for any non-deterministic mod tick.
- `cf-render-2d --offline` uses the software rasterizer ( `pixman` / `tiny-skia` candidate). The render path must not call any wgpu surface; it writes RGBA into a `Vec<u8>` frame buffer that the ffmpeg_bridge converts to YUV420P / YUV444P per preset.
- Camera director scripts are RON files (consistent with the rest of the workspace's data format). Per-tick pose interpolation is cubic Catmull-Rom between declared keyframes; non-keyframe ticks are computed deterministically from neighboring keyframes. Avoid `f64`; pose is `[f32; 6]` `(x, y, zoom, rotation, lookahead_x, lookahead_y)`.
- Commentary mixer sample rate is locked at 48 kHz stereo; voice clips at other rates are resampled deterministically (linear interpolation, not cubic — keeps the encoder deterministic across libav versions).
- Chapter rules in `chapter_rules/default.ron` are data, not code. A mod can ship its own chapter_rules.ron to customize titles + which event types become chapters; the rule engine is just `(event_type, chapter_template_string)` pairs.
- Watermark renderer uses `cf-localization` for the build-version text + falls back to en-US if no locale is loaded. Tournament watermark format: `run=<run_id[..12]> anchor=<chain_anchor[..12]> build=<build_version>` rendered in 12pt monospace at 50% opacity, bottom-right corner.
- The editor UX uses `egui` (already vendored via Bevy 0.18.1). The timeline widget is custom; reuse `cf-shell::widget::ScrubBar` from M11A's foundation work.
- `m10b_deterministic_export_matrix.sh` is the release-blocker CI gate; it MUST run on every PR that touches `cf-replay-export` or its dependencies. The matrix runs only the `clip_compact` preset for speed; the full 5-preset matrix runs on nightly.
- Mod overlay extension: mods declare overlays in their manifest under `overlays.<name>: { z_order, dyn_lib_entry_point }`; M10B looks up the entry point at export time and asks for per-tick render commands. Sandbox the entry point per M33 modding workbench rules. Out of scope for M10B is the mod's UX for authoring an overlay — that's M33B.
- The "Export Last Replay" CTA in the post-mission debrief modal (cf-app) defaults to the `clip_compact` preset; one-click export to `~/Movies/Corefall/` on macOS, `~/Videos/Corefall/` on Linux, `~/Videos/Corefall/` on Windows. Path resolution uses `dirs-next` (already a dependency).
- Audio mix in export: by default mixes `cf-audio` runtime SFX + voice + music tracks captured in the run bundle's `audio.event_played` events (M12A schema). Commentary track adds on top of base mix; user can disable base mix with `--no-audio-base` for clean commentary-only export.
- Per-replay audio determinism is a soft contract: the same SFX events render the same waveforms because the audio engine is deterministic, but small differences in OGG decoder version + sample rate may produce ±1-bit drift on WAV checksum. The export-side audio determinism matrix tolerates ±1 LSB.

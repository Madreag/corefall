# M15B — GPU Material Kernel + Precipitation Cycle

## Status

`done`

## Intent

Resolve the M15-internal GPU contradiction (intent promises GPU compute, dependencies block defers it) by giving the GPU material kernel its own milestone + add the steam → cloud → rain precipitation chain that M15 references but doesn't enumerate. **M15B also lifts the M15 2-output reaction-record limit** by adding the `emissions: Vec<MaterialId>` field so cascade reactions can release tertiary gas products (smoke, CO2, etc.) into adjacent air cells without breaking the fire-cascade invariant.

## Player-facing behavior

- Material reactions run on the GPU (10× to 50× faster than M15 CPU baseline) with deterministic CPU fallback that the replay verifier can byte-compare against.
- Lighting a fuel tank in an oil-coated room cascades 5000+ pixel reactions per tick without dropping below 60Hz.
- Steam rising from a geyser nucleates into visible cloud at altitude > 80px and ambient temp < 80°C; cloud accumulates; eventually precipitates as rain that flows back down per terrain.
- Acid rain (Vulcan ambient): airborne pollutant + steam react → acid_droplets fall → corrode metal_nohook surfaces over time.
- Player can observe the full water cycle: ground evaporates → cloud forms → rain falls → puddles flow back into low ground → repeat.
- **Real-world chemistry accuracy** — burning wood/paper/fabric emits a visible smoke + CO2 plume into adjacent air cells (not just a "wood → charcoal" pixel swap); acid on concrete fizzes out CO2 instead of steam; water-gas shift releases hydrogen when water hits hot carbon fires (the "why magnesium fires are dangerous" mechanic); gunpowder explosions emit dense smoke clouds.
- **Pressure-aware precipitation** — low-pressure systems accelerate cloud formation (adiabatic cooling); vacuum/near-vacuum blocks nucleation entirely (Mimas never rains); high-pressure pressurized domes slow saturation. Per-cell pressure samples come from M19 atmospherics.

## Notes for the implementer

- The GPU kernel is the **performance** path; the CPU fallback is the **determinism** path. Per DR-036 + DR-052: every replay must verify identical checksums regardless of which path was used at runtime.
- Material reactions on the GPU require deterministic ordering — use a per-chunk Margolus checker-pattern shader pass + atomic merge step. NO atomic-CAS loops on shared sim state.
- Precipitation altitude threshold is sea-level + 80 px; per-world ambient_temp affects nucleation rate. Vulcan = always-rain due to high humidity from oceans; Mimas = never rain (vacuum); Mars = rare rain (thin atm).
- The CPU fallback must be `par_iter`-clean (no thread_rng, no f64) so it can run on the dedicated server tier without GPU.

## M15B reaction-record extension (`emissions`)

The M15 `MaterialReaction` struct shipped with a 2-output slot system:
- `output: MaterialId` — the new material id at the `input_a` position
- `byproduct: Option<MaterialId>` — the new material id at the `input_b` position (or `None` to leave `input_b` unchanged, used for cascade reactions)

This limited cascade reactions (wood+fire, paper+fire, fabric+fire, oil+fire, fuel+fire, coal+fire, gunpowder+fire) to **just** the `input_a` transformation. Real chemistry says burning wood ALSO releases CO2 + smoke into the surrounding air — but the 2-output model couldn't express that without breaking the fire-cascade (the `input_b` fire pixel must STAY as fire so adjacent wood pixels also ignite next tick).

M15B lifts this with:

```rust
pub struct MaterialReaction {
    pub id: String,
    pub input_a: MaterialId,
    pub input_b: MaterialId,
    pub output: MaterialId,
    pub byproduct: Option<MaterialId>,
    /// **M15B** § Tertiary-and-beyond emissions: each material id in
    /// this list spawns one pixel into an adjacent air cell when the
    /// reaction fires. NESW search order around input_a then input_b.
    pub emissions: Vec<MaterialId>,
    // ... rest unchanged
}
```

Per-tick behavior when a reaction fires:
1. Pixel at `input_a` → `output`
2. Pixel at `input_b` → `byproduct` (or stays if `None`)
3. For each material in `emissions`, the kernel finds the next adjacent air cell (NESW search starting from `input_a`'s neighbors then `input_b`'s) and spawns the emission there. Dropped emissions (no air cell available) record the `EMISSION_DROPPED` sentinel position in the recorder event.

The `ReactionTriggeredEvent` carries `emissions: Vec<MaterialId>` + `emission_positions: Vec<[i32;2]>` so replay viewers + AI consumers can reconstruct the full spatial picture.

**Determinism:** NESW search order is fixed; same inputs → same emission cells across runs. Per-tick blake3 checksum sees the emission pixel writes.

**Backward compat:** `emissions` is `#[serde(default)]` so legacy 2-output JSON entries round-trip cleanly with an empty Vec — no schema migration required.

## M15B chemistry-accuracy reaction audit

| Reaction | Before (M15) | After (M15B) | Real chemistry |
|---|---|---|---|
| water + fire | steam + air | steam + smoke + water-gas shift variant (steam + H2 above 973 K) | Incomplete combustion leaves smoke; water on hot carbon releases H2 |
| rain + fire | steam + air | steam + smoke + water-gas shift variant | Mirror of water+fire for the droplet form |
| concrete + acid | loose_fill + steam | loose_fill + **CO2** | `CaCO3 + 2HCl → CaCl2 + H2O + CO2` — the fizzing is CO2 |
| ore_copper + acid | polluted_water + ammonia | polluted_water + **hydrogen** | `Cu + H2SO4 → CuSO4 + H2`; ammonia requires nitrogen (absent) |
| alcohol + fire | steam + nothing | steam + **CO2** | `C2H6O + 3O2 → 2CO2 + 3H2O` — ethanol combustion |
| H2 + O2 | steam + air | steam + **steam** | `2H2 + O2 → 2H2O` — both reactants → water, no air byproduct |
| wood + fire | charcoal | charcoal + emissions [smoke, CO2] | Cellulose combustion releases CO2 + smoke + char |
| paper + fire | ash | ash + emissions [smoke, CO2] | Same as wood (cellulose) |
| fabric + fire | ash | ash + emissions [smoke, CO2] | Organic polymer combustion |
| oil + fire | fire (cascade) | fire (cascade) + emissions [smoke, smoke, CO2] | Heavy black soot from hydrocarbon |
| fuel + fire | fire (cascade) | fire (cascade) + emissions [smoke, CO2] | Refined hydrocarbon (less sooty than oil) |
| coal + fire | fire (cascade) | fire (cascade) + emissions [smoke, smoke, CO2] | Dense bituminous coal smoke |
| coal + O2 | ash + CO2 | ash + CO2 + emission [smoke] | Incomplete combustion soot |
| gunpowder + fire | smoke | smoke + emissions [smoke, smoke, CO2] | Detonation releases dense gas plume |
| acid + alkali | brine + brine | brine + brine + emission [steam] | Exothermic neutralization boils local water |

## M15B pressure-aware precipitation

The spec dependency `M19 atmospherics (active): provides temperature + pressure inputs for precipitation gating` declared pressure as an input. M15B implements:

- `PrecipitationInputs.ambient_pressure_kpa: f32` — per-cell pressure sample
- `pressure_rate_multiplier(p_kpa) -> f32` — `REFERENCE_PRESSURE / p` clamped to `[0.5, 2.0]`
- `saturation_rate_per_tick_with_pressure(world, p_kpa)` — pressure-modulated saturation
- `update_cloud_cell_with_pressure(cell, world, p_kpa, ...)` — explicit pressure entry point
- `PrecipitationCycle::step_cell_with_pressure(x, y, p_kpa, tick)`

Physics:
- Low pressure (≤50 kPa) → multiplier 2.0 → faster cloud formation (adiabatic cooling)
- Earth ambient (101.325 kPa) → multiplier 1.0 → baseline
- High pressure (≥300 kPa) → multiplier 0.5 → slower (fair-weather high-pressure systems)
- Vacuum (<1 kPa) → nucleation gate BLOCKS (satisfies "Mimas = never rain")

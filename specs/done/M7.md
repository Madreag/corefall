# M7 — AI Archetypes + Mission Director

## Status

`active`

## Intent

**M7** is the **second bridge slice** between M6 (closed actor + equipment core) and M8 (UX + accessibility polish). It closes the **AI + perception + mission director + basic personality/faction** gap. After M7, the game has multiple intelligent enemies with distinct archetypes, real mission pacing, basic personality traits that affect AI behavior, and a faction relationship surface — all the things M9 reactor defense and M13 chassis need to feel meaningful.

M7's player-facing promise: **"the enemies feel intelligent and the mission feels dynamic."**

## Player-facing behavior

### 5 enemy AI archetypes (M2: 1 reactive guard → M7: 5 archetypes + behaviors)

**Per DR-008 hybrid utility + scripted layered AI model.** All archetypes share `BaseEnemyState` (M2 ReactiveGuard) + archetype-specific behaviors:

| Archetype | Primary behavior | FOV / range | Reaction time | Health | Key trait |
|---|---|---|---|---|---|
| **Rifleman** | Cover seeking + suppression fire | 180° / 320u | 12 ticks | 80 HP | Bread-and-butter combat unit |
| **Sniper** | High-ground preference + scope settle (1.5s before fire) | 240° / 800u | 18 ticks | 60 HP | Flanker; positions on rooftops |
| **Assault** | Sprint toward player + grenade thrower | 120° / 200u | 6 ticks | 90 HP | Close-quarters specialist |
| **Engineer** | Digs cover + repairs squadmates + sets explosive traps | 180° / 280u | 12 ticks | 70 HP | Force multiplier (support role) |
| **Spotter** | Calls reinforcements + commands squad | 200° / 360u | 12 ticks | 50 HP | Mini-boss with multi-phase (see M8) |

**Cover seeking**: each archetype searches for `cover_state=Full` within sight; crouches + repositions toward cover when fired upon (per CCCP `AHuman.cpp` AI patterns).

**Suppression fire**: rifleman in squad maintains low-accuracy high-rate-of-fire while a squadmate flanks; emits `ai.suppression_started`.

**Retreat decision**: any archetype with HP < 30% OR squad dead → retreats to safe distance + cover.

**Squad communication**: 0.5s delay for alarm propagation through squad (M2 has direct line; M7 adds latency for realism).

**Patrol routes**: waypoint following with 5-10s idle stops at waypoints; emits `ai.patrol_waypoint_reached`.

**Friendly fire awareness**: AI repositions if a friendly is in line of fire OR within blast radius of a grenade; emits `ai.friendly_fire_avoidance`.

**High-ground preference**: sniper + spotter actively move to elevated terrain before firing.

### Personality traits + nicknames (basic; affects AI)

**M7 ships the surface; M13+ retention/campaign fills the full system.**

- Per-actor `traits: Vec<Trait>` (3-5 traits per actor)
- 20+ launch traits affecting AI: `brave, coward, loyal, disloyal, merciful, cruel, careful, reckless, sharp_shooter, terrible_shooter, hot_headed, calm, fast_reflexes, slow_reflexes, gun_collector, peaceful, paranoid`
- Per-actor name (generated from culture/faction name list — 50+ name pool per faction)
- Per-actor 1-line backstory (M13+ extends; M7 has placeholder)
- **Mood/stress accumulator (0..1)**: affects aim accuracy + retreat threshold + sprint speed; events that affect mood: ally killed (-15), kill landed (+5), mission progress (+5), wounded (-10)

Trait effects:
- `brave` → retreat threshold lowered (won't flee until <15% HP vs default <30%)
- `coward` → retreat threshold raised (flees at <50%)
- `sharp_shooter` → aim_accuracy × 1.15
- `terrible_shooter` → aim_accuracy × 0.7
- `paranoid` → false sightings (occasional ai.target_acquired with no real target)
- `loyal` → defends squadmates more aggressively

### Squad doctrine (Defensive / Aggressive / Scout)

Per-squad assigned doctrine affects all members:
- `Defensive` → hold cover positions; suppression fire; retreat at threshold
- `Aggressive` → push toward player; less suppression; flanking
- `Scout` → one member explores ahead while others wait

Set via `act.squad.assign_doctrine` (forward-compat for player vs enemy squads).

### Mission director v0.5 (multi-objective + branching + 4 phases)

Replaces M2's simple timer-and-objective with:

**Multi-objective `DiGraph<ObjectiveNode>`** with kinds:
- `ReachZone, KillActor, KillN, SurviveTimer, DefendActor, EscortActor, RetrieveItem, PlantItem, DetectAlarm, SneakStealth, RescueDowned, BreachContainer, Optional, Branching`

Sequential + parallel + branching support (e.g. `Breach → KillSpotter → Extract`, with optional `RescueDowned` as parallel).

**4-phase pacing** (Warframe-style):
- `Setup` (mission start; players orient)
- `Buildup` (early enemy encounters)
- `Climax` (main objective + reinforcement waves)
- `Debrief` (mission resolution)

**Dynamic respawn waves**: director spawns reinforcements based on phase + player progress; emits `mission.reinforcement_wave_spawned`.

**Mini-boss patterns** (per Diablo / Sea of Thieves design):

**Schema (forward-compat):** Spotter mini-boss is authored against the canonical `BossDef` schema defined in M25 § Mini-boss + boss patterns. At M7, the schema doesn't exist yet (M25 closes later), so Spotter uses a pre-schema-locked form. When M25 closes, M7's Spotter data row migrates to the canonical BossDef schema (no behavior change; schema-conformance only).

- 1 mini-boss per scenario (Spotter archetype as launch boss)
- Multi-phase HP thresholds (>75% phase 1; <75% phase 2 with shield ability; <25% enraged phase 3)
- Specific tactic required (e.g. break shield with electric weapon)
- Boss events: `boss.phase_changed`, `boss.special_ability_triggered` (canonical event family in M25)

## Smart commandable AI — 5-layer thinking stack + per-actor Priority Table + chatter

M7 is also the milestone where the AI stops being "ReactiveGuard FSM with a few extra states" and becomes **fully commandable + smart + CPU-heavy** per DR-008's layered AI direction. The 5-layer thinking stack runs every tick on M8A's parallel scheduler within the 4.0 ms p99 AI sim budget; per-actor Priority Tables let players tune behavior without micromanaging; bots speak what they see (chatter scaffold); every action carries a reason label.

### Three-layer control model (player perspective)

**Layer 1 — Autonomy mode** (set once per actor or globally; persistent in M25 campaign):

| Mode | What the player sees |
|---|---|
| `FullAuto` (default) | Bot does everything based on role + priority table; minimal player input needed. Player commands override when issued. Chatter is on. Recommended for 95% of players. |
| `Standard` | Bot auto-acts on top 3 highest-priority tasks; medium/low-priority tasks wait for player nudge. Chatter is reduced. |
| `Manual` | Bot waits for explicit orders only; default auto-behaviors disabled. Chatter is signals-only. Tactical-sim audience (ArmA / Squad / Door Kickers veterans). |

**Layer 2 — Priority Table** (22 tasks × 1-9 weight; per-actor; persists across missions for named actors):

The canonical 22-task list is locked in M8A (`TaskType` enum). M7 ships:

- **6 role templates** (Medic / Engineer / Rifleman / Sniper / Assault / Spotter) that auto-fill the priority table on archetype assignment. Each template has hand-tuned defaults for all 22 tasks.
- **Quick presets** (Aggressive / Defensive / Scout / Berserk / Custom) — shift the template weights ±2 across the relevant task families.
- **Per-task override**: player can manually set any one task's priority 1-9 OR disable (0) it. UI lives in M8 (Tab overlay).
- **Apply-to-role**: Shift+click sets priority for ALL bots in the same role.

The Priority Table feeds the **utility scorer** as a multiplicative weight prior: `final_score(task) = base_utility(task, world_state) × priority_weight[task] / 5.0`. Priority weight 5 = neutral (1.0×); priority 9 = strong preference (1.8×); priority 1 = strong avoidance (0.2×); disabled = never (0.0×).

**Layer 3 — Live Orders** (in-mission tactical; layered on top of priority math):

| Surface | Effect | Owner |
|---|---|---|
| Single-key panic (M / R / G) | "Medic on me!" / "Repair this!" / "Regroup on me!" — overrides all priorities for one assignment | M8 |
| Q-hold context wheel | Context-sensitive 6-8 commands based on what player is looking at | M8 |
| MMB tag | Drops a priority signal on a target (enemy / ally / hazard / repair-target); feeds utility scorer as a +0.5 weight bonus on tasks targeting it | M8 |
| Tab tactical overlay | Pause-and-plan compound orders + plan composer (up to 8-step queues per bot) | M8 |

Live Orders **temporarily override** priority math for their duration. When the order completes (or is aborted), bot resumes priority-driven autonomous behavior.

### 5-layer AI thinking stack

Every AI tick runs all 5 layers in dependency order. M8A's parallel scheduler runs the entire stack within the 80 µs per-bot effective parallel slice.

```
┌─ Layer 5: LLM Mind (async, 5s tick, OPTIONAL) ─────────┐
│ Doctrine: "press_attack_north_wall"                    │  ← M23 layer
│ Output: doctrine string cached in BotMemory            │     (off by default; M7 ships interface)
└──────────────────────┬─────────────────────────────────┘
                       ↓ feeds as strong prior to Layer 3
┌─ Layer 4: HTN Planner ─────────────────────────────────┐
│ Current goal stack: [capture_room, clear_left,         │  ← M7 layer
│                      cover_east_corner]                │
│ Re-plans when goals achieved / failed                  │
└──────────────────────┬─────────────────────────────────┘
                       ↓ outputs current sub-goal
┌─ Layer 3: Behavior Tree ───────────────────────────────┐
│ Sequence: move_to_cover → check_los → suppress         │  ← M7 layer
│ Selector / Sequence / Decorator nodes                  │
└──────────────────────┬─────────────────────────────────┘
                       ↓ selects current action class
┌─ Layer 2: Utility Scorer ──────────────────────────────┐
│ score(suppress) = base × priority[Suppress]/5 = 0.82   │  ← M2.2B + M7
│ score(advance)  = base × priority[Flank]/5    = 0.71   │
│ chosen = argmax(scores)                                │
└──────────────────────┬─────────────────────────────────┘
                       ↓ chosen action
┌─ Layer 1: Reactive Layer ──────────────────────────────┐
│ If incoming projectile within 0.2s impact              │  ← M2 (shipped)
│ → emergency dodge override                             │
└────────────────────────────────────────────────────────┘
                       ↓
                AiTickOutput {
                  chosen_action, reason_label,
                  utility_candidates (top 3),
                  htn_goal_stack, behavior_tree_node
                }
```

Reason label format (every tick, deterministic, structured string):
```
"chosen=TriageDownedAlly(Mendez); score=0.92 (base=0.46 × prio[Triage]=9/5=1.8 × tag_bonus=1.11);
 candidates=[Suppress(0.61), Advance(0.45)]; htn=protect_squad/triage_medic_route;
 bt=move_to_cover→approach_ally→treat_loop; doctrine=defensive; role=Medic"
```

| Bot does | Placeholder caption text |

| Engages target | "Engaging!" |

Chatter selection uses a **cooldown table** (each bot can emit at most one chatter event per 4 seconds; reduces audio spam). Priority-based — Combat-critical chatter ("Contact!", "Reloading!") preempts conversational chatter ("Roger"). Cooldown deterministic via M8A's seeded RNG (no thread_rng).

### Memory grid usage (BotMemory consumes M8A foundation)

The `BotMemory` struct (16 KB per bot, locked in M8A) gives every bot a per-actor world model:

- **Perception grid** (64×64 cells): each cell tracks `seen_recently` (last tick a bot or player observed this cell) + `threat_level` + `cover_quality` + `friendly_marked`. Updated per-tick during the perception pass. Drives utility scoring of MarkThreats / Patrol / Investigate / ScoutAhead tasks.
- **Threat memory**: per-enemy record of last-seen position + last-known weapon + suspected role + age. Decays after 60-300 seconds; longer for player-tagged threats (MMB tag bumps the decay timer to 600s).
- **Ally memory**: per-ally record of last-known HP + last-known cover + last-known order received. Drives triage / cover decisions.
- **Recent events ring buffer** (last 64 events the bot witnessed): consumed by HTN re-planner to detect goal failure (e.g., "I just lost LOS on my target → re-evaluate sub-goal").

Memory ages out deterministically via tick-counter comparison (NOT wall-clock; preserves replay determinism).

```gherkin
  When shield destroyed: boss.phase_changed fires phase=3 (enraged final stand)
  When boss HP=0: mission completes
```

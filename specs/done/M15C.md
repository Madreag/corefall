# M15C — Full Material Registry Buildout + 50+ Materials with Complete Schemas

## Status

`active`

## Intent

Author the explicit 50+ material registry with full ONI + Stationeers + Noita schemas. M15 promises "50+ materials, 30+ reactions" but does not enumerate every entry with complete `MaterialDef` fields. M15C closes the gap: 50+ materials each declared with id / display_name / hardness / density_kg_per_m3 / specific_heat_capacity_j_per_kg_k / thermal_conductivity_w_per_m_k / ignition_temp / melt_temp / boil_temp / molar_mass / 9 affordance flags / toxicity / corrosiveness / radioactivity / electrical_conductivity / viscosity / surface_tension.

## Canonical ownership

Owns the **solids / powders / plasmas / energy-fields** catalog with full thermodynamic schemas. M3B per-tile element model + M15 active material kernel + M15D reaction matrix + M19I plants + M28B thermal all read from this registry.

**Gases + liquids are NOT owned here** — they live in **M19L** because their state carries richer thermodynamics (PV=nRT, latent heat, viscous flow, surface tension, critical points, partial pressures) that the broader material registry does not capture. M15C references gas + liquid IDs by name; M19L authors the full schemas.

| Topic | Owner |
|---|---|
| **Solids / powders / plasmas / energy fields (this spec)** | **M15C** |
| Gases (24 launch) — full thermodynamic schemas | M19L |
| Liquids (33 launch) — full thermodynamic schemas | M19L |
| Reaction matrix (55 reactions) | M15D |
| Per-pixel CA kernel (CPU + GPU) | M15 / M15B |
| Per-tile element + heat | M3B |
| Atmospherics PV=nRT | M19 |

## Acceptance criteria

```gherkin
Scenario: All 50+ materials declared with full schema
  Given content/materials/material_registry.json
  When cf-material::load_registry runs
  Then 50+ MaterialDef entries parse successfully
  And every entry has non-default values for: hardness, density, specific_heat_capacity, thermal_conductivity, color_hex

Scenario: Per-material properties accessible via cfctl
  Given the player runs cfctl inspect.material iron
  Then full property dump returns: hardness=8, density=7870, specific_heat=449, thermal_conductivity=80.4, etc.

Scenario: ONI parity numbers used for thermal properties
  Given iron material entry
  Then specific_heat_capacity_j_per_kg_k = 449 (ONI parity)
  And thermal_conductivity_w_per_m_k = 80.4

Scenario: Per-state materials phase-transition correctly
  Given water material with melt_temp_k=273.15, boil_temp_k=373.15
  When tile temperature crosses 373.15K:
    Then phase change fires water → steam

Scenario: Mod validation catches incomplete material entries
  Given a mod author adds material with no specific_heat_capacity
  When cf-mod validate runs:
    Then validation fails with "field 'specific_heat_capacity_j_per_kg_k' required"

Scenario: F8 tile inspect overlay shows complete material data
  Given player F8 inspect hovers a steel tile
  Then HUD shows: element=Steel, mass=920kg, temp=298K, hardness=12, density=7800
```

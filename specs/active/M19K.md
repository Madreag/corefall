# M19K — Per-Pixel Priority Queue + Dig/Build Task Allocation (ONI Style)

## Status

`active`

## Intent

ONI-grade per-tile/per-task priority system: player paints priority levels (1-9) onto dig zones, build sites, mining sites, repair tasks. AI workers (miners, engineers, medics) consume the priority queue in order — Stationeers + ONI's defining player-as-foreman gameplay.

## Player-facing behavior

- **Per-pixel priority paint**: player drags brush across dig zones / build sites / repair queues / placement targets; each pixel/tile gets a priority 1-9.
- **9 priority levels**: 1 = lowest (do when nothing else); 9 = highest (urgent; do first).
- **AI workers read priority queue**: per actor-archetype assignment respects priority. Miners go to priority-9 dig zones first.
- **Per-task type priority**: separate queues for Dig / Build / Repair / Mine / Plumb / Wire / Cook / Combat. Player tunes each independently.
- **AI commander override**: in combat or emergency, AI commander promotes ALL priorities to 9 for life-support / repair tasks (M25 integration).
- **Visual priority labels**: F10 overlay shows priority numbers on every tile with an assigned task.
- **Drag-to-paint UX**: hold [P] + drag mouse to paint priority across a zone.
- **Per-actor work-style preferences**: some actors prefer high-priority work (driven), others avoid it (avoidant; per M48 origin trait).

## Acceptance criteria

```gherkin
Scenario: Player paints priority 9 on emergency dig
  Given a 32-pixel zone needs digging + 2 AI miners idle
  When player drags priority paint tool over the zone with [P] + 9 key
  Then priority_painted fires per tile
  And tile_priority buffer updates
  And both AI miners path toward the priority-9 zone

Scenario: AI miners consume priority queue in order
  Given a base with priority-9 dig zone + priority-3 dig zone
  When AI miners are idle
  Then they path to priority-9 first
  And work_task_started fires with target_tile in priority-9 zone
  And only after priority-9 zone is complete do miners move to priority-3

Scenario: Priority cleared via clear_priority
  Given a previously-painted zone
  When player triggers act.player.clear_priority
  Then priority_cleared fires
  And tile_priority resets to 0 across the zone
  And AI workers re-evaluate task list (no longer attracted to the zone)

Scenario: Per-task type priority separation
  Given player paints "dig 9" on zone A + "build 9" on zone B
  When AI workers evaluate task types
  Then a miner targets zone A (dig)
  And an engineer targets zone B (build)
  And the same priority level (9) doesn't cause cross-discipline confusion

Scenario: AI commander emergency-promotes life-support
  Given a base in brown-out cascade (M29C)
  When AI commander emergency-promotion triggers
  Then priority_promoted_emergency fires
  And all life-support tasks (repair scrubbers, fix airlock, etc.) promoted to priority 9
  And HUD displays "EMERGENCY MODE — RESPONDING"
  And per-actor work-style preferences are overridden

Scenario: Actor work-style affects task selection
  Given an actor with work_style="avoidant" + priority-9 and priority-5 tasks available
  When the actor evaluates
  Then the avoidant actor picks priority-5 (avoiding chaos)
  And per-actor reason_label="avoidant_workstyle"

Scenario: F10 overlay shows priority labels
  Given F10 active + dig zone with priority 9
  When the per-frame render runs
  Then each tile in the zone shows numeric "9" label
  And per-tile color matches priority value (red=9; green=3; gray=0)

Scenario: Priority queue persists across save/load
  Given a base with multiple priority assignments
  When game saves + reloads
  Then all priority assignments restore identically
  And SaveBlob.checksum identical to pre-save state

Scenario: Determinism across priority + AI consumption
  Given two engines with same seed + same priority paint
  When 300 ticks elapse
  Then identical AI worker task selection sequence
  And identical task completion order
  And SaveBlob.checksum identical at tick 600
```

## Notes for the implementer

- Per-tile priority is u8 (0=none; 1-9=levels). Stored in tile_priority buffer (1 byte per tile × 256×256 chunk = 64KB per chunk).
- AI consumer reads tile_priority + matches against actor's `work_style.priority_curve` (per RON file).
- Emergency promotion is a single-tick override; reverts when emergency state clears (M29C consumer).
- Per-task type queues live in separate BTreeMap<TaskKind, Vec<TilePos>> structures; deterministic iteration.
- Drag-to-paint UX uses M28A's existing brush pattern.

## Intent

**M12 is the Public PvP Arenas + Persistent MMO Shards milestone — Extended With Bunker Defence Flagship Per DR-042 + Realistic Comms Per DR-043**. Architecture supports public PvP arenas + persistent MMO shards under `cf-server`, with community-hostable defaults, anti-cheat foundation enabled, persistence proven across restart, interest management proven at scale, and per-client run bundles aligning tick-for-tick.

M12 is the **full-product readiness gate** (was previously post-launch-only research). PvP arena half (`cf-server --mode pvp_arena`) + MMO shard half (`cf-server --mode mmo_shard`) + Bunker Defence as flagship mode + realistic comms.

M12 promise: **"the world is alive; faction wars unfold across thousands of players; Bunker Defence is the flagship mode; persistent meta-game retains forever."**

## Player-facing behavior

### Public PvP arena half (`cf-server --mode pvp_arena`)

- 2-8 player server-authoritative match server
- Anti-cheat profile `competitive` default; `tournament_strict` available for ranked
- Replay archive per match
- Latency-masked client prediction with reconciliation
- Pure replication for any AI bots in the arena
- PvP-specific scenarios under `content/scenarios/pvp/`
- Bandwidth/authority/cheat models tested at 4-8 player density
- Per-arena leaderboards (M11 endgame tournament mode extends to M12 ranked)

### Bunker Defence flagship mode (per DR-042)

- The most polished mode in the entire game; M12 polishes
- 2-4 defenders + 2-4 attackers (PvP) OR vs AI commander
- Defenders: build + defend bunker + manage power grid
- Attackers: breach + assault + capture
- Per-side persistent base across sessions
- Per-server-shard tournament ladder
- Per-match replay shared via Steam Workshop

### MMO shard half (per `spec/persistent-mmo-architecture`)

### Persistent world state

- Cross-server persistent universe (shared backend)
- Faction territory map updated in real-time across all players
- Per-region persistent resources (mining + extraction per DR-041)
- Per-server shard = subset of universe (4 launch shards: NA / EU / APAC / SA)
- Cross-shard events (mass faction war events)

### Faction-vs-faction war (large scale)

- 8 factions vs 8 factions (per README)
- Per-faction territorial expansion based on player wins
- Mass attack events triggered by faction relationship drops
- Faction-controlled regions confer benefits (resource bonuses, equipment access)
- Faction-controlled territory tracked on universe map

### Cross-server events

- Daily / weekly / monthly events (per DR-048 retention)
- Examples: solar flare disrupts all comms for 6h; pirate raid on 3 random servers; faction summit (negotiation events)
- Players from multiple servers participate
- Event rewards: rare loot, faction reputation, server-wide perks

### MMO shard architecture (per DR-035)

- Each shard: dedicated server cluster
- Per-shard player cap: 1000-10,000 (config)
- Cross-shard events bridge shards
- Per-shard world state persistence

### Persistent player progression

- Player level + perks + curses + achievements persist
- Veteran bots persist (M11 baseline)
- Bunker meta-game persists (M11)
- Inventory + gold persist
- Per-player Steam Workshop progress

### Anti-FOMO + anti-pay-to-win audit (DR-031)

- All cosmetics earnable through play
- No timed events that can't be replayed
- Archive mode: previous events replayable forever
- No pay-to-win mechanics
- Cosmetic-only gacha/battle-pass hooks: dormant by default + activation DR required

### Live operations (T-LIVEOPS finalization)

- Telemetry pipeline
- Crash + bug reporting
- Marketing campaign
- Steam community engagement
- Legal + license ledger
- Sustainability / sunset posture

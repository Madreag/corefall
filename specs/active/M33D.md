# M33D — FRE Wizard Deep + Contextual Tooltips + Progressive Disclosure + Skill-Rating Bot + Tutorial Replay + Sandbox Mode + 8 System Mini-Tutorials

## Status

`active`

## Intent

**M33D is the new-player-experience (NPE) deep-dive milestone** — closes the surface-level "FRE wizard" + "contextual tooltips" + "tooltip fade" + "show me why" hand-offs reserved across M33A / M11A / DR-023 with a full kernel: a **5-step First-Run-Experience wizard** (language → accessibility presets → difficulty recommendation → game-mode pick → initial calibration) + **hover-tooltips on every HUD widget** with per-actor skill-rating-aware verbosity (verbose for novices; terse for veterans; fully suppressed at mastery) + **progressive disclosure** that unlocks advanced HUD panels and cfctl actions per achievement milestone + an **M22 skill-rating bot** that evaluates the player's aim / pathing / resource-management on a 30-second rolling window and tunes hint cadence + a **tutorial replay system** that lets the player rewind and re-attempt any tutorial step from the in-tutorial pause menu + a **sandbox mode** where permadeath is disabled and resources are infinite for safe experimentation + **8 system mini-tutorials** (Atmospherics / Mining + Refining / Squad Commands / Cooking + Food / IC10 Chips / Crafting + Quality / Combat + Healing / Vehicles + Convoys) that each take 3-6 minutes and slot into the M33A tutorial-lab launcher.

M33D promise: **"a brand-new player launches Corefall, picks their language and accessibility profile in 90 seconds, gets a difficulty + game-mode the game thinks suits them, plays a calibration sequence that proves the controls work, and then steps into First Contract knowing what every HUD widget means. As they play, the game watches their aim and decisions, fades tooltips they no longer need, surfaces hints when they stumble, and unlocks deeper HUD panels as they earn them. If they break something, sandbox mode lets them experiment without losing progress. If they want to dig into atmospherics or IC10, 8 mini-tutorials each cover one system in 5 minutes — and any tutorial step can be replayed from any failure."**

## Canonical ownership

This spec is the **canonical owner of the FRE 5-step wizard schema + the per-tooltip verbosity-tier resolver + the progressive-disclosure unlock graph + the player skill-rating bot (M22 extension) + the tutorial replay/rewind subsystem + the sandbox-mode safety policy + the 8 system mini-tutorial scenarios**. ## Player-facing behavior

### 5-step FRE wizard (extends M11A FreStep state machine)

On first launch (no profile detected), the engine routes the player into a 5-step wizard before the title screen. Each step is keyboard + mouse + controller + touch navigable; "Back" is always available; "Skip wizard" demands two-step confirm and locks the player to defaults.

| Step | Title | Player choices | Default | Persisted to |
|---|---|---|---|---|
| 1 | **Language** | 19 locales per M38A canonical roster (11 Tier-A: en / es / fr / de / pt-br / ja / zh-CN / zh-TW / ru / ko / pl + 8 Tier-B: tr / ar / nl / sv / hi / vi / id / it) | OS-detected; falls back to en | `profile.language` |
| 2 | **Accessibility presets** | 4 named bundles (`default` / `low_vision` / `motor_assist` / `cognitive_assist`) + per-key override | `default` | `profile.accessibility_preset` + 9 ACC-A settings (text_scale / high_contrast / captions / reduce_motion / reduce_shake / reduce_flash / hold_to_confirm / hold_threshold_ms / color_cue_mode) |
| 3 | **Difficulty recommendation** | 3 questions (gaming experience / sim-game familiarity / desired challenge curve) → engine recommends one of 5 difficulties (`story` / `easy` / `standard` / `hard` / `ironman`); player can override | `standard` if all skipped | `profile.difficulty` |
| 4 | **Game-mode pick** | 4 modes (`campaign` / `sandbox` / `tutorial_track` / `quickplay`) with one-line summary + recommended-storyteller pairing | `tutorial_track` if first profile | `profile.starting_mode` |
| 5 | **Initial calibration** | Walk → look → fire → reload → pickup mini-sequence in safe arena; engine measures input latency + frame stability + control hesitation; persists baseline skill_rating | n/a | `profile.skill_rating_baseline` |

Wizard completion fires `fre.completed { profile_id, choices, ms_elapsed }` into the run-bundle. Re-entering the wizard is available any time from Settings → "Re-run first-run wizard".

#### Accessibility preset bundles (step 2)

| Bundle | ACC-A floor mutations |
|---|---|
| `default` | All defaults from M38 schema; no overrides |
| `low_vision` | text_scale=2.0, high_contrast=true, captions=true, color_cue_mode=`shape+color` |
| `motor_assist` | hold_to_confirm=true, hold_threshold_ms=900, sticky_aim_assist=true, repeat_press_filter_ms=180 |
| `cognitive_assist` | reduce_motion=true, reduce_shake=true, reduce_flash=true, show_objective_summary=`always`, tutorial_hint_cadence=`verbose` |

A player can layer any per-key override after picking a preset. Bundle choice + overrides are persisted separately so a future preset upgrade does not stomp the player's overrides.

#### Difficulty recommender (step 3)

3 self-report questions feed a 12-state decision table:

1. "Have you played a sim like Stationeers, Rimworld, Project Zomboid, or Helldivers?" (yes / some / no)
2. "How comfortable are you with chassis-based first-person combat (Halo / Doom / Helldivers feel)?" (yes / some / no)
3. "What kind of challenge do you want?" (gentle / balanced / brutal / no-respawn)

Recommended difficulty is a single deterministic function of the 3 answers; the recommendation is surfaced with one-line rationale ("you've played sims + want balanced → **Standard** with Cassandra Classic storyteller"). Player can override; the override is persisted alongside the recommendation so the analytics-grade event `fre.difficulty_override { recommended, chosen }` captures drift.

#### Calibration arena (step 5)

A 30-second mini-scenario in a curated safe room: actor spawns with full health + a training rifle + 5 stationary practice targets at varying ranges. The wizard guides the player through walk / look / fire / reload / pickup, measuring:

- Per-input median + p95 latency (used for input-latency settings hint, not gating)
- Hit-rate on the 5 targets (used to seed `skill_rating_baseline.aim`)
- Movement-to-target time (used to seed `skill_rating_baseline.pathing`)
- Reload + pickup completion (used to seed `skill_rating_baseline.resource_management`)

If the player fails a step (e.g. can't fire after 15s), a tooltip auto-surfaces with the control hint; calibration never "fails" — it only collects data. Baseline skill_rating is clamped to `[0.05, 0.95]` so a single calibration never pins a player to a tier they'll never escape.

### Contextual tooltips on every HUD widget

Every HUD widget (per the M11A widget registry) carries a `tooltip_id`. Hovering the widget (mouse) or focusing it via keyboard / controller D-pad raises the tooltip after a per-widget `hover_dwell_ms` (default 350 ms; ACC-A `motor_assist` preset lowers to 600 ms for forgiveness).

**Per-tooltip verbosity tiers** (resolved per-widget per-tick from current skill_rating):

| Tier | When shown | Content |
|---|---|---|
| `verbose` | skill_rating < 0.30 OR `cognitive_assist` preset OR widget-use-count < 3 | 1-line summary + 2-line explanation + control hint + cross-link to relevant mini-tutorial |
| `terse` | 0.30 ≤ skill_rating < 0.70 AND widget-use-count 3..20 | 1-line summary + control hint |
| `mastery` | skill_rating ≥ 0.70 AND widget-use-count ≥ 20 | suppressed entirely (tooltip silent); player must re-enable from Settings |

`widget-use-count` is a per-profile per-widget counter incremented on meaningful interaction (not just hover). Counters survive sandbox-mode sessions but are tagged with a `sandbox=true` source so the bot can discount sandbox-rep-grinding when computing the live skill_rating.

Tooltip events: `tooltip.shown { tooltip_id, verbosity, skill_rating_bucket }`, `tooltip.dismissed { tooltip_id, dismiss_reason }`, `tooltip.faded_to_mastery { tooltip_id, profile_id }`.

A player can re-enable any tooltip from **Settings → Accessibility → Tooltips → Per-widget overrides** (lists every `tooltip_id` + current verbosity + manual override; "Reset all" restores adaptive behavior).

### Progressive disclosure (advanced features unlock per achievement)

Advanced HUD panels and cfctl actions are gated by per-achievement unlocks; before the unlock, they are hidden from the HUD + the in-game options menus. After the unlock, the panel materialises with a celebratory toast + a "what's new" tooltip.

Canonical unlock graph (data-driven; lives in `content/progression/disclosure_graph.ron`):

| Locked surface | Unlock trigger (achievement id) | Default visibility |
|---|---|---|
| HUD `personal_power_panel` (M17 surface) | `complete_first_engineering_lab` | hidden until unlocked |
| HUD `priority_queue_inspector` (M28 surface) | `assign_first_repair_priority` | hidden |
| HUD `atmospheric_dashboard` (M19E) | `complete_atmospherics_mini_tutorial` | hidden |
| HUD `squad_doctrine_panel` (M22 / M26) | `issue_5_squad_orders` | hidden |
| cfctl `act.player.write_ic10` (M29A IC10 editor) | `complete_ic10_mini_tutorial` | hidden |
| HUD `crafting_quality_grader` (M32 / M27) | `craft_5_items_quality_>=_uncommon` | hidden |
| HUD `cooking_dashboard` (M32+) | `cook_first_meal` | hidden |
| HUD `vehicle_convoy_planner` (M44B) | `complete_first_convoy_run` | hidden |

A player can opt **out** of progressive disclosure from Settings → "Disclose everything now"; this flag flips the gating evaluator to always-true and emits `disclosure.opt_out_full { profile_id }`. A player can opt back **in** (re-hides un-earned surfaces) any time; un-earned surfaces remain functional in the underlying sim — the gate is UI-layer only, not a sim feature flag, so a save loaded with disclose=on still works under disclose=off.

Disclosure events: `disclosure.unlocked { surface_id, achievement_id, ms_into_session }`, `disclosure.opt_out_full { profile_id }`, `disclosure.opt_back_in { profile_id }`.

### M22 skill-rating bot (per-30s rolling window evaluator)

`cf-ai::skill_rating_bot` evaluates the player's performance on three axes every 30 seconds (game-time, not wall-time) and exposes a live `PlayerSkillRating { aim, pathing, resource_management, composite, updated_at_tick }` resource.

Per-axis signals (all bounded `[0.0, 1.0]`):

| Axis | Signal sources |
|---|---|
| `aim` | hit-rate on intended targets (cone-of-fire vs target body zone) + time-to-acquire (target-painted-to-fire) + ammo-efficiency-per-kill |
| `pathing` | path-completion-time vs theoretical-optimum (per H-PA* of M22) + stuck-fraction (velocity ≈ 0 with intent ≠ 0) + collision-frequency (player-vs-terrain + player-vs-actor) |
| `resource_management` | ammo-reserve-at-engagement-end + medkit-burn-rate vs damage-taken + battery-burn-rate vs personal-power-budget (M17) |

Composite = weighted mean (default 0.4 aim + 0.3 pathing + 0.3 resource_management; weights expose to Settings → Adaptive Hints → "Bias toward …"). Rolling window is a circular buffer of the last 6 thirty-second buckets (3-minute total horizon); EWMA decay factor 0.7 so recent buckets dominate but a single bad bucket cannot crash the score.

**Hint cadence is a deterministic function of composite skill_rating** (no thread_rng; seeded off the engine RNG channel `skill_rating_bot`):

| skill_rating composite | Hint cadence (game-time between proactive hints) | Examples |
|---|---|---|
| `[0.00, 0.30)` | 45 s | "You've taken damage twice in 30 s — press F to heal" |
| `[0.30, 0.50)` | 120 s | "Battery is below 25% — consider switching to passive scope" |
| `[0.50, 0.70)` | 300 s | "Volatiles 6% in the room — vent recommended" |
| `[0.70, 1.00]` | 900 s (basically silent) | Only critical hazard warnings |

Hint event: `skill_rating.hint_emitted { skill_rating_composite, hint_id, suppression_threshold }`. Sandbox-mode hints are tagged so they're discounted from the live composite (per the verbosity-tier rule above).

The bot is **strictly read-only on sim state** + emits hints via `event.hint.proactive`; never mutates AI, never mutates difficulty mid-mission. It is gated by the M22 `cf-ai` deterministic-RNG contract.

### Tutorial replay system (rewind + re-attempt)

Inside any M33A tutorial lab OR M33D mini-tutorial, the tutorial player widget gains a **"Replay this step"** + **"Replay from start"** + **"Jump to step N"** affordance. The underlying mechanism reuses `cf-replay`'s deterministic rewind: each tutorial step records its scenario snapshot at step-entry (`tutorial.step_entered { lab_id, step_index, snapshot_hash }`); rewind re-loads the snapshot + re-plays from there.

Per-step rewind events: `tutorial.step_replayed { lab_id, step_index, attempt }`, `tutorial.lab_replayed_from_start { lab_id }`, `tutorial.step_skipped { lab_id, step_index, reason }`. Per-profile per-lab completion record (`profile.tutorial_progress.<lab_id>` = `{ steps_completed: [...], attempts_per_step: {...}, ms_total: u64 }`) survives across sessions.

"Show me why" handoff (per DR-023): on any tutorial-step failure, the in-step recap panel offers four buttons: **Retry step** / **Watch replay of my attempt** / **Open relevant lab from start** / **Continue past this step** (skip with no-credit).

### Sandbox mode (permadeath disabled + infinite resources)

`Sandbox` is one of the 4 storytellers (M25 spec) **plus** a profile-level flag (`profile.starting_mode = sandbox`). When sandbox is the active storyteller:

- `tutorial_safety = true` on every scenario load (lethal events demote to KO per DR-018)
- Permadeath disabled (Ironman-only storyteller has permadeath; Sandbox is its opposite)
- `infinite_resources = true` (ammo + medkits + battery + crafting inputs auto-refill from a sandbox-only spawn buffer; per-tick budget bypass for resource consumption)
- `no_xp_no_achievements = true` (player cannot earn XP / achievements / progression in sandbox; this prevents grind-skipping the live game)
- Skill-rating bot still runs (so tooltip fade still works) BUT bucket samples are tagged `sandbox=true` and weighted at 0.1× in the live composite (per the per-widget rule)
- All M33A labs + M33D mini-tutorials are unlocked from launch in sandbox mode
- Saves are clearly badged "SANDBOX" in the slot UI; sandbox saves cannot promote to Career saves

Sandbox toggle events: `sandbox.entered { profile_id, ms_into_session }`, `sandbox.exited { profile_id, ms_total }`.

### 8 in-game system tutorials (distinct from M33A's 8 standalone tutorial labs)

**Naming clarity:** M33A ships **8 standalone tutorial labs** (movement / combat / medical / engineering / AI command / hazards / inventory / objectives) — each a separate scenario the player launches from the Tutorials menu. M33D ships **8 in-game system mini-tutorials** (atmospherics / mining + refining / squad commands / cooking + food / IC10 chips / crafting + quality / combat + healing / vehicles + convoys) — each a self-contained mini-scenario that introduces a deeper subsystem. The two sets do NOT overlap; the combined game-wide total is **16 tutorial scenarios** (8 M33A labs + 8 M33D system mini-tutorials). The vision statement "8 tutorial labs" refers exclusively to M33A; M33D mini-tutorials are not labs.

Each in-game system tutorial is a self-contained scenario authored against the M33 editor + Lua + IC10 surfaces. Each plays in the M33A tutorial player widget (same UX as the 8 M33A labs, but the content is distinct subsystem-onboarding rather than mission-mechanic onboarding). Each ends with a "Now you try" sandbox handoff where the player keeps the scenario open in sandbox mode to experiment.

| Mini-tutorial | Topic | Mechanics covered | Duration |
|---|---|---|---|
| 1 | **Atmospherics** | sealed-room composition / hypoxia / combustible mix / vent + scrubber / damper / atmospheric analyzer reads | 5 min |
| 2 | **Mining + Refining** | tool affordance per material / ore vein detection / smelter inputs/outputs / quality tier / scrap recycling | 6 min |
| 3 | **Squad Commands** | 4 verbs (Follow / Hold / Defend / Push) + AI doctrine + priority weights + retreat trigger | 4 min |
| 4 | **Cooking + Food** | ingredient quality / per-recipe nutrition + morale buffs / stove + oven / spoilage + refrigeration | 4 min |

| 6 | **Crafting + Quality** | recipe inputs / tier progression T1→T4 / quality grades Common→Legendary / per-recipe time + fail rate | 5 min |
| 7 | **Combat + Healing** | aim + fire mode / cover / suppression / medkit + triage + bleed stop / KO vs death (tutorial_safety) | 5 min |
| 8 | **Vehicles + Convoys** | chassis + drivetrain / fuel / cargo + ammo loadout / waypoint route / ambush response | 5 min |

Each mini-tutorial has a manifest in `content/missions/tutorials/mini_<topic>.ron` + voice narration baked alongside M33A's voice prompts (per M37A) + entry hook in the tutorial menu (per M27A) + completion achievement (e.g. `complete_atmospherics_mini_tutorial`) that maps onto the progressive-disclosure unlock graph.

## Notes for the implementer

- **cfctl write-merge convention** — multiple specs each add ~5 cfctl methods to `cf-control/src/server.rs`; to avoid merge conflicts and tangled handlers, **M33D creates `game/crates/cf-control/src/m33d_actions.rs`** containing the 8 cfctl method handlers (`act.fre.advance_step`, `act.fre.set_preset`, `act.fre.run_calibration`, `act.tutorial.replay_step`, `act.tutorial.jump_to_step`, `act.tutorial.show_me_why`, `act.profile.toggle_sandbox_mode`, `act.profile.reset_tooltip_use_counts`) and registers from `cf-control/src/server.rs` via a `pub mod m33d_actions;` line plus a single `m33d_actions::register(&mut router)` call. `server.rs` itself stays a thin dispatcher; per-spec handler bodies live in their own files. Same pattern is mirrored by M33B / M33C / M37C.
- The FRE wizard MUST be skippable with two-step confirm; never lock a returning player out for >5s if they accidentally re-enter the wizard.
- The difficulty recommender table lives in `content/fre/difficulty_decision_table.ron`; modders can override it via mod-priority load order (per M33C) but the engine ships a vanilla copy that is the deterministic source-of-truth for `fre.difficulty_override` analytics.
- `cf-ai::skill_rating_bot` MUST seed off the engine's deterministic RNG channel `skill_rating_bot`; never `thread_rng()`. The bot is in `cf-ai` not `cf-sim-core` so this is a soft rule — but the per-tick budget MUST land inside `cf-sim-core`'s `ai_step` profile, not as a side-thread.
- Per-widget tooltip `hover_dwell_ms` is per-widget data in `content/ui/tooltip_widgets.ron` so authors can dial in fast hovers for combat widgets (200 ms) and slow hovers for codex panels (700 ms). ACC-A `motor_assist` preset adds +250 ms across the board.
- Sandbox-mode `no_xp_no_achievements = true` is checked at the achievement-fire site, not at the achievement-display site; achievements baked at content time are not stripped from the player's view of "all 75 achievements" — they're just non-earnable in sandbox.
- The "Disclose everything now" toggle is **UI-layer only**; the sim does not gate features on disclosure. A save written under disclose=on opens cleanly under disclose=off (the hidden widgets just don't render until earned).
- Tutorial replay reuses `cf-replay` snapshots; each tutorial step's `tutorial.step_entered` snapshot_hash is the rewind anchor; the per-profile completion record only mutates on success, never on rewind, so replay-grinding does not inflate `ms_total`.
- The 8 mini-tutorials' acceptance criteria live as inline scenario manifests; each `mini_<topic>.ron` ships its own per-step acceptance test (run via `cargo run -p cf-tutorial -- verify-mini <topic>`).
- All 12 new replay event schemas MUST be additive to `cf-replay::EventKind`; never break existing replay-bundle backward compat (M25B + M37A consumers depend on the schema being stable).
- The skill-rating bot's per-axis weights are exposed to Settings (player bias) but the underlying deterministic computation does NOT consult Settings — Settings only affect what gets shown to the player, not what the bot computes. This preserves replay parity across players with different bias preferences.

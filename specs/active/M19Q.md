# M19Q — Per-Actor Memory + Grudges + Favors + Relationship Persistence + Witness Propagation + Memory Decay

## Status

`active`

## Intent

RimWorld-grade per-actor memory: every actor carries a bounded slot ring of ~50–100 tagged event memories (`saw_steal`, `saw_kill`, `saw_kindness`, `received_gift`, `shared_meal`, `fought_together`, `saved_life`, `betrayed`, `insulted`, `praised`, `refused_aid`, `stolen_from`, `threatened`, `promoted`, `demoted`), each scored for significance, each decaying on a per-category curve, accumulating into per-target **grudge** and **favor** scalars that drive a relationship matrix; witnesses propagate memories via gossip when chatting (M26B), and the entire memory + relationship state survives save / load / replay deterministically.

After M19Q, an NPC the player robbed in hour 2 still glares at the player in hour 30, has told three friends about it, and when grudge crosses the revenge threshold will refuse aid, draw weapons, or sabotage a shared task — independent of M19P's trait sheet or M16C's PTSD trigger.

## Canonical ownership

Canonical owner of per-actor episodic memory ring, grudge / favor accumulators, relationship matrix update rules, witness propagation / gossip transport, and memory decay curves. M19P owns trait sheet + social bond category; M16C owns mental-health trigger consumption of `witness_death`; M26 owns faction-relationship deltas at the **faction** scope; M26B owns dialog-state consumption of relationship pip; M14I owns scar / veteran persistence. M19Q is the **per-actor-pair** layer between M19P (bond categories) and M26 (faction relationships).

## Player-facing behavior

- Every actor (player, NPC, pet, veteran roster member) carries a memory ring of capacity `memory_slot_max` (default 80; trait modifiers `forgetful = 50`, `sharp_memory = 120`) of `MemoryRecord` entries. When full, the lowest-significance entry is evicted first, ties broken by oldest tick.
- Each memory has a `MemoryTag` from a 15-tag launch roster, a `significance` in [0.0, 1.0] at acquisition, and a `decay_curve` keyed by tag category. Significance at observation tick `t_now` is `significance_at_acquire * decay(tag, t_now - t_acquired)`.
- Per-target **grudge** accumulator = `sum(-1 * signed_significance(m) for m in memories where target == other and signed_significance(m) < 0)`; per-target **favor** = the symmetric positive sum. Grudge or favor crossing a category threshold publishes `actor.relationship.threshold_crossed` and drives observable behavior changes.
- When two actors converse (M26B dialog session OR M19P social-tick chatter), a fraction of each actor's significant memories about a third party are copied into the other actor with a `gossip_origin` tag and a significance-multiplier ≤ 1.0 — so the village hears about the player's theft within a few in-game days.
- Memories influence M26B dialog branches via a `requires: MemorySee(tag, about: target, significance_min)` condition slot; an NPC who watched the player save their friend can unlock a "you saved Pavel — drinks are on me" branch.
- Memories persist 1:1 across save / load and survive replay reproduction. Schema version `memory_v1` is captured in the save header and migration is forward-compatible.
- Grudge threshold breach triggers per-actor behavior overrides (refuse-trade / refuse-aid / draw-weapon / sabotage / steal-back) via the existing M7 utility scorer and M19K priority promote / demote table.
- Per-tag observability surfaces in the M8 UX inspector: clicking an actor shows their top-5 memories about the inspected target, including significance, age in ticks, and gossip origin if propagated.

### Thresholds

| Threshold | Value | Behavior |
|---|---|---|
| `favor_friend_threshold` | +1.5 | Unlocks `praise` / `recruit` dialog branches |
| `favor_reciprocity_threshold` | +3.0 | Actor offers unprompted gift / aid (M19P social tick) |
| `grudge_avoid_threshold` | −1.5 | Actor refuses trade; avoids same-tile co-location |
| `grudge_revenge_threshold` | −4.0 | Actor enters Revenge state: M7 utility +0.6 on hostile actions toward target |

Trait modifiers (M19P consumer): `forgiving` multiplies negative significance acquisition by 0.5; `vengeful` multiplies by 1.5; `gossip` increases propagation fraction from 0.25 to 0.5; `secretive` decreases to 0.05.

## Acceptance criteria

```gherkin
Scenario: Memory ring evicts lowest-significance entry when full
  Given an actor with memory_slot_max = 80 and 80 stored memories
    And the lowest-significance entry is `shared_meal` at significance 0.18
  When a new `saw_kill` memory at significance 0.9 is offered
  Then the `shared_meal` entry is dropped
    And the `saw_kill` entry is stored
    And the ring length remains exactly 80
    And no other entry is mutated

Scenario: Per-tag decay reduces significance on the configured curve
  Given an actor stored a `saw_steal` memory at tick 0 with significance 0.6
    And the decay τ for `saw_steal` is 30 in-game days
    And the engine advances by exactly 30 in-game days of ticks
  When the actor's effective significance for that memory is read
  Then the value lies within 0.6 * 1/e ± 0.02 (≈ 0.22)

Scenario: Grudge accumulator crosses revenge threshold and publishes event
  Given an actor with no prior memories of the player
  When the player commits 5 `saw_steal` and 1 `betrayed` events witnessed by the actor
    And the resulting grudge sum first crosses -4.0
  Then exactly one `actor.relationship.threshold_crossed` event is emitted
    And its payload includes { actor_id, target_id, threshold: "revenge", value: <= -4.0 }
    And the actor's behavior FSM enters the Revenge state on the next tick

Scenario: Favor accumulator crosses reciprocity threshold and triggers unprompted gift
  Given an actor with grudge = 0 and favor toward the player = +2.4
  When the player triggers a `saved_life` event witnessed by the actor
    And the resulting favor sum first crosses +3.0
  Then exactly one `actor.relationship.threshold_crossed` event is emitted with threshold: "reciprocity"
    And within 24 in-game hours the actor's M19P social tick offers an unprompted gift trade to the player

Scenario: Witness propagation copies memory to bystanders within radius
  Given the player commits a `saw_steal`-eligible action in front of actors A and B
    And both A and B are within the witness_radius of 12 tiles
    And actor C is at 30 tiles (outside radius)
  When the action resolves on the storyteller tap
  Then A and B both gain a `saw_steal` memory targeting the player
    And C gains no memory from this event

Scenario: Gossip propagates a significant memory between conversing actors
  Given actor A has a `saw_steal` memory about the player at significance 0.6
    And actor B has zero memories about the player
    And A and B are in a M26B dialog session OR M19P social-tick chatter
    And actor A has trait `gossip` (propagation fraction 0.5)
  When the conversation completes
  Then actor B has acquired a memory about the player tagged with `gossip_origin: A`
    And the propagated significance is 0.6 * 0.5 = 0.3 ± 0.01
    And the original memory on actor A is unchanged

Scenario: Forgiving trait halves negative significance acquisition
  Given actors X and Y both witness the same `betrayed` event with default significance 1.0
    And X has trait `forgiving`
    And Y has trait `vengeful`
  When the event is recorded
  Then X's stored memory significance is 0.5 ± 0.01
    And Y's stored memory significance is 1.5 ± 0.01 (clamped to ring cap if needed)

Scenario: Save / load round-trips the memory ring deterministically
  Given an actor with 47 memory entries spanning 9 distinct tags and 3 gossip origins
  When the game is saved
    And a fresh process loads the save
  Then the actor's memory ring has exactly 47 entries
    And every entry's tag, target_id, significance, tick_acquired, and gossip_origin matches the pre-save value byte-for-byte (per the `memory_v1` schema)
    And the actor's grudge / favor scalars match pre-save values exactly

Scenario: Replay determinism over memory acquisition
  Given a recorded replay of 18000 ticks containing 312 memory acquisitions across 24 actors
  When the replay is re-executed from the same seed
  Then the final memory ring of every actor matches the recorded final state exactly
    And no `actor.relationship.threshold_crossed` event diverges in order or payload

Scenario: Dialog choice gate fires on MemorySee predicate
  Given the player saved actor Pavel's life 4 in-game days ago (saved_life memory, significance 1.0)
    And Pavel's dialog tree contains a choice with `requires: MemorySee(tag: saw_kindness OR saved_life, about: player, significance_min: 0.5)`
  When the player opens a M26B conversation with Pavel
  Then the gated choice is enabled
  When the player instead saved a different NPC and approaches Pavel with no qualifying memory
  Then the gated choice is disabled with tooltip "Pavel doesn't owe you that yet"

Scenario: Grudge-driven refuse-aid overrides squad triage utility
  Given actor M is a Medic role with PriorityTable[TriageDownedAlly] = 9
    And actor M has grudge toward the player at -4.2 (past revenge threshold)
    And the player goes Downed within M's triage radius
  When the M7 utility scorer evaluates TriageDownedAlly for M targeting the player
  Then the score is reduced by 0.6 from the grudge term
    And another candidate (or NoOp) wins the scorer
    And M does not dispatch to triage the player

Scenario: Inspector exposes top-5 memories per target
  Given the player inspects actor Vega via M8 UX
    And Vega has 22 memories about the player spanning 6 tags
  When the inspector requests `observe_frame` with detail=true
  Then the response includes Vega.memories_about[player] as an ordered array of 5 entries
    And each entry contains { tag, signed_significance, age_ticks, gossip_origin: Option<ActorId> }
    And entries are sorted by absolute signed_significance descending
    And the response also includes Vega.grudge[player] and Vega.favor[player] scalars

Scenario: Memory ring respects forgetful trait cap
  Given actor F has trait `forgetful` (memory_slot_max = 50)
    And F has 50 stored memories all at significance >= 0.4
  When a new significance 0.2 memory is offered
  Then the new memory is REJECTED (not stored)
    And no existing memory is evicted
    And no `actor.relationship.threshold_crossed` fires from this attempt
```

## Out of scope

- Faction-wide reputation deltas (M26 canonical owner).
- Per-NPC personalized dialog text generation from memory (M25A LLM expansion — M19Q only exposes the gate predicate).
- Mental-health condition triggers from witnessed memories (M16C consumes `witness_death`; M19Q only emits the memory record).
- Long-term scar / aging persistence (M14I owner).
- Per-pet bond curve (M19P pet-behavior scope; M19Q stores the tagged memory, M19P interprets pet-specific reaction).
- Witness propagation to neutral / off-screen actors via rumor LLM (M25A future scope).
- Multiplayer cross-client memory reconciliation (M43 PvE Survival scope).
- Cosmetic visualization of grudge / favor (M9A portrait expression coupling — M9A consumer).

## Notes for the implementer

- Memory acquisition + decay tick MUST seed off the engine's deterministic RNG stream — never `thread_rng`. The propagation fraction roll and the gossip selection roll both consume the sim RNG.
- Decay is computed lazily on read (`signature(t_now) = sig_acquire * exp(-dt_days / τ)`); do NOT iterate every memory every tick. The threshold evaluator runs only on memory acquire / on memory eviction / on conversation completion — three event-driven hooks, not a per-tick scan.
- The bounded ring uses a binary-heap-ordered evict slot rather than a sort-on-insert array; eviction is O(log n) on a slot count of ≤120, well under the per-actor tick budget.
- `MemoryRecord::target_id` is `Option<ActorId>`; some tags (`shared_meal` with the squad) admit a `None` target meaning "the group" — handle with a NULL-target bucket in the relationship matrix and treat it as broadcast favor against squad-mates at observation tick.
- `gossip_origin` chains MUST NOT compound infinitely: when actor C gossips to D about a memory C heard from B (who heard from A), the propagation fraction is applied cumulatively and the chain stops when significance drops below the gossip cutoff (default 0.1). Store only the immediate origin, not the full chain.
- The `actor.relationship.threshold_crossed` event MUST be edge-triggered, not level-triggered: emitting once on the tick the threshold is first crossed, and re-emitting only after the value drops at least 0.5 below the threshold and crosses again. This prevents oscillation chatter.
- M19K's role promote / demote already publishes `role.changed`; wire that producer to also enqueue `promoted` / `demoted` memories on every actor that observed the change (or for whom the promoted/demoted actor is in the same squad — broadcast within the squad ring).
- `content/ai/memory_thresholds.json` ships under M3B hot-reload — modders can rebalance favor / grudge thresholds and per-tag decay τ without a code change.
- Do NOT short-circuit the threshold publish during replay: the replay determinism test depends on edge events firing on the same tick.

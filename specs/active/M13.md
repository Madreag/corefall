## Player-facing behavior

### Chassis archetypes — M13 ships 5 (was 3 in v0; M6-M8 bridge routing added 2)

- **Infantry** (default; baseline humanoid)
- **Powered armor** (Spartan-ish; +50% HP, +30% mass, jet module)
- **Light mech** (~3× human; cockpit anchor, full module set, pilot ejection critical)
- **Crab / quadruped** (NEW; 4 legs + lateral scuttle stance; non-humanoid body graph: 4 legs + 2 claws + carapace + sensor cluster; no jet; M6-M8 routing)
- **Drone** (NEW; autonomous miniature chassis; no pilot; 3 modes Follow/Auto-Mine/Auto-Repair/Auto-Carry; M6-M8 routing — see Drone Allies section)

Each chassis has a body graph: humanoid=15 zones (head, torso, arms, forearms, hands, legs, shins, feet, backpack), 14 joints, 5 equipment sockets. Quadruped=11 zones (4 legs + 2 claws + torso + sensor cluster + carapace). Drone=4 zones (chassis + 2 arms + sensor pod).
- Armor is layered: External → Internal → Core → wound. Each layer has its own HP and hardness.
- Modules: jet, shield, sensor, repair-drone, weapon-mount. Each module has state Nominal → Degraded → Warning → Failed → NotPresent.
- Damage stages: nominal → degraded → module-warning → module-failed → weapon-jammed → armor-cracked → disabled → pilot-injured → eject → bail-too-late → wreck → gibbed/exploded.
- Limb damage has consequences: limp on leg loss, one-arm rifle handling on arm loss, dropped gear on hand loss, disabled grip, reduced climb/jump/jet.
- Pilot eject works: when chassis stage hits eject, the pilot detaches (shown as a separate small actor) and can continue. If the eject window expires, bail-too-late.
- Chassis salvage: after wreck, the player can salvage modules with `act.chassis.salvage` and pick up recoverable parts.
- Repair: `act.chassis.repair --zone <zone>` repairs a damaged zone (consumes repair-drone capacity if present).

### Hit zone determination — how a 2D side-view projectile picks a limb

**The 2D-side-view question**: when a projectile hits an actor, which zone (head / torso / arm / leg / foot) takes damage?

**Per CCCP `Atom::Travel` + Soldat `Sprites.pas` precedent**: side-view games use **stance-aware AABB-per-zone** with the projectile's **impact point in actor local space** determining the zone hit. Pixel-perfect masks are too expensive at 50-actor scale; per-zone AABBs are fast + deterministic.

**Algorithm (locked at M13):**

```text
PROJECTILE-VS-ACTOR HIT DETECTION (deterministic; no RNG)

1. Sweep collision test (M14): projectile path vs actor overall AABB
   → if no intersection: miss; continue
   → if intersection: compute entry_point in world space

2. Transform entry_point to actor local space (origin = actor.position)
   local_x = entry_point.x - actor.position.x  (signed; negative = left of actor center)
   local_y = entry_point.y - actor.position.y  (signed; positive = above actor center)

3. Mirror local_x by facing direction:
   if Actor::facing == Left:
     local_x = -local_x  // flip so "near arm" is always on positive-x side

4. Lookup per-stance zone AABB table (see below); test which zone's local AABB contains the entry point

5. Refine by Y-position (vertical zoning is primary cue for side-view):
   for HUMANOID STANDING:
     y_rel = local_y / actor.height
     if y_rel ∈ [0.85, 1.0]:    candidate = head
     if y_rel ∈ [0.55, 0.85]:   candidate = torso (or arms if x near edges)
     if y_rel ∈ [0.45, 0.55]:   candidate = abdomen
     if y_rel ∈ [0.10, 0.45]:   candidate = legs (front or back per local_x)
     if y_rel ∈ [0.00, 0.10]:   candidate = feet

6. Refine candidate by X-position (per facing direction):
   if local_x ∈ [near_arm_xrange] AND y_rel ∈ [arm_yrange]:
     candidate = arm_near
   if local_x ∈ [far_arm_xrange]:
     candidate = arm_far  // partly hidden behind torso

7. If projectile direction is mostly horizontal AND hit is at torso/arm Y-band:
   → torso candidate (50% likely target)
   → check arm_near in front of torso (if projectile from facing direction)
   → check torso direct hit

8. If projectile from above (sky-shot / falling):
   → head + shoulders + backpack are exposed
   → torso_top + shoulders + jet_pack

9. If projectile from below (low angle):
   → feet + legs + abdomen exposed
   → head + torso are NOT hit (blocked by legs)

10. Per CCCP `MOSRotating::CollideAtPoint`:
    - Apply zone's armor (M9 angled armor math)
    - Compute effective_thickness per zone's mount angle vs incoming direction
    - Roll ricochet probability per zone surface (per M9)
    - If penetration: M14 ray traverses through chassis (M13 modules) in projectile direction
    - Subsequent zones along ray path can take secondary damage
```

| `torso_front` | -0.30 to 0.0 | 0.45 to 0.85 | Facing direction = chest |

### Per-stance hit probability distributions (designer reference)

For a typical horizontal shot at standing actor from front, the deterministic AABB tests yield roughly:

| Stance × shot angle | Head | Torso | Arms | Legs | Feet |
|---|---|---|---|---|---|
| Standing × horizontal | 12% | 50% | 15% | 20% | 3% |
| Standing × from above | 60% | 25% | 8% | 5% | 2% |
| Standing × from below | 5% | 15% | 10% | 50% | 20% |
| Crouching × horizontal | 8% | 60% | 15% | 17% | — |
| Prone × horizontal | 30% | 50% | 12% | 8% | — |
| Crawl × from above | 35% | 45% | 12% | 8% | — |

These distributions emerge naturally from AABB sizes — NOT from random rolls. The player learns to aim at vulnerable zones (head for instant kills; legs for crippling without killing).

### Multi-zone passthrough — when projectile passes through one zone into another

Per M14 ray traversal: high-velocity projectile can pass THROUGH a zone and continue into another zone behind it (front-back). For example:

- AP round hits arm_near → penetrates → continues into torso → hits liver organ
- HEAT shaped charge hits torso → ray through to far side → emerges from torso_back
- Sniper hits leg_front → ray continues backward through leg_back → exits at far side

**Event chain for multi-zone hit:**

```
1. combat.projectile_hit_mo fires for arm_near (entry zone)
2. armor.layer_destroyed fires for arm_near armor
3. armor.penetration_ray_traversed fires (M14)
4. combat.projectile_hit_mo fires for torso (secondary zone, with reduced energy)
5. M14 ray hits internal organ (liver)
6. internal.organ_damaged fires for liver
```

### Side-view body layout (2D side-profile orientation)

**Per DR-019 visual direction + Soldat / Cortex-Command lineage**: Corefall is a **2D side-view game**. Actors are rendered as side-profile sprites — they face LEFT or RIGHT (never into/out of camera). The user noted current limb resolution "seems to be facing the camera" — M13 corrects this with explicit side-view body orientation.

**Side-view body orientation:**

- `Actor::facing: FacingDirection { Left | Right }` — explicit field; flips sprite + armor zone visibility
- Each chassis zone has a side-view orientation:
  - `head`: top-center; always visible
  - `torso`: side-profile; chest faces forward (current facing direction)
  - `arms`: 
    - "Near arm" = arm closer to camera (always visible)
    - "Far arm" = arm farther from camera (mostly hidden behind torso)
  - `legs`: both visible as side-profile (front leg slightly forward; back leg slightly behind)
  - `backpack`: behind torso (visible when facing perpendicular to view)
  - `feet`: paired side-by-side at the bottom

**Side-view hit zone routing:**

When projectile hits actor:

| Enemy fire direction (relative to actor) | Body zones exposed |
|---|---|
| Front (facing left → enemy at left) | head_front, torso_front, near_arm, near_leg |
| Back (facing left → enemy at right) | head_back, torso_back, far_arm (now exposed), far_leg, backpack |
| Top (overhead) | head_top, torso_top, shoulders, backpack |
| Bottom (low angle) | feet, legs, abdomen |

This means **angled armor + facing direction matter together**: an actor facing toward enemies is harder to penetrate than an actor facing perpendicular to the threat. M9 + M13 armor angle math respects facing direction.

**Sprite render contract:**

- `cf-render-2d::actor` renders sprite based on `Actor::facing`
- Walk-cycle animation per stance + facing direction
- Sprite flip per facing change (instant; cosmetic)
- Side-profile silhouette: head + torso side + 2 arms (near + far) + 2 legs (front + back) + backpack
- M11 HUD silhouette widget renders the side-profile body (not the camera-facing perspective)
- Animation frames per stance + facing direction (e.g. walking-left + walking-right)

### Limb loss functional consequences — per-zone capability degradation

The user demand: **"limbs can also be lost/blown off, cut, etc... that doesn't kill outright, but it does lose what the limb does... its legs for walking, arms for holding and using weapons, head (instant death?) etc..."**

Per CCCP body-damage-wound-gib-lifecycle (vault audit) + M13 chassis 15-zone body graph. M13 ships the **functional capability degradation matrix** when limbs are lost (per zone):

**Head loss:**

- `head` HP = 0 (via direct damage OR severed via heavy melee/explosion)
- **Consequence: INSTANT DEATH** (per CCCP `AHuman.cpp:2620` decapitation rule)
- No recovery possible without prosthetic (M25+)
- Event: `actor.head_destroyed` → instant `actor.status_changed=DEAD`

**Torso loss:**

- `torso` HP = 0 = catastrophic loss
- **Consequence: INSTANT DEATH** (cannot survive without torso; per CCCP)
- Event: `actor.torso_destroyed` → instant DEAD

**Arm loss (per arm):**

- `arm_left/right` severed → `Attachable::Detached` per M14
- **Consequence**: 
  - Held weapon DROPS (per CCCP `Actor.cpp:1215`)
  - Cannot fire two-handed weapons (rifle / sniper / shotgun / grenade launcher) — REJECTED with reason "no_arm_for_two_hand_weapon"
  - Can fire one-handed weapons (pistol) at reduced accuracy (+30% bloom)
  - Cannot perform melee_bash with that arm
  - If both arms lost → cannot fire ANY weapon; cannot use any tool
- Event: `actor.arm_severed { side, cause }`

**Forearm loss:**

- Less critical than full arm
- **Consequence**:
  - Grip degraded (50% chance to drop weapon per shot fired)
  - Aim wobble × 2 with that hand
  - Cannot two-hand-grip rifles
- Event: `actor.forearm_severed { side, cause }`

**Hand loss (per hand):**

- Hand HP = 0 (per zone)
- **Consequence**:
  - Cannot grip weapon — DROPS immediately
  - Can pick up items in non-handed slot (backpack)
  - Cannot use tools
- Event: `actor.hand_severed { side, cause }`

**Leg loss (per leg):**

- `leg_left/right` severed → Attachable detached
- **Consequence**:
  - Stance: `KneelStance` (per-leg knee balance) — speed × 0.4
  - Cannot sprint
  - Cannot jump
  - Jet pack still works (if backpack intact + powered)
  - Crawl-stance if both legs lost
- Event: `actor.leg_severed { side, cause }`

**Shin loss:**

- Less critical than full leg
- **Consequence**:
  - Limp animation
  - Speed × 0.7
  - Cannot vault / climb
- Event: `actor.shin_severed { side, cause }`

**Foot loss (per foot):**

- **Consequence**:
  - Minor speed reduction (× 0.85)
  - Cannot kick (M6 melee)
- Event: `actor.foot_severed { side, cause }`

**Both legs lost (crawl mode):**

- Stance: `Crawl` (continuous on ground)
- Speed: 25% normal walk speed
- Sight range: reduced (low height)
- Cannot fire two-hand weapons (need to balance)
- Banner: "CRAWLING — both legs lost"

**Both arms lost (no weapons):**

- Cannot fire any weapon
- Cannot use any tool
- Can still walk + jump + jet
- Tactical: must avoid combat; melee-kick only
- Banner: "DISARMED — both arms lost"

**Backpack loss:**

- Battery module disabled (if applicable)
- Inventory storage capacity = 0 (cannot pickup items)
- Carried items DROP at impact site
- Event: `actor.backpack_severed { cause }`

### Limb severance triggers (per CCCP joint physics)

Per CCCP `Attachable::Update` + M14 contract. Limbs sever when:

1. **Joint impulse > joint_strength** (per CCCP):
   - Light hit: joint takes damage but holds
   - Heavy hit: joint impulse exceeds strength → DETACH
   - Per-zone `joint_strength_n` field (e.g. arm joint = 1500 N; leg joint = 2500 N)

2. **High-velocity projectile** (per M14 ray):
   - Sufficient kinetic energy passing through joint zone → instant severance
   - Sniper / APFSDS / HEAT can sever joints with one hit

3. **Heavy melee severance** (per M6 melee weapons):
   - Hatchet / katana / chainsaw can sever joints (50% chance per heavy hit + roll vs joint_strength)
   - Damage_kind=cutting weapons have severance bonus
   - Light melee (knife / baton) cannot sever joints

4. **Explosion proximity** (per M14 explosion model):
   - Explosion radius + impulse on actor → joint impulse roll
   - Close-range explosions can sever multiple limbs simultaneously
   - Per CCCP `MOSRotating::DetachAttachablesFromImpulse`

5. **Falling damage** (per M14 physics):
   - Hard landing (velocity > threshold) → leg joint impulse
   - If joint impulse > strength → leg severance
   - Falling onto sharp terrain (spikes, broken metal) → severance bonus

6. **Vehicle ramming** (per M14 chassis collision):
   - High-velocity vehicle impact → multiple joints take impulse
   - Sufficient impact severs limbs facing the rammer

### Physics-driven limb damage (M14 forward-compat)

**Falling damage routes to legs first:**

- Per M14 impulse routing: vertical landing impulse routes to feet → shins → legs (in that order)
- Per zone, impulse is absorbed proportional to mass × material hardness (bone/circuit)
- If accumulated impulse exceeds zone's `joint_strength` → severance
- Example: fall from 20m → impact velocity ~20 m/s → impulse on foot ~ 60 kg × 20 m/s = 1200 N → exceeds foot joint (500 N) → foot severed

**Ramming damage routes to facing direction:**

- Chassis collision with another chassis or wall → impulse on forward-facing zones
- Forward-facing arm + leg take primary impulse
- If accumulated impulse exceeds joints → severance
- Cosmetic: 200ms hit-stop (per DR-055) on heavy ramming

**Explosion-proximity severance:**

- Explosion within radius → impulse on all zones inversely proportional to distance
- Multiple zones can sever simultaneously (per explosion strength)
- Per CCCP `MOSRotating::DetachAttachablesFromImpulse`: nearest attachable severs first if impulse > joint_strength

**Per-module positioning + War Thunder-style module ray traversal**

Per M9's reserved penetration ray surface — M13 fills with full module hit detection per chassis:

**Per-chassis module positions:**

Each chassis has internal modules with AABB positions (in chassis local space):

| Chassis archetype | Modules + positions (relative to chassis center) |
|---|---|
| **Infantry** (humanoid) | head_module (head zone), heart_module (torso center), lungs (torso upper L+R), spine (torso back center), gut (torso lower) |
| **Powered armor** | + jet (backpack), power_core (torso center), targeting_computer (head), gun_mount (arm), shield_emitter (chest) |
| **Light mech** (cockpit + frame) | + cockpit (top-front; pilot inside), reactor (torso center; large), fuel_tank (torso back; large), ammo_rack (torso side; explosive), engine (torso back; fire-risk), transmission (between torso + leg), motor_controller_per_leg, optics_pod (head), comm_relay (head), targeting_computer (chest) |
| **Crab / quadruped** | + sensor_cluster (front), carapace_core (torso center), 4× motor_controller_legs, fuel_tank (back), oil_reservoir, coolant_pump |
| **Drone** | + power_core (center), sensor_pod (top), motor_controllers, comm_relay |

Each module has:
```rust
pub struct ChassisModule {
  pub id: ModuleId,
  pub kind: ModuleKind,         // Cockpit / Reactor / AmmoRack / Engine / Optics / etc.
  pub local_aabb: Aabb,         // bounding box in chassis local space
  pub hp: f32,
  pub max_hp: f32,
  pub bound_to_zone: ChassisZone,
  pub backstop_armor: Option<ArmorRef>,  // inner armor that protects this module from far-side hits
  pub failure_cascade: FailureCascade,
}
```

**Penetration ray traversal flow** (per CCCP `Atom::Travel` extended for chassis):

```text
1. Projectile achieves penetration through outer armor at impact_point
2. Compute remaining_energy = projectile_energy * (1 - armor_absorption_factor)
3. Trace ray from impact_point along velocity_vector through chassis local space
4. For each module AABB intersected (in ray-order):
   a. Apply damage_to_module = remaining_energy * module_damage_multiplier
   b. remaining_energy -= damage_absorbed_by_module
   c. If remaining_energy ≤ 0: projectile stops at module
   d. If remaining_energy > 0: continue to next module
5. If projectile exits chassis through backstop armor:
   a. Apply backstop armor check (M9 angled armor math)
   b. If penetrates → emerges from chassis other side
   c. If absorbed → stops at backstop
6. Spalling fragments fire INTO chassis from impact_point (random 30° forward cone)
7. Each spalling fragment performs simplified ray (damage = 0.2-0.5 of original)
```

### Critical chassis modules with full mechanics

**Cockpit module** (pilot inside; mech weight class only):
- Pilot HP = pilot actor HP (M13 has dual silhouette per M11)
- Cockpit penetration → pilot takes direct damage
- Cockpit fully destroyed → pilot ejects OR dies inside
- Cockpit damage tier: scratched (visible cracks; no penetrator yet) → cracked (small spalling) → critical (60% damage; pilot wounded) → destroyed (pilot killed if no eject)

**Ammo rack module** (explosive cascade):
- AmmoRack HP track + `ammo_quantity_remaining`
- When ammo_rack penetrated:
  - First-hit: visible explosion + 1/3 ammo "cook off" (random rounds detonate)
  - Severe-hit: full ammo rack detonation = chassis destroyed in massive explosion (catastrophic event)
- M4 event: `module.ammo_rack_cooking`, `module.ammo_rack_detonated`
- HUD: red HUD-warning when ammo rack at 30% HP

**Engine module** (fire risk):
- Engine HP track + `oil_level` + `coolant_level`
- Engine penetrated → oil leak fires if fluid system damaged (per M9 fluid system)
- Engine fully destroyed → chassis immobile + cascading fuel ignition if fuel adjacent
- Engine fire effect: continuous afflictions.burning on adjacent modules

**Optics module** (vision impairment):
- Optics HP track
- Optics damaged → reduced sight range × 0.5
- Optics destroyed → blind (sight range = melee only; can't aim)
- HUD: "OPTICS DAMAGED" warning + blurred reticle effect

**Transmission module** (mobility):
- Transmission HP track
- Damaged → reduced movement speed × 0.6
- Destroyed → chassis immobile (cannot move; can still fire)
- Per-leg motor_controller similar pattern

**Reactor module** (catastrophic if destroyed; M9 reactor model carried into M13 chassis):
- Reactor HP track + `pressure_state` (M9 5-tier signature)
- Penetration → pressure_state advance
- Critical → atmos.gas_released (volatiles); ignition risk
- Destroyed → mission-critical loss (per M13 chassis stage=disabled cascade)

**Crew slot modules** (per chassis crew; M25+ vehicles):
- For vehicles M25+ that carry multiple actors (gunner / loader / driver / commander)
- Each crew member is a separate actor instance bound to chassis
- Crew member HP independent; one knockout doesn't kill chassis
- M9/M13 ships infantry baseline (1 pilot); M25 vehicles extend with multi-crew

### Spalling integration with chassis modules

Spalling fragments fire INTO chassis from impact_point:
- 1-3 fragments per `spalling_threshold` crossing (per armor type)
- Each fragment: random angle within 30° forward cone (relative to impact normal)
- Each fragment: simplified ray traversal hitting 1-2 internal modules
- Per-fragment damage = 20-50% of original projectile damage
- M4 event: `module.spalling_damage { module_id, fragment_id, damage }`
- M13+ chassis: spalling can knock out crew slots (each fragment may hit a crewmate)

### Armor mounting angles per chassis archetype

Each chassis has natural mounting angles per zone:

| Chassis archetype | Front armor mount | Side armor mount | Back armor mount |
|---|---|---|---|
| Infantry (powered armor) | 0° (vertical) | 0° | 0° |
| Powered armor (Spartan-ish) | 15° forward slope | 0° | 15° back slope |
| Light mech (cockpit) | 30° slope (cockpit angled) | 0° | 15° slope |
| Heavy mech | 45° slope (deeply angled) | 30° angled side | 30° back slope |
| Crab / quadruped | 30° angled carapace | 30° flank slope | 30° rear slope |
| Drone | 0° (small target) | 0° | 0° |

Players can **rotate / face their actor toward incoming fire** to increase effective armor:
- Facing direction tracked per tick
- HUD armor angle indicator (M11) shows current facing relative to threat
- Tactical pattern: angle armor at 30-45° to bounce shots; minimize side-armor exposure

### Tutorial-safety scenario variant (per DR-023)

- `scenario.tutorial_safety=true` → lethal damage caps at DYING (pilot survives even if chassis destroyed)
- Allows new players to learn chassis system without permanent loss
- M13 ships tutorial variant of each chassis archetype

## Out of scope

- Full collision physics (limb-to-limb, projectile-projectile contacts) — M14
- Material kernel (sand falls, water pools, fire spreads) — M15
- Atmospherics (PV=nRT gas/liquid) — M19
- Universal gravity ballistic drag — M16
- Ricochets / tracer rounds — M14+ visual juice
- Body damage extension into M10 replay viewer — M10 done; chassis death events feed it
- M20 worlds / factions / narrative — BP6+

## Dependencies

- M1 actor controller (must be done): ActorState, body status state machine.
- M3 chunked terrain (must be done): chassis movement collides with terrain pixels.
- M4 event recorder (must be done): chassis events flow into events.jsonl.
- M11 readability (must be done OR concurrent): HUD silhouette + module strip read chassis state.
- **M8A (must close before M13 lands)**: chassis state lives as an ECS component bundle (per M8A's ECS migration of `ActorWorldComponent`). `ChassisModule[]`, `armor_layers[3]`, `power_grid`, `repair_pads`, `doors`, `uprooted_avatar` are all serde-compatible fields the Powder-Toy-derived snapshot envelope (M8A § "Snapshot Field Contract") restores byte-identically. Per-chassis tick (limb impulse routing, armor cascade, module status) runs in M8A's snapshot-read / compute-parallel / commit-serial pattern. Chassis state crosses the determinism boundary (no `thread_rng`, no default-hashed `HashMap`, no `f64` in armor / module / power calculations).

## Notes for the implementer

- The 3 chassis archetypes (`infantry_v1`, `powered_armor_v1`, `light_mech_v1`) live in `cf-chassis::spec`. Half-extents: infantry 8x16, powered armor 10x20, light mech 18x36. Visual proportion (Spartan-ish, mech-ish) is render-layer asset work, not sim data.
- `apply_zone_damage` MUST be monotonic on stage advancement — once stage=disabled, never goes back to nominal without explicit `repair` or `force_stage` (test-only).
- `EjectWindow.ticks` MUST be tick-rate-stable: at 120 Hz, the window in real seconds is the same as at 60 Hz. Use `from_real_seconds(seconds, tick_rate_hz)` for construction.
- LOAD-A loadouts must export to `content/equipment/loadouts/*.json` and be loaded at runtime — NOT hardcoded in Rust. The hardcoded versions in `cf-equipment::loadout::load_a_*` are the seed data the export script writes from.
- 7 cfctl methods + 13 chassis events: any future cf-control schema bump must include a migration shim. (Current policy: additive methods don't bump SCHEMA_VERSION; if you change a method's params shape, that's a bump.)
- Pilot eject is a real actor split: the pilot becomes a new ActorId with its own ActorState (no chassis attached). The chassis becomes a wreck (interactable for salvage). Don't model eject as a state flag on the same ActorId.

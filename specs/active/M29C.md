# M29C — Power Grid Failure Cascade + Recovery Scenarios

## Status

`active`

## Intent

Ship 8 flagship scenarios that teach players the M29 cascade model + battery economy as deep gameplay tension — turn the contract into playable proof.

## Player-facing behavior

- Reactor overheats + breaker trips → cascading shutdown → emergency lighting → critical systems only → mission failure cascade if player can't restore in 90s. Pure Stationeers tension.
- "Watch the gauge" missions: depart base with full T2 battery, drill 3 distant veins, return before NVG goes dark. M30 mining + M14A mass + M29 battery in one playable loop.
- Brown-out attrition: enemy raid forces defense load up; without enough generators, turrets shed mid-fight; player learns to plan generation capacity ahead of need.
- Cold snap: weather (M31) drops local temp 30°C; heated suits draw 3× rate; mid-mission battery crisis.
- EMP raid: enemy EMP grenade disables base electronics + IC10 chips for 30s; player must restart load shed manually.
- Battery fire: thermal_runaway propagates from one battery rupture; player must vent the room + isolate the affected bank.
- Solar eclipse: per DR-039 astrography event drops solar to 0% for 6 in-game hours; base must run on stored + chemical generators only.
- Power cable arc-fault: damaged cable arcs into combustible atmosphere → secondary fire → racing-clock challenge.

## Acceptance criteria

```gherkin
Scenario: m29c_01 — Reactor meltdown recovery
  Given a base with nuclear_reactor + coolant_loop_assembly + Heavy Trooper actor
  When the radiator is sabotaged at tick 600
  Then coolant_loop heat accumulates per tick
  And brown-out cascade begins at tick 750
  And player has 90 seconds to dispatch repair crew + replace radiator
  When repair completes before tick 900
  Then mission_success fires
  Else mission_failed_reactor_meltdown fires

Scenario: m29c_02 — Battery attrition field op
  Given a powered_armor actor with T2 battery (5 kWh) + NVG + radio
  And 3 ore veins at 400m / 600m / 800m from base on Mimas (cold ambient)
  When the player drills all 3 veins
  Then total power consumption ≈ 2.8 kWh (drill + suit + NVG + radio)
  And the actor has ~1 kWh reserve for return trip
  When the player returns to charging pad
  Then mission_success fires
  When the player attempts a 4th vein
  Then NVG sheds at 30% threshold + radio sheds at 15% + sealed_suit_life_support holds
  And mission_failed_attrition fires if actor runs INERT before charging

Scenario: m29c_03 — Brown-out under raid
  Given a defended base with 4 turrets + 8 enemies attacking
  And generation capacity = 20 kW; load with turrets active = 24 kW
  When all 4 turrets fire simultaneously
  Then load = 28 kW > 20 kW supply
  And brown-out (mild) triggers: lights dim + cosmetic systems off
  And 1 turret sheds at brown-out (severe) threshold
  And player must place additional generators OR sacrifice turret coverage

Scenario: m29c_04 — Cold snap crisis
  Given a base with 3 actors in heated suits + ambient temp 15°C
  When weather event "cold_front" fires (per M31) dropping ambient to -15°C
  Then heated_suit draw triples per M29B table (10 W × ΔT)
  And total grid load increases 600 W per actor (1.8 kW total spike)
  And brown-out (mild) triggers within 5 ticks
  And player has 60s to add generator OR reroute heated_suits to critical priority

Scenario: m29c_05 — EMP raid recovery
  Given a base with 3 IC10 chips + 5 turrets
  When an enemy EMP grenade detonates within 4-tile radius
  Then IC10 chips offline for 30 seconds (per M29 EMP spec)
  And turrets default to manual until IC10 restored
  And player must defend manually OR power-cycle the chips
  After 30 seconds, IC10 chips boot back up + custom load shed resumes

Scenario: m29c_06 — Battery fire isolation
  Given a battery_bank with 4 batteries, one at 95°C (thermal_runaway risk)
  When the runaway threshold (80°C) is exceeded
  Then power.battery_thermal_runaway fires
  And the affected battery ignites adjacent combustible material per M15
  And player must:
    1. Manually isolate the affected battery via breaker
    2. Vent the room via emergency_vent (M28B)
    3. Wait for fire to extinguish
  When mission_objective "fire_extinguished" completes
  Then mission_success fires

Scenario: m29c_07 — Solar eclipse endurance
  Given a base with 4 solar_panel + 0 chemical generators
  When DR-039 astrography event "solar_eclipse" fires
  Then solar generation = 0% for 6 in-game hours
  And the base must run on battery_bank discharge alone
  And per-tick load shed cascade keeps critical systems online
  When eclipse ends + solar returns
  Then mission_success fires

Scenario: m29c_08 — Arc fault chain in combustible atmosphere
  Given a base with damaged cable in a methane-rich room (M19 Volatiles > 5%)
  When the cable arcs (per M29 arc_fault event)
  Then arc heat exceeds Volatiles autoignition (573 K)
  And local combustion ignites per M19 + M15
  And fire cascades along cable run within 5 ticks
  And player must:
    1. Manually trip the upstream breaker
    2. Vent the affected room
    3. Repair the cable
  When all 3 objectives complete, mission_success fires

Scenario: Determinism + replay across all 8 scenarios
  Given each scenario run twice with the same seed + same inputs
  When each run completes 600 ticks
  Then per-tick event stream is byte-identical
  And SaveBlob.checksum at scenario_end is byte-identical
```

## Notes for the implementer

- Each scenario should ship with a 1-2 minute cfctl smoke script so CI can drive it deterministically.
- The "battery attrition field op" (scenario 02) is the canonical flagship — implement it FIRST as proof; others follow the same pattern.
- Reward structure: clean completion = bonus, recovered-just-in-time = base reward, failed = lesson-learned debrief (replay walks the player through the cascade chain via M10 viewer).
- Commander AI doctrine `prioritize_generator_protection` fires when grid surplus < 20% — orders nearest squad to defend the generator zone.

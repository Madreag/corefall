# M2.5 — Micro Reactor Defense Fun Slice

## Status

`active`

## Intent

One 60-90 second `micro_reactor_defense` scenario that proves M2 chunked terrain is fun in the player's hands: dig a trench around the reactor, hold position while one reactive enemy attacks for 60 seconds, win if the reactor survives, lose if it explodes. Win and loss both ship as scripted cfctl runs with full terrain + combat + mission events.

## Player-facing behavior

- Player spawns at a generator core. An objective banner says "Defend the reactor for 60 seconds."
- The reactor is a single non-player static actor with HP, visible on the HUD.
- A countdown timer ticks from 60s down to 0.
- One reactive enemy spawns and attacks. The player can dig a trench around the reactor for cover/defense.
- HUD shows: reactor HP bar, time-remaining timer, player HP, enemy HP, last important event.
- Win = reactor survives 60 seconds. Lose = reactor HP reaches 0 (with `mission.loss_reason=reactor_destroyed`) OR player dies.
- Both outcomes emit `mission.mission_resolved`.

## Acceptance criteria

```gherkin
Scenario: Win path with trench
  Given a fresh micro_reactor_defense scenario
  When the cfctl script micro_reactor_defense_win.cfctl.json runs
  Then the player digs a trench (terrain.terrain_carved count >= a defined threshold for trench-shape)
  And the reactor survives the 60-second timer
  And mission.mission_resolved fires with result=won, objective.defend_reactor=completed
  And cf-e2e wins all 4 expectations

Scenario: Loss path — reactor destroyed
  Given a fresh micro_reactor_defense scenario
  When the cfctl script micro_reactor_defense_loss.cfctl.json runs
  Then enemy fire damages the reactor over time
  And the reactor HP reaches 0 before the 60-second timer
  And mission.mission_resolved fires with result=lost, loss_reason=reactor_destroyed
  And cf-e2e wins all 3 expectations

Scenario: No-trench loss is faster than with-trench
  Given a fresh micro_reactor_defense scenario
  When the cfctl script m2.5_no_trench_loss.cfctl.json runs
  Then the player does NOT dig a trench (terrain.terrain_carved count == 0 OR very small)
  And the reactor dies before the 60-second timer
  And the resolution time is shorter than the with-trench loss path

Scenario: Reactor HP visible in HUD and observe surface
  Given the scenario is running
  Then the HUD shows a reactor HP bar with current/max
  When cfctl observe.mission.reactor_hp runs
  Then the response includes current_hp and max_hp

Scenario: Reactor damage emits structured events
  Given the reactor takes damage from enemy fire
  When the damage is applied
  Then mission.reactor_hp_changed fires with from=<old>, to=<new>, cause="projectile_hit", source_actor_id=<enemy_id>

Scenario: 60-second timer drives the win
  Given the scenario is at tick 0
  When 3600 ticks (60 seconds at 60Hz) pass without reactor death
  Then mission.mission_resolved fires with result=won, time_elapsed_ticks=3600

Scenario: Run bundles validate
  Given the win and loss bundles
  When the canonical run-bundle checker runs
  Then errors=0 for both bundles
  And the bundles include T-CAPTURE summary grids
```

## Out of scope

- Multiple enemy waves — BP5+ mission director
- Reactor self-repair — DR-029 / save-game ladder
- Reactor module damage (M5 chassis grammar applied to reactor) — M5+ optional
- Active material reactions (fire spreads to reactor) — M5.6
- Comic-noir mission card — M4B (deferred)
- Project-owner playtest — OPTIONAL (AI Self-Test is primary gate)

## Dependencies

- M2 chunked terrain (must be done): `terrain.terrain_carved`, dirty regions, 8 materials.
- M1.5 reactive guard (must be done): `ReactiveGuard` AI; mission state machine.

## Notes for the implementer

- Reactor is a static actor: no movement, no AI. Use the existing `ActorState` with a kind discriminator (e.g., `ActorKind::Reactor`) so cf-replay snapshots include it via the existing actor snapshot path — don't invent a parallel reactor snapshot path.
- The trench-shape threshold for the win path is implementation-defined; document the exact threshold in the scenario .ron file (e.g., `terrain_carved_count >= 200`) so the cf-e2e expect line is reproducible.
- M2.5 must run cleanly at both 60 Hz and 120 Hz (the run-bundle checker validates final_sim_checksum stability across tick rates).
- Reuse `ReactiveGuard` unchanged. Do NOT add a new AI variant for M2.5; targeting reactor vs player is a 5-line `select_target` extension.

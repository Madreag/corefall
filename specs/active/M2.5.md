# M2.5 — Micro Reactor Defense Fun Slice

## Status

`active`

## Intent

One 60-90 second `micro_reactor_defense` scenario that proves M2 chunked terrain is fun in the player's hands: dig a trench around the reactor, hold position while one reactive enemy attacks for 60 seconds, win if the reactor survives, lose if it explodes. Win and loss both ship as scripted cfctl runs with full terrain + combat + mission events.

## Player-facing behavior

M2.5 is **the closure milestone for the live destruction loop**: terrain has visible per-pixel integrity, the reactor takes layered damage (External / Internal / Core armor), shields placeholder, hazard spawn surface, atmospheric venting surface, affliction surface. Every damage event from M2.5 forward emits the structured `combat.*` / `terrain.*` / `hazard.*` / `affliction.*` / `atmos.*` / `shield.*` event families so M3A's taxonomy + M3B's cause chains + M4A's HUD readability all consume one truth.

### Player narrative flow (60-90 seconds)

- Player spawns near a **generator core / reactor**. An **objective banner** reads "Defend the reactor for 60 seconds."
- The **reactor** is a single non-player static actor: HP, position fixed, no movement, no AI, **mission_critical=true** (per CCCP `m_MissionCritical`; cannot be gibbed instantly). It is the **predecessor of the future command-core** (DR-027 / DR-015) — the simplest defendable static actor we will ever ship. Its state surface is forward-compatible with M5+ chassis (armor layers, modules), M7+ command-core (power grid, shields), and DR-029 base-power identity (uproot/reroot, avatar core). At M2.5 `hp`, `max_hp`, `pressure_state`, `armor_layers` (3 layers: External / Internal / Core), `heat_signature_k`, and `mission_critical` are LIVE; `shields`, `modules`, `power_grid`, `uprooted_avatar`, and `affliction_overlay` are `serde(default)` placeholders.
- A **countdown timer** (default 60s = 3600 ticks at 60Hz; configurable) ticks down. The HUD timer changes color: green >30s, yellow 10-30s, red <10s. **Caption + banner warnings** fire at 30s, 15s, 5s ("30 SECONDS — HOLD" / "15 SECONDS — REACTOR STRESSED" / "5 SECONDS — HOLD THE LINE").
- One **reactive enemy guard** (reused from M1.5, unchanged) spawns and attacks. The guard picks its target (reactor vs player) using **utility scoring per DR-008**: weighted by proximity × line_of_sight × threat (player) + value (reactor). Player-aggressive guards target the player when in LOS; defensive guards target the reactor.
- **The player can dig a trench** around the reactor for cover/defense using M2's chunked terrain. The trench changes the guard's **path-cost lookups** — guard reroutes around the trench or fires over it depending on geometry. AI emits `ai.path_invalidated` when the player carves, then `ai.recovery_action` with reroute decision.
- **Reactor visual feedback** (per DR-055 + DR-003 hooks): bullet-impact **sparks** on the reactor's surface when hit; **sprite deterioration** as HP drops (5 visual states: pristine / scratched / cracked / critical / destroyed); **pressure-state HUD line** ("REACTOR: NOMINAL / STRESSED / CRITICAL / VENTING / DESTROYED"); **explosion VFX** on destruction (debris scatter, flash, screen shake scaled by player distance + accessibility's `reduce_camera_shake_pct`); **wound emitter pattern** per CCCP `MOSRotating::AddWoundExt` — every hit spawns an emitter at entry point (sparks/spall) AND exit point if projectile passes through, with state persisting on the sprite until repair.

### Destructible terrain — 5-tier HP color states + per-pixel integrity

Destruction is the simulation backbone players see directly. Every terrain pixel has integrity 0..1 tied to its `MaterialId`; visible decay is the readability surface for `try_carve` + `try_penetrate` decisions.

| Integrity band | Tint state | Visual cue | Material overlay color (in integrity mode) | Trigger event |
|---|---|---|---|---|
| **`Pristine`** (1.0) | Material's base color | Smooth | Full saturation | (no event — default) |
| **`Scratched`** (0.75-1.0) | Slight darkening + faint hairline crack overlay | 1-2 hairline cracks at impact origin | 80% saturation | `terrain.material_state_changed { from: Pristine, to: Scratched }` |
| **`Cracked`** (0.50-0.75) | Color shifted toward gray + branching crack texture | 3-5 cracks, debris dust on impact | 60% saturation | `terrain.material_state_changed` |
| **`Critical`** (0.25-0.50) | Gray tone + visible structural holes + spalling | Tile-edge holes, falling pebbles, dust cloud | 30% saturation + RED HALO | `terrain.material_state_changed { to: Critical }` + `ux.banner_raised` (warning) if mission-critical |
| **`Destroyed`** (0.0-0.25) | Tile removed (replaced by air/empty + falling debris) | Tile gone; nearby tiles shed pebbles via cascade rule | (no tile to color — material removed) | `terrain.pixel_removed { pos, was_material, cascade_cause? }` + `terrain.debris_spawned` |

**Per-pixel integrity is a `f32` field on `terrain.pixel_meta_grid` keyed by (chunk_id, local_pos)**. Damage from `try_penetrate` decrements integrity by `(impact_energy * material.softness_factor / material.hardness)`. When integrity crosses tier thresholds, a `terrain.material_state_changed` event fires. When integrity reaches 0, `terrain.pixel_removed` fires + the pixel becomes air. **Adjacent pixels of low-hardness materials may cascade** (M2.5 cascade default: `cascade_threshold=0.6`; `cascade_depth=1` — only direct neighbors checked); cascade events carry `cause: "neighbor_destroyed"` for full attribution.

### Per-limb armor model + armor-piercing math (M5 forward-compat)

The user demand: **"Armor takes damage before it goes through to limb and every limb has separate armor, based on what's equipped."** This is the canonical model. M2.5 reserves the per-limb armor surface; M5 chassis fills it with real per-zone armor items. Reactor at M2.5 demonstrates the same layered grammar at 1 zone × 3 armor layers so M5 ships additively.

**Armor item shape (canonical at M2.5 schema lock, M5+ producer):**

```rust
pub struct ArmorItem {
  pub item_id: ItemId,
  pub kind: ArmorKind,                  // Helmet | Vest | Pauldron | Gauntlet | Greave | Boot | BackpackShell | Cockpit
  pub material_id: MaterialId,          // metal | ceramic | composite | cloth | leather | hardened_plate | reactive_armor
  pub layers: Vec<ArmorLayer>,          // External / Internal / Core (1-3 layers; cheap armor=1 layer; high-end=3)
  pub mass_kg: f32,
  pub coverage_zones: Vec<BodyZone>,    // which limb zones this armor covers (e.g. Helmet → head; Vest → torso; Pauldron → arm_left + shoulder)
  pub damage_resist: BTreeMap<DamageKind, f32>,  // 0.0=no resist, 1.0=full immunity per damage kind
  pub absorption_factor: f32,           // 0.0..1.0 — how much of incoming damage routes to armor vs limb
  pub ap_resistance: f32,               // 0.0..1.0 — resistance to AP penetration
  pub durability_per_layer: u32,        // HP per layer (e.g. 100/80/40 for External/Internal/Core)
  pub chunkable: bool,                  // can it visibly chunk off when destroyed? (default true)
  pub debris_kind: DebrisKind,          // metal_plate_fragment | ceramic_shard | composite_chunk | cloth_strip
  pub origin_compatibility: Vec<OriginId>, // [Human] | [Android] | [Robot] | [Human, Android]
  pub sound_clips: ArmorSoundClips,     // hit / cracked / destroyed / chunked-off sound IDs per material
}

pub struct ArmorLayer {
  pub kind: LayerKind,                  // External | Internal | Core
  pub hp: f32,
  pub max_hp: f32,
  pub hardness: f32,                    // resistance to penetration (0.0..1.0)
  pub condition: LayerCondition,        // Pristine | Scratched | Cracked | Critical | Destroyed | ChunkedOff
}
```

**Damage routing through armor (M2.5 contract; M5 fills per-zone):**

```text
For each projectile hit:
  1. determine impact zone (from impact_point + actor pose)
  2. lookup armor item covering that zone
  3. compute effective_hardness = armor.layers[active_layer].hardness * (1 - ap_factor) * (1 - armor.ap_resistance)
  4. compute armor_absorption = clamp(armor.absorption_factor * effective_hardness, 0.0, 0.95)
  5. compute damage_to_armor = damage * armor_absorption
  6. compute damage_passthrough = damage * (1 - armor_absorption)
  7. apply damage_to_armor to armor.layers[active_layer].hp
  8. if armor.layers[active_layer].hp <= 0 → mark layer destroyed; route subsequent damage to next layer; if all layers destroyed → armor chunked-off; route 100% passthrough to limb
  9. apply damage_passthrough to limb.hp
  10. if heavy_damage_threshold exceeded AND limb is humanoid/android/robot torso → roll internal damage on organs/circuits
  11. emit combat.projectile_hit_mo with full attribution including ap_factor, armor_effective_hardness, armor_absorbed_dmg, passthrough_dmg, hit_zone, layer_struck
```

**4 round tiers with `ap_factor`:**

| Round tier | `ap_factor` | Effective armor reduction | Use case |
|---|---|---|---|
| `standard` | 0.0 | None | Default rifle/SMG; light hits |
| `armor_piercing` | 0.4 | 40% armor effectiveness reduction | Anti-armor sidearm; light AP |
| `hardened_AP` | 0.7 | 70% reduction | Heavy AP rifle; military-grade |
| `discarding_sabot` | 0.95 | Near-total bypass | Anti-tank / anti-mech; rare and heavy |
| `explosive_warhead` | 0.5 + radial cascade | 50% per-zone + cascade damage | RPG / grenade / heavy explosive |
| `kinetic_impact` (high-velocity) | 0.3 | 30% + significant internal_shock risk | Sniper rounds, railgun (M5+) |

**Internal damage routing:**

```text
For each hit that passes through armor with passthrough_damage > heavy_damage_threshold (default 5 HP):
  1. compute internal_shock_probability based on (passthrough_dmg, impact_impulse, ap_factor)
  2. roll random organ/circuit weighted by hit_zone proximity to organ's mount_point
  3. apply (passthrough_dmg * internal_damage_modifier) to selected organ/circuit
  4. emit internal.organ_damaged or internal.circuit_damaged event
  5. if organ/circuit hp reaches 0 → emit internal.organ_destroyed or internal.circuit_destroyed + failure cascade
  6. failure cascade applies affliction(s) per organ's failure_cascade table
```

**Explosion + heavy AP variant:** when `damage_kind == explosive` OR `ap_factor >= 0.7`, internal damage routes to MULTIPLE organs/circuits in radius proximity (per-blast: 3 random organs hit; per-AP: 1-2 organs hit).

**Repetitive small arms fire model** (user-requested):
- Each non-penetrating hit on armor contributes to `concussion_dose` (humans/androids) or `internal_shock_dose` (robots) even though the limb itself doesn't take damage
- Per-hit dose = `impact_impulse * armor_blunt_factor * origin_concussion_susceptibility`
- Accumulates over a 10-second sliding window
- Cleared by medikit (humans/androids) OR repair tool (robots)
- Triggers concussion/internal_shock affliction at threshold

### Concussion + Internal Shock dose accumulator

Per `origin-reaction-and-resource-model.md`:

- **Humans:** susceptible to concussion + G-load + fall damage. Concussion vignette + screen blackout.
- **Androids:** reduced concussion susceptibility (~50% rate). Reduced vignette severity.
- **Robots:** NEVER concussed. Same impulse routes to `internal_shock` damage on random module.

**5-band accumulator:**

| Band | Dose threshold | Player effect | HUD cue |
|---|---|---|---|
| `Clear` | 0-20 | None | (no cue) |
| `Mild` | 20-40 | Slight aim wobble | Edge vignette dim 10% |
| `Moderate` | 40-60 | Reduced aim, slight movement penalty | Vignette dim 30%, slight bloom |
| `Severe` | 60-80 | Significant aim/movement, vision tunneled | Vignette dim 60%, screen sway |
| `KO_Imminent` | 80-99 | Severely impaired, sway camera | Vignette dim 85% + tunnel vision |
| `KO` | 100 | Knocked out for 5-10s; cannot act | Full blackout + caption "KNOCKED OUT" |

Dose decays at `5/s` (humans), `8/s` (androids), `0/s` (robots — N/A). Robot's `internal_shock_dose` decays at `2/s` and routes to module damage at threshold crossings.

Events: `concussion.applied`, `concussion.escalated`, `concussion.recovered`, `concussion.ko_threshold_crossed`. For robots: same events with `kind=internal_shock` discriminator.

### Fluid drain system (robots / mechs / power suits)

The user demand: **"Robots and mechs able to lose fuel and oil when armor is pierced etc... should slowly drain and eventually break the mech or heavy armor or power suite."**

**4 fluid reservoirs (per robot/chassis):**

| Fluid | Default capacity | Source organ/module | What happens when empty |
|---|---|---|---|
| `oil` | 100 L | oil_reservoir | Joint seizure; movement -50%; eventually motor controllers fail |
| `coolant` | 80 L | coolant_pump | Heat buildup accelerates; overheating affliction stacks |
| `fuel` | 150 L | fuel_tank | Mobility (jet, engine) disabled; chassis inert if no battery backup |
| `electrolyte` (battery) | 100 % | power_core | All actions cost more; eventually inert |

**Leak mechanics:**

- When armor is pierced AT a zone covering a fluid-bearing organ/module → `fluid.leak_started`
- Leak rate scaled by `puncture_severity = impulse * (1 - armor_absorbed) * material_softness`
- Visible particle emission (cosmetic per M3A) — green for coolant, dark for oil, amber for fuel, blue for electrolyte
- Ground splatter material at leak site (terrain hazard surface; M5.7+ material kernel consumes for slippery/wet tile)
- Per-tick drain: `reservoir.level -= leak_rate * tick_dt`
- When 50% → `FLUID_LOW` warning banner
- When 20% → `FLUID_CRITICAL` warning banner
- When 0% → `FLUID_EMPTY` critical banner + module failure cascade

**Ignition risk:**

- Oil + fire/electric hazard tile contact → `fluid.ignition` event → chassis fire affliction
- Fuel + ignition → larger explosion (M5.5+ collision; M2.5 placeholder)
- Coolant is non-flammable but corrosive on prolonged ground contact (M5.7+ material kernel consumes)

**Events:**
- `fluid.leak_started { actor_id, fluid_kind, source_module, leak_rate, position }`
- `fluid.leak_rate_changed { actor_id, fluid_kind, from_rate, to_rate, reason }`
- `fluid.reservoir_warning { actor_id, fluid_kind, level_pct }` (at 50%)
- `fluid.reservoir_critical { actor_id, fluid_kind, level_pct }` (at 20%)
- `fluid.reservoir_empty { actor_id, fluid_kind }`
- `fluid.ignition { actor_id, fluid_kind, source_event_id }` (combustible only)
- `fluid.leak_stopped { actor_id, fluid_kind, reason: 'sealed' | 'repaired' | 'reservoir_empty' }`

### Layered reactor armor — External / Internal / Core (CCCP forward-compat)

Even at M2.5 the reactor uses the **3-layer armor model** that M5 chassis inherits without renaming. Damage cascades through layers; HUD shows each layer's HP independently.

```text
External armor (60% of total HP, 0.9 hardness) — first to absorb
  ↓ when External HP = 0, breach event fires; damage routes to Internal
Internal armor (30% of total HP, 0.7 hardness) — secondary buffer
  ↓ when Internal HP = 0, breach event fires; damage routes to Core
Core (10% of total HP, 0.5 hardness) — the actual reactor; when 0 → Destroyed
```

**Each layer emits explicit events** on transitions:

- `reactor.armor_layer_hp_changed { layer: External|Internal|Core, from, to, cause, source_actor_id, parent_event_id }`
- `reactor.armor_layer_cracked { layer, hp_at_crack: 0.0, cause }` — fires when a layer reaches 0 HP
- `reactor.armor_layer_destroyed { layer, breach_kind: 'punctured'|'shattered'|'melted', cause }`

**HUD shows 3 armor pip indicators** under the reactor HP bar: each pip filled to its layer's remaining HP %. Pips transition Pristine → Scratched → Cracked → Critical → Destroyed using the same 5-tier color signature as terrain (the player learns ONE damage grammar).

This 3-layer model is the forward-compat surface for M5 chassis (CCCP-style 15-zone graph × 3 layers per zone) and M7+ base modules (each module is one logical zone × 3 layers).

### Atmospheric coupling — reactor venting (M5.9 forward-compat)

Per DR-040 + atmospherics-and-chemistry-model. M2.5 ships the **`atmos.*` event surface** for the reactor as it crosses pressure_state:

- When `pressure_state` becomes `Stressed` → `atmos.temperature_changed { atm_id, from_k, to_k, source: reactor_id }` (reactor heats local air; placeholder until M5.9 atmos kernel)
- When `pressure_state` becomes `Critical` → `atmos.pressure_changed { atm_id, from_pa, to_pa, source: reactor_id }` (placeholder; M5.9 fills)
- When `pressure_state` becomes `Venting` → `atmos.gas_released { atm_id, gas: 'volatiles', moles, source: reactor_id, ignition_risk: 0.0..1.0 }`

### Trench gameplay depth — partial cover + erosion

Trench mechanics get the **gradient cover** treatment M4A's accessibility-friendly cover system requires:

- **Trench-depth indicator** (HUD): when player is inside a trench, a small chevron shows depth (1 pixel ≤ Shallow, 2-3 = Medium, 4+ = Deep) + caption "COVER: <state>"
- **Partial cover absorption**: projectiles passing through the trench wall lose energy based on remaining wall integrity at that pixel column (NOT binary; gradient absorption per `try_penetrate.energy_loss = impact_energy * (1 - (integrity * material.absorption_factor))`)
- **Trench wall erodes** as more rounds hit: integrity decay visible via terrain HP color cascade (Pristine → Scratched → Cracked → Critical → Destroyed); event `terrain.material_state_changed` per cross
- **Trench-floor moisture** (forward-compat M5.7): trench dug below water table fills with water (wet hazard tile); future surface
- **Trench-cover banner**: `TRENCH_INTEGRITY_LOW` warning when adjacent terrain reaches Critical (visible "cover failing" cue)

## Notes for the implementer

### Architecture rules

- **Reactor is a static actor**: no movement, no AI, no ControlIntent. Use the existing `ActorState` with `ActorKind::Reactor` so cf-replay's actor snapshot path covers it — do NOT invent a parallel reactor snapshot. The reactor's `mass = f32::INFINITY` so impulses never move it; HP-only damage routing per CCCP `m_MissionCritical` pattern.
- **mission_critical=true blocks instant gib**: per CCCP `Actor.cpp` mission-critical flag, the reactor cannot be one-shot. HP only drops through accumulated normal damage; pressure_state ladder steps through Nominal → Stressed → Critical → Venting → Destroyed.
- **Reuse ReactiveGuard unchanged**: per M1.5 spec rule. Add target_selection.rs that uses utility scoring (per DR-008 lean) — NOT a new AI variant. Target switching reactor↔player happens within the existing ReactiveGuard's Engaged state.
- **Single source of truth for trench-shape threshold**: document the threshold in `content/scenarios/micro_reactor_defense.ron` as a scenario-level constant. The cfctl scripts + cf-e2e expects all reference it by name (not literal). So a future re-tune doesn't break tests.
- **Per CCCP BunkerBreach.lua proof-mission lessons**: scene-area contracts (Reactor Zone, Player Spawn, Guard Spawn, optional Extraction Zone) live in the scenario .ron; cf-mod validate enforces presence. Brain placement, attacker AI setup, win checks, objective arrows are all wired through cf-mission's typed manifest, NOT free-form script.

### Pitfalls / things that have bitten us before

- **Reactor as duck-typed actor**: don't add `if actor.kind == Reactor` branches everywhere. Use `mission_critical` flag + standard apply_damage path. Same code path for player + guard + reactor.
- **Trench threshold hardcoded**: must be a scenario-level constant. Otherwise rebalancing requires recompile + cfctl script edits.
- **Timer at 60Hz only**: at 120Hz the tick count doubles. Use seconds (real time) for the timer math, not ticks.
- **Forgetting parent_event_id for reactor_hp_changed**: M3B's cause-chain walker returns ParentMissingFromBundle. Every damage event MUST link to the projectile_hit_mo that caused it.
- **Sparks/explosion not flagged cosmetic=true**: replay determinism breaks because cosmetic particle RNG drifts cross-platform. Set `cosmetic: true` on the events.
- **Reactor never gibs**: if mission_critical=true is forgotten in the .ron, an explosion at M5.5+ could instant-gib the reactor and skip the pressure_state machine.
- **AI ignores trench**: ai.path_invalidated must fire when terrain.terrain_dirty_region_batch intersects guard's path. Without this, "terrain matters" is fake.
- **Reactor HP bar lags HUD at 120Hz**: HUD reads observation AFTER sim tick, never mid-tick. Test explicitly at 120Hz.
- **No emoji in any HUD or replay text** (project rule).

# M2 — Pixel Terrain And Materials

## Status

`in_progress`

## Intent

Mutable chunked pixel terrain with 8 launch materials. The player can dig a soft-material wall, the change is visible within one frame, replay-recorded with material id and bbox, and respected by the simple physics. Material affordances (hardness, anchorability, hazard, path-cost) are data-driven and queryable.

## Player-facing behavior

- The world is made of pixels grouped into chunks (default 256×256, configurable). Each pixel has a material id from the launch set: `air / dirt / concrete / metal_nohook / hazard / loose_fill / repair_fill / anchor`.
- The digger tool carves dirt fast, concrete slowly, refuses metal_nohook with a labeled reason ("REFUSED: cannot dig metal").
- Carving is visible in the next render frame; chunk dirty-rect tracker triggers per-chunk re-upload.
- Pixel debris particles spawn at the carve site (loose `MOPixel`-style debris, capped per event for readability + perf per CCCP `Material.SpawnMaterial`).
- A **material-overlay toggle** (`act.player.toggle_material_overlay` / hotkey M) cycles 5 visualization modes: `integrity` (color by hardness), `pathability` (passable/blocked), `mobility` (anchorable / nohook / passable), `hazard` (red tint on damage tiles), `build_repair` (where can repair-fill be placed).
- Hazard tiles damage the player on contact and emit a structured event with a reason label.
- Anchor materials accept future tethers; non-anchorable materials refuse with the same labeled-reason pattern (placeholder at M2; tether tool ships at BP4+).
- Bullets / projectiles can chip terrain by impulse: rifle hits dirt → small chip; rifle vs concrete → spark + no penetration; explosives carve large bbox (M5.5+).
- Density / priority / piling rules apply: dense materials (metal) win pixel overlap; loose materials (sand, rubble) pile/settle under their own kind.
- A `material_legend` HUD widget lists all 8 materials with their display name and a swatch, updated when overlay mode changes.

### Penetration formula + projectile interaction

```gherkin
Scenario: Bullet vs material follows impulse² > integrity² (per CCCP SceneMan.cpp:571)
  Given a projectile with mass=0.05, velocity=400, sharpness=0.8
  When it hits a dirt pixel (integrity=10)
  Then impulse=mass*velocity*sharpness=16; impulse²=256; integrity²=100; 256>100 → penetrates; pixel cleared to air
  When it hits a concrete pixel (integrity=40)
  Then impulse²=256; integrity²=1600; 256<1600 → does NOT penetrate; rifle bounces / stops with restitution
  When it hits metal_nohook (integrity=100)
  Then 256<10000 → does NOT penetrate; rifle definitely bounces

Scenario: Penetration spawns spawn_material as debris (per CCCP Material.SpawnMaterial)
  Given dirt with spawn_material=loose_fill
  When a projectile penetrates
  Then a small loose_fill MOPixel-style debris is spawned at the impact point with retardation
  And terrain.terrain_pixel_dislodged fires with source_material=dirt, spawn_material=loose_fill, child_pixel_id
  And the debris is cosmetic but collidable
  (Settling — debris becoming terrain again — is M5+ deferred)

Scenario: Stickiness — projectile draws into terrain on impact (per CCCP Material.Stickiness)
  Given metal_nohook with stickiness=0.7 (high)
  When a projectile fails to penetrate
  Then with probability 0.7 the projectile is "drawn into" the terrain pixel (becomes part of color_grid)
  And with probability 0.3 it bounces off per friction/restitution
  (Determinism: stickiness rolls use the engine RNG, not thread_rng)

Scenario: Threshold event for projectile/material interaction
  Given any projectile-vs-material contact
  Then terrain.terrain_penetration_threshold fires with: projectile_id, material_id, impulse, integrity, passed (bool), spawned_material (id or null), debris_count
  And the event has parent_event_id linking to the projectile_spawned event
```

## Out of scope

- GPU-assisted carving compute shader — BP4 perf optimization (CPU path is the M2 floor; the chunk renderer can use GPU upload for dirty rects but the carve math stays on CPU for determinism)
- Active material kernel (cellular automaton: sand falls, water pools, gas rises, fire spreads) — M5.6 (M2 ships the schema fields with `serde(default)` so M5.6 reads them; M2 itself does not step a CA)
- Active reaction table (water+fire→steam, oil+ignition→fire, lava+water→rock+steam) — M5.6
- Settling: dropped MOPixel debris becoming terrain via `MovableObject::DrawToTerrain` — M5+ (M2 spawns debris but it does not re-settle into terrain)
- Pathfinder consuming material path-cost — M6+ (M2 stores the costs and emits dirty-region events; M6 implements the pathfinder)
- AI consulting terrain materials for cover / route / hazard avoidance — M6
- Collapse / structural support rules (carved tunnel ceiling falls in) — M5.5+ (prototype-only at BP3 by design per terrain-material-slice-a)
- Tether / grapple / rope tool implementation — BP4+ (anchor material affordance exists at M2 with refusal-label surface; the tool that consumes it ships later)
- Background terrain layer (CCCP `SLTerrain` foreground+background) — M5+ (M2 ships foreground only)
- Door material override (CCCP `ADoor.cpp` per-team material edits) — M2.5 (doors are scenario actors that may stamp material; edge case, defer)
- Marching squares chunk-border smoothing — M5.6 visual polish
- Terrain object stamps (CCCP `TerrainObject::DrawToTerrain` for static structures) — M2.5 ships reactor as terrain stamp; M2 ships the API surface only
- Per-platform CI checksum match (Linux + Windows + macOS aarch64 cross-OS deterministic identity) — M3A scope (M2 produces deterministic checksums per platform; cross-OS match is M3A's CI work)
- Hazard variants beyond damage_on_touch (electric, fire spread, toxic gas) — M5.7 atmospherics
- Repair tool implementation — BP4+ (M2 ships repair_fill material id and try_fill_or_repair API; the tool that consumes it lands later)
- Multi-pixel CA stepping inside chunks — M5.6 (M2 chunks have an `active_region` flag, always false at M2; M5.6 will set it true and step CA inside)
- Real-player playtest — OPTIONAL per AGENTS.md (AI Self-Test = scripted dig + refusal + overlay verification + replay match is the primary gate)
- Formal 1280×720 / 4K perf measurement — T-PERF gate scope (M2 ships the surface; T-PERF measures it)

## Notes for the implementer

### Architecture rules

- **Single source of truth for materials**: `content/materials/material_registry.json` is canonical. Do NOT hardcode material defs in Rust. The registry is loaded at scenario load and frozen for the run's duration. cf-mod validates at content-load.
- **Sparse chunk storage**: only allocate chunks that have non-air pixels. An empty world has zero chunks. A 1km wide world with 4 actors should be a few hundred chunks, not millions.
- **AddUpdatedMaterialArea is the ONLY dirty path**. Every place that mutates a pixel MUST call it. Per CCCP `SLTerrain.cpp:397-481`: there are paths in the legacy engine that bypass dirty-tracking and they cause stale pathfinding. We will not repeat that mistake. Code review checks this contract.
- **Chunk size 256×256 is the M2 default; configurable** via scenario manifest. Noita uses 64×64 for falling-sand (smaller chunks = finer dirty granularity, more chunks). M2 starts at 256×256 because we're not yet stepping a CA; M5.6 may halve to 128×128 or 64×64 when the CA wants finer dirty granularity. Document the choice + tradeoff in the implementer commit message.
- **Active-region flag is forward-compat for M5.6**: every Chunk has `active_region: bool` field. M2 always writes false. M5.6 will step the cellular automaton ONLY inside chunks where `active_region=true` (Noita pattern: most of the world is sleeping; only chunks with falling materials wake up). Do NOT remove this field.

### Sim numbers / formulas (anchor to source code)

- **Penetration**: `impulse_squared > integrity_squared` (CCCP `SceneMan.cpp:571`). Use squared comparison to avoid `sqrt` in the hot path.
- **Material reference values** (registry baseline; document in description fields so future tuners know the source):
  - `air`: hardness=0, integrity=0
  - `dirt`: hardness=10 (CCCP earth normalized; fast carving)
  - `loose_fill`: hardness=5 (CCCP earth_rubble=25 normalized; slow movement, low support)
  - `concrete`: hardness=40 (CCCP concrete=200 normalized; slow drill, hard cover)
  - `metal_nohook`: hardness=100 (CCCP metal=400 normalized; refuse-by-default; nohook flag)
  - `anchor`: hardness=60 (CCCP stone=140 normalized; hard but anchorable)
  - `hazard`: hardness=50 (medium; damage_on_touch=true)
  - `repair_fill`: hardness=15 (player-placed; medium; can be carved)
- **Density / piling / priority** (CCCP `Material.h`):
  - Priority decides what wins when pixels overlap (e.g. concrete > dirt during stamp/draw).
  - Piling controls how dislodged pixels relocate upward when intersecting same material (sand pile, scrap compaction).
  - Density determines mass for spawned debris pixel.
- **Stickiness probability**: rolled per-impact via the engine RNG (NOT thread_rng). Determinism critical for replay.
- **Coalesce budget**: 5 explosions in same tick → ≤25 path-update rects (terrain-material-slice-a budget).
- **Debris cap per event**: 100 (configurable). Excess is reported via `terrain.debris_capped`.
- **Path-refresh budget** (M6 forward-compat): 100-node default per call (CCCP `Scene.cpp:2384-2426`); 1000-box stale fallback. M2 emits the surface; M6 consumes it.

### Replay envelope + cause chains (DR-002)

- All M2 events use the `prototype-recorder-event.v0.1` envelope.
- **Every terrain edit MUST set `parent_event_id`**. The cause chain at M2:
  - Player intent (act.player.dig) → `equipment.tool_action_started` → `terrain.terrain_carved` → `terrain.terrain_pixel_dislodged` (per debris) → `terrain.terrain_dirty_region_batch` (per tick coalesce)
  - Projectile spawn → `terrain.terrain_penetration_threshold` → `terrain.terrain_carved` (if pass) OR projectile bounce (if fail)
  - Actor walking onto hazard → `terrain.hazard_contact_or_avoidance` → `actor.apply_damage` → `actor.actor_status_changed` (M1 surface)
- **mask_id is stable**: blake3 hash over (mask_shape, tool_id, dig_radius). Same dig at same spot in two replays produces the same mask_id, even though wall-clock time differs.

### Pitfalls / things that have bitten us before

- **Raw `set_material_pixel` without `add_updated_material_area`** = stale pathfinding. CCCP TODO bug. Don't replicate.
- **256×256 vs 64×64 chunks**: smaller chunks = better dirty granularity but more chunks to iterate. Pick 256×256 for M2 (we're not running CA yet); M5.6 may revisit.
- **Foreground-only terrain at M2** is a deliberate scope cut. CCCP has foreground+background+material+color layers. We ship one foreground material grid + optional color grid. Background ladders up at M5+.
- **Sparse storage means empty chunks are None**: `chunks.get((x,y))` returns None for unallocated chunks; downstream code must treat None as "all air".
- **Settling (debris→terrain) is NOT in M2**: dropped MOPixels persist as physics objects but do not re-stamp into the terrain bitmap. M5+ adds settling.
- **Stickiness uses engine RNG, not thread_rng** — replay determinism breaks if you call `rand::thread_rng()`. Per AGENTS.md "no thread_rng in sim crates" rule.
- **Mask-id collision**: blake3 over (mask_shape, tool_id, dig_radius) is enough entropy. Don't include time-of-day or any non-deterministic input.
- **No emoji in any HUD or replay text** (project rule).

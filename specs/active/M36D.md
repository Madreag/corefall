# M36D — GPU Compute Job Scheduler + Cross-OS Determinism Gates + CPU/GPU Parity Validation

## Status

`active`

## Intent

M36D locks the **deep authority layer** beneath M36C: a deterministic per-tick GPU compute job scheduler with backpressure, a WGSL shader registry with locked entry points, a mandatory CPU fallback path for every GPU kernel, per-frame CPU/GPU parity validation at a 1/15 tick cadence, a CI gate that runs the full simulation on CPU and GPU in parallel and verifies byte-identical sim state across both paths, and per-mod resource throttling that prevents a malicious or unbalanced mod from starving the scheduler. Where M36C declared the budget and tier targets, M36D enforces them at machine-checkable granularity across every supported OS (Linux x86_64, Windows x86_64, macOS aarch64) and every GPU vendor (NVIDIA, AMD, Apple Silicon, Intel Arc).

## Canonical ownership

Owns the GPU compute job graph, per-shader CPU fallback pairs, GPU dispatch backpressure policy, GPU/CPU parity harness, per-mod GPU resource quotas, cross-OS determinism CI gate `m36d_gpu_cpu_parity_matrix.sh`, and the `cf-gpu-scheduler` crate. M8A established parallel determinism on the CPU; M15B introduced the first GPU compute kernel; M36C declared the per-tick budget. M36D is the binding glue that proves the budget holds and the determinism contract survives the GPU path.

## Operator-facing + indirectly-player-observable behavior

- **Operator: GPU job graph visible.** `cfctl observe.perf.gpu_jobs` returns the current frame's compute job graph (kernel, queue depth, dispatch wall time, fallback engaged y/n).
- **Operator: backpressure policy configurable.** Server admin sets `gpu_backpressure_mode = strict | adaptive | cosmetic_drop` in `server.ron`; strict halts the tick on overrun, adaptive switches affected kernel to CPU fallback for the next 60 ticks, cosmetic_drop drops only cosmetic-flagged jobs.
- **Operator: per-mod GPU quota enforced.** A mod can be allocated at most N microseconds of GPU compute per tick (default: 1500 µs); exceeding quota triggers `mod.gpu_quota_exceeded` and demotes the mod's kernels to CPU fallback for the rest of the session.
- **Operator: parity-failure halts cleanly.** When 1/15-cadence parity check detects byte-mismatch between CPU and GPU paths, server halts the GPU dispatch, replays the divergent tick on CPU, and emits `parity_drift_detected` to the audit log; no client visible glitch.
- **Indirectly-player-observable: no stutter under load.** Player on Workstation tier with 1000 active hazard pixels + 200 actors + 500 projectiles sees no frame stutter, because the scheduler shifts overflowing work to next-frame budget instead of blocking.
- **Indirectly-player-observable: identical world across server OS.** Player A connecting to Linux VPS shard and Player B connecting to Apple Silicon shard with the same seed + scenario + inputs see byte-identical world state evolution; mod that fails determinism on one platform is rejected at server join.
- **Indirectly-player-observable: clean degradation on weaker GPUs.** Server running on Intel Arc / older AMD card with partial WGSL support automatically demotes unsupported kernels to CPU fallback; play continues at degraded per-tick budget; no crash.
- **Indirectly-player-observable: no cheating via GPU divergence.** Player cannot mod local GPU shader to produce different sim outcome — server-authoritative path always runs CPU + GPU in parallel during competitive PvP and rejects clients whose GPU path diverges from server's CPU truth.

## Acceptance criteria

```gherkin
Scenario: GPU job graph deterministic across runs
  Given the same seed + scenario + inputs
  When the per-tick GPU dispatch runs twice
  Then job order, workgroup launch parameters, and buffer hashes are byte-identical run-over-run

Scenario: Every GPU kernel has a registered CPU fallback
  Given cf-gpu-scheduler boots
  When the WGSL registry enumerates all kernels
  Then each kernel has a `CpuFallback` impl registered
  And startup fails with cf_gpu_scheduler::Error::MissingFallback if any kernel lacks a pair

Scenario: 1/15 cadence parity check passes
  Given GPU compute path active for 150 ticks
  When the parity sampler runs every 15th tick (ticks 15, 30, 45, ...)
  Then per-chunk blake3 of the CPU and GPU output buffers match exactly on 10 of 10 samples

Scenario: Parity drift halts GPU path cleanly
  Given an injected fault flipping one bit in the GPU material kernel output
  When the next parity sample runs
  Then parity_drift_detected fires with kernel=material_ca cpu_hash=<a> gpu_hash=<b>
  And the scheduler demotes material_ca to CPU fallback for the remainder of the session
  And no sim state corruption is observable to clients

Scenario: Per-mod GPU quota enforced
  Given a mod declaring `max_gpu_us_per_tick = 1500`
  When the mod's kernel dispatch exceeds 1500 µs on tick T
  Then mod_gpu_quota_exceeded fires for mod_id + tick=T + consumed_us=<n>
  And on tick T+1 the mod's kernels run via CPU fallback only

Scenario: Backpressure strict mode halts cleanly
  Given gpu_backpressure_mode=strict and a deliberate overload (3× budget)
  When the dispatch overruns its 4.0 ms p99 slice
  Then gpu_backpressure_triggered fires with mode=strict overrun_us=<n>
  And the tick is rejected and replayed on CPU
  And the server logs a structured warning; no panic, no crash

Scenario: Backpressure adaptive mode demotes affected kernel
  Given gpu_backpressure_mode=adaptive and a deliberate overload on the atmos kernel only
  When 3 consecutive ticks overrun the atmos slice
  Then atmos_kernel is demoted to CPU fallback for 60 ticks
  And other GPU kernels (material_ca, decal) remain on GPU
  And after 60 ticks the scheduler retries GPU dispatch for atmos_kernel

Scenario: Cross-OS GPU/CPU parity CI gate
  Given the CI workflow `m36d_gpu_cpu_parity_matrix.sh`
  When the same seed + 1000-tick scenario runs on (Linux x86_64 / Windows x86_64 / macOS aarch64) × (CPU-only / GPU-on)
  Then all 6 run bundles produce byte-identical events.jsonl and per-tick determinism.sim_checksum
  And the CI gate FAILS the build if any pair diverges

Scenario: cfctl exposes the live GPU job graph
  Given a running server with GPU compute active
  When the operator runs `cfctl observe.perf.gpu_jobs --tick now`
  Then JSON output lists each kernel: name, queue_depth, dispatch_us, fallback_engaged, mod_id (if any)
  And total_gpu_us is reported with p50/p95/p99 percentiles over the last 600 ticks

Scenario: Unsupported GPU degrades cleanly
  Given a server boots on a GPU without WGSL storage buffer support (older Intel iGPU)
  When cf-gpu-scheduler enumerates capabilities
  Then unsupported kernels are routed to CPU fallback at boot
  And tier_detection reports the degraded configuration
  And the server starts; sim runs at degraded per-tick budget without panic
```

## Out of scope

- Multi-GPU dispatch (SLI / Crossfire / multi-card) — single primary GPU per process.
- GPU compute on the client-only cosmetic path — covered by M8A.
- ROCm / CUDA native paths — wgpu is the only allowed GPU abstraction (DR-052).
- Cross-shard GPU resource sharing — see M36E.
- Distributed parity check across server cluster — single-shard scope.

## Notes for the implementer

- Job graph is a topologically-sorted `Vec<GpuJobNode>`; deterministic order via `(kernel_id, mod_id, dispatch_seq)`.
- Parity check uses per-chunk blake3 over the kernel output buffer; never over float reductions (use bit-exact integer hashing).
- The `CpuFallback` trait MUST be a bit-exact emulation of the WGSL kernel; not an approximation. CI gate enforces.
- Mod quota tracking uses a per-mod `AtomicU64` rolling window over the last 60 ticks; sample-once-per-tick to avoid hot-path contention.
- Backpressure policies live in `cf-gpu-scheduler::backpressure` as a `BackpressurePolicy` trait with one impl per mode; selection via `server.ron`.
- `m36d_gpu_cpu_parity_matrix.sh` is the canonical CI gate; runs on the same matrix as M48A's cross-platform replay gate and must complete in under 20 minutes for the 1000-tick scenario.
- Cosmetic backpressure-drop policy is opt-in via the M8A `cosmetic: true` flag — never drop a sim-affecting job.
- Adaptive demotion uses an exponentially-weighted moving average of overrun ratios; reset on session boundary.

# M32A — Tier 2 ComfyUI Asset Pipeline

## Status

`active`

## Intent

**M32A is the Tier 2 production-quality visual asset pipeline** — full SDXL + Flux + AnimateDiff + ControlNet + LoRA training stack via ComfyUI. Every M9A Tier 1 SVG placeholder is replaced with production-quality pixel-art / hand-drawn / illustrated assets at the launch quality floor. After M32A, the game LOOKS like a real game — not "AI-generated placeholder", but "this is what we ship."

**Why after M32 (crafting):** by M32 close, BP7 (campaign + factions + loot + atmospherics + power + mining + worlds + crafting) is complete; every recipe + weapon + actor + chassis + base module + cosmetic + UI surface is defined. M32A replaces the M9A Tier 1 SVG of all those entities with Tier 2 production art.

**Why this is the BACKBONE:** the human stops authoring production art FOREVER at M32A. Per-faction LoRA training + ControlNet pose consistency + AnimateDiff frame coherence + auto-style-grading rejects out-of-style assets. The pipeline runs unsupervised; outputs are ledgered + reproducible; modders use the same stack.

M32A promise: **"every weapon, every actor, every chassis, every vehicle, every base module, every cosmetic, every UI surface has production-quality art generated by SDXL/Flux/AnimateDiff/ControlNet, per-faction-style LoRAs trained from initial AI reference sets, auto-graded for style consistency, fully ledgered, regenerable, moddable — no human pixel-pushing required."**

## Pipeline algorithm

```text
1. Read all M9A Tier 1 SVG entries from cf-asset-ledger
2. For each Tier 1 entry:
   a. Look up faction / origin / kind metadata
   b. Compose ComfyUI prompt:
      - Base prompt template (per workflow JSON)
      - Faction LoRA reference (trained from faction_reference_seed_sets/)
      - Per-faction palette from M9A palette JSON
      - ControlNet input: the M9A Tier 1 SVG as pose reference
      - Negative prompt: NSFW / blur / illegible
      - Seed: derived from M9A entry's seed + tier (Tier 2 namespace)
   c. cf-asset-pipeline submits ComfyUI workflow via WebSocket
   d. ComfyUI runs SDXL/Flux/AnimateDiff/ControlNet stack
   e. Output: high-res PNG at base resolution (typically 512×512 or 1024×1024)
   f. mipmap_generator.py creates [16, 32, 64, 128, 256] px versions
   g. normal_map_baker.py creates _normal.png via Flux Depth ControlNet
   h. style_grader.py runs LLM-grader:
      - Score 0.0-1.0 against faction style descriptor
      - If < 0.75: regenerate with adjusted prompt (max 3 retries)
      - If still < 0.75: flag for human review
   i. Write outputs to content/assets/tier2/<category>/<canonical_name>.{png,_normal.png,_16.png,...}
   j. Compute blake3 hashes
   k. cf-asset-ledger entry added with tier=Tier2_ComfyUI, pipeline=M32A_comfyui_v1, upstream_assets=[<M9A entry>]
3. After all Tier 2 entries generated:
   a. Mark M9A entries as `superseded_by = <Tier 2 entry>`
   b. cf-render-2d::asset_loader prefers Tier 2 at runtime
   c. Tier 1 SVG entries remain for modder ControlNet inputs + low-end-device fallback
```

## Per-faction LoRA training

```text
Per faction (8 launch):
1. Use M9A Tier 1 SVG outputs as initial reference seed (20-50 images per faction)
2. Tag each reference with style descriptors from M9A style.json
3. Train LoRA via kohya_ss or sd-scripts:
   - Base model: SDXL or Flux.1-dev
   - Training steps: 2,000-5,000
   - Output: faction_<faction_id>_v1.safetensors
4. Per faction LoRA loaded by ComfyUI workflows when generating that faction's assets
5. LoRA ledgered as Tier 2 entry; regen reproduces same LoRA from same training data
```

After per-faction LoRAs trained, the LoRA is automatically applied via ComfyUI workflow when faction_id is in the asset's metadata. Style consistency across all that faction's assets is enforced.

## Notes for the implementer

### Architecture rules

- **ComfyUI WebSocket API** — Python orchestrator stays Python; Rust orchestrator (cf-asset-pipeline) acts as CLI front-end
- **Pinned models** — SDXL 1.0 base + Flux.1-dev + AnimateDiff v3 + ControlNet 1.1; commits in model_pins.ron
- **Per-faction LoRA training** — 8 LoRAs (one per launch faction); modders add their own
- **Workflow JSON portability** — per-asset-kind workflow JSON; shared per-faction LoRA loaded conditionally
- **Style grader is non-blocking** — flags review but doesn't stop generation (max 3 retry)
- **Freeze-then-store for non-determinism** — Tier 2 outputs stored in git LFS; regen verifies stored output
- **Detail-LOD switching at runtime** — cf-render-2d::lod_switcher selects appropriate mip per zoom level
- **Tier 1 fallback** — if Tier 2 missing, Tier 1 SVG used; no crash; visible debug indicator

### Decision-record alignment

- **DR-019 (visual direction)**: M32A is the production-quality floor
- **DR-044 (audiovisual production pipeline)**: M32A is visual Tier 2
- **DR-053 (asset ledger)**: every Tier 2 entry ledgered
- **DR-006 (mod parity)**: modders use same pipeline
- **DR-052 (determinism)**: cross-platform PNG render parity verified at CI

### Pitfalls

- **GPU memory at SDXL+AnimateDiff scale** — single asset bake can require 24+ GB VRAM
- **LoRA training takes 30-60 minutes per faction** — 8 factions × 60 min = 8 hours; parallelizable per-GPU
- **Style drift on small reference sets** — provide 20+ images per faction; augmentation if smaller
- **Mid-bake CI failures** — partial bakes need to be resumable; pipeline tracks per-asset completion status
- **PNG file size at full launch roster** — 4500 assets × multi-mipmap = ~5 GB texture data; git LFS
- **Per-stance × per-origin × per-facing combinatorial explosion** — use AnimateDiff once for human walk; per-origin via per-faction LoRA color-shift + override; saves ~10× time

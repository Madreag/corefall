# M36H — Per-Mission Analytics + A/B Test Framework + Opt-In Privacy Controls + Player Progression Tracking

## Status

`active`

## Intent

M36H locks the **deep analytics layer** that M36B declared but did not exhaust: per-mission analytics (completion rate / median duration / loss-cause distribution / per-mission-step quit-point detection / drop-off detection across funnel stages), an A/B test framework gated through the M32 storyteller mod (so cohorts can be randomized into feature-toggle variants and balance feedback flows back per cohort), per-data-type opt-in privacy controls (basic / gameplay / chat / voice / replay each toggled independently, with chat + voice defaulting OFF), player progression tracking (per-cycle XP curve + skill curve + retention cohort + dollars-per-hour-of-play sanity), funnel analysis per game-mode entry (M44 / M48A onboarding through First Contract through first PvP queue through first MMO shard join), and a per-shard admin dashboard that surfaces all of it. M36B shipped the telemetry pipeline (opt-in batched uploads + privacy gating + 9 launch categories + crash + bug reports + 8-row dashboard); M36H is the binding glue that turns telemetry into actionable per-mission balance signals, A/B test verdicts, and per-cohort retention curves.

M36H promise: **"every mission has a completion rate, a median duration, a loss-cause histogram, and a quit-point heatmap; A/B tests can be defined as RON cohort assignments and roll out via storyteller mods; chat + voice telemetry is default OFF and per-data-type toggleable; player progression and retention are tracked anonymously per cohort; the per-shard admin dashboard surfaces every signal; no PII ever crosses the wire."**

## Canonical ownership

Owns the per-mission analytics aggregator, the A/B cohort assignment + variant resolution path through the M32 storyteller, the per-data-type opt-in surface in Settings + first-run wizard, the player progression cohort tracker, the funnel-stage definition table + per-stage drop-off detector, the per-shard admin dashboard extensions, and the `cf-analytics-deep` modules listed below. M36B keeps owning the underlying telemetry pipeline + privacy gating engine + crash + bug-report flows; M32 keeps owning the storyteller; M36H binds them into a single per-mission + per-cohort + per-data-type analytics surface.

## Player-facing behavior

- **Per-data-type opt-in is granular.** First-run wizard + Settings → Privacy presents five checkboxes (`basic` / `gameplay` / `chat` / `voice` / `replay`); each toggles independently; `chat` + `voice` default OFF; the others default OFF too per M36B's overall opt-in posture; changing a toggle takes effect at the next session boundary.
- **Per-mission analytics surface to the player too.** After mission resolution, a "Mission stats" panel shows the player's personal time vs the global anonymous median (e.g. "You: 14:32 · Global median: 11:08"); zero PII exposed; only aggregate stats.
- **Quit-point detection captures partial-mission churn.** A player who quits mid-mission emits `mission.quit_point { mission_id, mission_step, tick_count, reason_label }` if `gameplay` opt-in is on; the per-mission step heatmap surfaces which step has the highest abandonment rate.
- **A/B test cohorts assigned deterministically per account.** When a storyteller-modded A/B experiment is active (e.g. `weapon_balance_2026q2 { variant_a: 0.5, variant_b: 0.5 }`), each account is hashed-bucketed into one cohort; cohort assignment is stable across sessions; flipping back and forth between variants per session is forbidden by design.
- **A/B test results feed back per cohort.** The per-shard dashboard shows per-cohort metrics side-by-side (variant A: completion rate 42 % vs variant B: 58 %); statistical-significance threshold gating prevents overreact-on-noise.
- **Player progression is anonymous.** Per-cycle XP, skill curve (KDA equivalent or per-mission win/loss), retention cohort (day 1 / day 7 / day 30 retention) tracked per anonymized session id only; never linked to player name or Steam id; admins see aggregate cohort curves, never per-player identities.
- **Funnel analysis surfaces drop-off.** Onboarding funnel (M44 First Contract → tutorial step N → first mission win → first PvP queue → first MMO shard join → day-7 retained) computes per-step drop-off + flags any step with >30 % session-over-session drop for designer review.
- **Admin dashboard is per-shard.** M49 MMO shard admin sees their shard's analytics; cross-shard aggregation rolls up to the lobby_directory operator dashboard (per DR-031 anti-pay-to-win audit); no cross-shard data leak.
- **Privacy export + delete still works.** Per M36B, a player can export all their telemetry tagged with their anonymized session id and delete it; M36H extends this to per-mission stats + A/B cohort + progression cohort assignments.
- **Mod authors can ship A/B experiments.** A storyteller mod can declare an A/B experiment in its manifest; the framework reads the manifest at mod-load and enrolls accounts into cohorts; modders see per-cohort aggregate metrics (no PII) via the dashboard.

## Per-data-type opt-in matrix

| Data type | Defaults | Contents | Privacy gate behavior when OFF |
|---|---|---|---|
| `basic` | OFF | session start/end, build_id, anonymized session id rotation, system info anonymized | NO telemetry uploaded at all from this account |
| `gameplay` | OFF | per-mission completion, loss-cause, quit-point, A/B cohort metrics, funnel stage, progression XP cohort | Per-mission events dropped; A/B cohorts not enrolled; funnel + progression skipped |
| `chat` | OFF (locked behind extra confirmation modal) | aggregate chat behavior counters (NEVER chat content; only counts and toxicity-flag aggregate) | All chat-derived telemetry dropped at source |
| `voice` | OFF (locked behind extra confirmation modal) | aggregate voice usage counters (NEVER audio content; never STT'd; only push-to-talk and session-time aggregates) | All voice-derived telemetry dropped at source |
| `replay` | OFF | full replay run bundle attachment on opt-in submit (e.g. for bug reports + appeal portal evidence) | Replay attachments stripped from bug reports + appeal payloads |

All five toggles are independent. Enabling `gameplay` does NOT enable `chat` or `voice`. Chat + voice toggle ON requires a confirmation modal that explicitly enumerates "no chat content / no audio is ever transmitted; only aggregate counters" before the toggle commits.

## A/B test cohort assignment

```ron
ABExperimentManifest(
    experiment_id: "weapon_balance_2026q2",
    variants: [
        ABVariant(id: "variant_a", weight: 0.5, payload: { "rifle_damage_mult": 1.0 }),
        ABVariant(id: "variant_b", weight: 0.5, payload: { "rifle_damage_mult": 1.15 }),
    ],
    enrolled_modes: ["pvp_arena", "coop_room"],
    min_sample_per_cohort: 200,
    significance_threshold_p: 0.05,
    auto_advance_on_significance: false,
)
```

Assignment formula: `cohort = variants[ blake3(experiment_id || anonymized_session_id) mod sum(weights) ]`. Stable per session; never flips. Storyteller mod reads `payload` at session start and applies the variant's settings to the active scenario.

Per-cohort metrics collected: completion rate, median mission time, K/D ratio, faction win rate, retention day-7. Statistical significance gated at `p ≤ 0.05` chi-squared (or configured); below significance + below `min_sample_per_cohort` → dashboard shows "insufficient sample" instead of a verdict.

## Funnel stage examples

`funnel_onboarding`: `[install, first_launch, fre_completed, first_contract_started, first_contract_completed, first_pvp_queue, first_pvp_win, first_mmo_join, day_7_retained]`

`funnel_competitive`: `[ranked_queue_first_enter, placement_match_completed, first_ranked_win, bronze_tier_reached, silver_tier_reached, gold_tier_reached]`

`funnel_mmo`: `[mmo_shard_first_join, faction_picked, first_territory_contest, first_mass_war_participated, day_30_retained]`

Per stage: count entered, count completed, count dropped. Drop-off rate per stage = dropped / entered. Stages with rate > `dropoff_threshold` flagged for designer review.

## Out of scope

- Per-player identity-linked analytics (intentionally forbidden by the privacy posture; analytics are anonymous-session-id-keyed only).
- Real-time analytics streaming to a third-party SaaS (Mixpanel / Amplitude / etc.) — Corefall self-hosts; integrations live in optional adapter crates outside this spec.
- Predictive churn modeling (deferred; M36H ships descriptive funnel analysis, not predictive ML).
- Per-cosmetic anti-pay-to-win audit deep (M36B already declared the dashboard view + DR-031 charter; this spec does NOT extend that audit beyond piping per-mission stats into it).
- Live A/B test admin UI for editing experiments mid-flight from a web dashboard (admin uses `cfctl admin.ab_test.advance_phase` + RON manifest editing; web UI is a M48C polish).
- Chat content moderation pipeline (separate behavioral system; out of scope; M36H only ships aggregate counters).
- Voice STT or sentiment analysis on voice (intentionally NOT pursued; voice telemetry is push-to-talk seconds + session-time aggregate only).
- Cross-shard A/B test cohort federation (each shard runs its own experiments; cross-shard joint analysis is a M49 extension if/when needed).

## Notes for the implementer

- Per-data-type opt-in is the privacy contract. NEVER capture chat or voice content; only aggregate counters. Payload-sniffing tests MUST verify this — do NOT trust the toggle alone.
- Cohort assignment uses BLAKE3 of `(experiment_id || anonymized_session_id)` — deterministic, stable per session, never flips mid-session. Do NOT use `rand` or any non-deterministic source.
- The analytics aggregator runs in `cf-analytics-deep` which is server-side per M36B's pattern. It MUST be deterministic — `BTreeMap` for sorted keys, no `HashMap` with `RandomState`, no `Instant::now()` in the aggregation hot path.
- The funnel drop-off detector emits flags as `funnel.stage_dropped { funnel_id, stage, drop_rate }` for designer review; it does NOT auto-fix or auto-block — humans decide.
- A/B significance gating uses chi-squared by default; the threshold + sample minimums are configurable per experiment in the manifest, never hardcoded.
- Per-mission heatmap data is `gameplay` opt-in gated; sessions that opt out contribute zero to the heatmap and do not skew the aggregate.
- Chat + voice toggles require an extra confirmation modal that explicitly enumerates the data contract ("only aggregate counters; never content") — do NOT bypass this modal even when the toggle is set via cfctl admin override.
- The privacy export + delete operations MUST cascade through every analytics category — verify in tests that aggregate metrics re-compute after a per-session delete.
- The dashboard view crates live under `cf-analytics-dashboard` (extending M36B); per-mission, A/B test, funnel, and progression each get their own view module so future M48C polish can re-style independently.
- Anonymized session id rotation per M36B continues — a session id never persists across session boundaries. For longitudinal retention cohort tracking, M36H uses a *cohort id* that is the per-account hash (blake3 of stable account identifier + a per-deployment salt) — this is NOT the session id and is NEVER linkable back to a Steam id or player name; the salt rotates per major version to break long-term linkability.

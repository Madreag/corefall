# M18A — Animation Production Pipeline Tier 1

## Status

`active`

## Intent

**M18A is the Tier 1 animation production pipeline** — sprite walk cycles + hit reactions + death animations + idle breathing + stance transitions + limb-loss visual updates + per-terrain gait variations + chassis boarding/eject animations. Generated via AnimateDiff (ComfyUI workflow) + Pillow frame-strip composition + LLM-prompted keyframe authoring + tween automation.

**Why after M18 (sabotage slice):** by M18 close, the game has full collision (M14) + material kernel (M15) + hazards (M16) + origin reaction (M17) + the BP4 sabotage proof scenario. Static M9A sprites work for the proof, but animations make the simulation FEEL alive — hit reactions per zone (M13), ragdoll-on-death (M14), limb-loss visual updates (M13/M14), chassis boarding/eject (M13). M18A ships right after M18 so M19+ atmospherics scenarios + M21 pressure-hold visualize correctly.

**Why this is the BACKBONE:** the human stops authoring animation FOREVER at M18A. Walk cycles, hit reactions, death animations, idle breathing — ALL generated by AnimateDiff + LLM-prompted keyframe authoring. M48A polishes via Spine; M18A is the Tier 1 floor.

M18A promise: **"every actor walks, runs, crouches, gets hit, dies, ejects from chassis, and loses limbs with believable side-view animation — all generated, all ledgered, all regenerable."**

## Player-facing behavior

After M18A, the player sees:

- **Per-actor walk cycles** — 6-frame walk cycles per stance × per origin (10 origins) × per facing (2) = ~240 actor walk variations
- **Per-stance transitions** — stand → crouch (4 frames) → prone (4 frames) → crawl (4 frames); slide (6 frames); vault (8 frames); climb up/down (12 frames); dive (6 frames)
- **Hit reactions per body zone** — per M13 hit zone routing: head stagger / torso knockback / arm grip-disrupt / leg limp / shin minor / foot minimal × 3 intensities (light/medium/heavy) = 18 per-zone hit reactions
- **Death animations per damage kind** — kinetic collapse / thermal char / electric convulse / chemical melt / radiation crystallize × 5 origins × 4 facing variants = 100 death sequences (Tier 1 quality; M48A polishes)
- **Idle breathing** — every actor breathes (2-frame idle loop per origin)
- **Limb-loss visual updates** — when an arm/leg severs, the sprite re-renders missing the limb + blood/oil spray per origin (M13 + M14 visual contract filled)
- **Per-terrain gait variations** — walk on sand has shuffle; on ice has slip; on metal has clang-step; on wood has creak — gait variations apply M9A frames with offsets
- **Chassis boarding/eject animations** — 1500ms transition with frame sequence per chassis archetype
- **Cockpit camera anchor transition** — first-person zoom-in animation (M13)
- **Spectator camera transitions** — 200ms ease per actor-switch (M41 forward-compat)
- **Reload animations** — per weapon (70+ weapons × reload sequence)
- **Magazine pop / shell eject** — per weapon shell sprite physics (M14 forward-compat)
- **Tool-use animations** — per tool (7 tools × use animation = digger swing, foam spray, weld arc, drill spin, etc.)
- **Photosynthetic / aqueous / methane-breather race-specific idle** — wave-in-water for aqueous; CO2 inhale for photosynthetic; cryo-breath for methane breather
- **War Thunder-style penetration cam animations** (M9 + M13 + M14 + M41 forward-compat): 200ms slow-motion ray traversal animation through chassis

## Animation state machine (cf-animation)

Per actor, per tick, the animation state advances:

```rust
pub struct ActorAnimationState {
    pub current_state: AnimationStateId,            // "walking", "idle", "hit_torso_medium", etc.
    pub current_frame: u8,
    pub frame_started_at_tick: u64,
    pub blend_state: Option<BlendState>,            // upper-body aim + lower-body walk
    pub interrupted_by: Option<InterruptKind>,      // hit reaction can interrupt walk
}

// Transition graph:
// idle ↔ walking ↔ running ↔ crouching ↔ prone ↔ crawl
// any → hit_reaction (per zone) → previous state
// any → death (per damage kind) → terminal
// crouching → climbing → climbed_up
// idle → boarding → vehicle → cockpit (M13)
// vehicle → ejecting → ejected pilot
```

Determinism: frame advancement keyed off sim tick, NOT wall-clock. Same tick + same animation state = same frame.

## Notes for the implementer

### Architecture rules

- **AnimateDiff for keyframe-to-keyframe motion**: produces 4-8 in-between frames; we author the start + end via LLM prompt; AnimateDiff fills the in-betweens
- **Frame strips, not per-frame files**: each animation = one PNG spritesheet with N frames; cf-animation indexes via UV offsets
- **Deterministic frame timer**: frame index = (current_tick - frame_started_at_tick) % total_frames; no wall-clock dependency
- **State machine on cf-animation side**: animation state is a function of (Actor::stance, Actor::active_animation_trigger, current_frame)
- **Layered animation (M48A forward-compat)**: upper-body (aim/fire) + lower-body (walk/crouch) blend via cf-animation::blend_state; M18A ships single-layer only; M48A adds blend

### Per-origin color shift saves bake time

Generating 6-frame walk cycles for 10 origins × 4 stances × 2 facings = 80 walks via AnimateDiff would take ~16 hours on a single GPU. Per-origin color shift on a shared template reduces to ~2 hours.

Trade-off: per-origin walks all look very similar (same silhouette, different palette). M48A Tier 3 adds per-origin animation variety via Spine + hand-authored variations.

### Decision-record alignment

- **DR-019 (visual direction)**: side-view animation per Corefall lineage
- **DR-044 (audiovisual production pipeline)**: M18A is animation Tier 1
- **DR-053 (asset ledger)**: every animation written to cf-asset-ledger
- **DR-055 (game feel)**: hit reactions + death animations support hit-stop + camera-punch from M14

### Pitfalls

- **Frame strip texture atlas size**: 1100 strips × ~64 KB each = ~70 MB. Use Bevy texture atlas with mipmaps; load lazily per-actor at scenario start.
- **Animation state drift in replay**: frame timer keyed off sim tick, NEVER wall-clock. Otherwise replay diverges.
- **AnimateDiff GPU memory**: each animation bake takes ~12 GB VRAM. CI workers with smaller GPUs use SDXL+ControlNet fallback (lower quality but deterministic).
- **Per-origin palette mismatch**: ensure each origin's palette covers the walk cycle's color tokens; pipeline validates.
- **Limb-loss overlay sync**: limb overlay sprite must align with walk-cycle frame coordinates. cf-animation::limb_overlay reads frame_data.ron pivot points.

# M33E — Mod Review + Curation + Recommendation Engine + Author Monetization (DR-031 Compliant)

## Status

`active`

## Intent

**M33E is the mod ecosystem community-quality + author-economics milestone** — closes the missing surface that M33 / M33A / M33B / M33C left behind: M33C shipped the trust + signing + load-order kernel; M33A shipped the in-game browser shell; M33B shipped the Lua sandbox API; M33D shipped the tutorial deep flow. None of those answer the questions a mod ecosystem actually lives or dies on: **"is this mod any good?"**, **"what mod should I try next?"**, **"how does a great mod-author get rewarded without breaking DR-031?"**. M33E ships the 4-pillar answer: **review widget + community moderation + curation pipeline + recommendation engine + DR-031-compliant author monetization**.

M33E promise: **"after a player finishes a Workshop mod session, the in-game review widget asks for a 5-star rating + a per-band comment; a community report-and-flag system policies spam/clones; a mod-of-the-month pipeline runs every 30 days mixing community votes with a 1-author dev-curation slot; a per-player recommendation engine surfaces 6 mods the player will actually like; and great mod-authors can accept tips + sell strictly-cosmetic optional mods + take a Workshop revenue share when Steam supports it — all without violating the anti-pay-to-win commitment in DR-031."**

## Player-facing behavior

### In-game mod review widget

After a Workshop mod has accumulated ≥30 minutes of session time across ≥1 separate session, the next time the player returns to the main menu the review widget auto-prompts (skippable; once-per-mod per profile until rated).

- 5-star slider (1 = "broken / unplayable", 5 = "I'd recommend to a friend")
- Per-rating-band comment box appears with band-specific prompt text:
  - 1-2 stars → "What went wrong?" (placeholder asks for repro/crash/balance feedback)
  - 3 stars → "What was missing?" (placeholder asks for feature gaps + polish notes)
  - 4-5 stars → "What clicked?" (placeholder asks for highlights + author shoutouts)
- 280-char limit per comment; spam-filter pre-pass per `cf-mod-moderation`
- Submit + Skip + "Remind me later" actions; remind-me-later defers 7 days
- Posted reviews aggregated server-side via Workshop API; in-game browser shows `★★★★☆ 4.2 (1,203 reviews)` per mod card
- Per-band comment band visible under expanded mod detail (3 most-upvoted comments per band)
- Player can edit/delete their own review at any time from "My Reviews" tab
- Review is rate-limited: ≥1h per mod between edits to prevent vote-bombing

### Community report-and-flag system

Every mod card has a [Report] action. Reports route to `cf-mod-moderation` queue.

| Report category | Auto-triggered action | Manual review SLA |
|---|---|---|
| `spam_or_clone` | After 5 distinct reporters within 7 days: mod auto-flagged + tier demoted to `experimental` pending review | 72h |
| `broken_or_crashes` | After 3 distinct reporters: yellow warning badge appears on card; mod not delisted | 7 days |
| `malicious_or_unsafe` | After 1 reporter: mod silently quarantined from auto-update + flagged for priority review | 24h |
| `tos_violation` (hate / copyright / adult-content-misflag) | After 2 distinct reporters: mod hidden from browser + flagged for priority review | 24h |
| `paid_pay_to_win` (DR-031 violation) | After 1 reporter: mod flagged + author notified + flagged for priority review | 48h |

- Reporter sees a confirmation toast + their report appears in "My Reports" tab with status (`open` / `under_review` / `actioned` / `dismissed`)
- Mod author sees the report category + count (NOT reporter identity) in their author dashboard
- Reporters who file ≥10 dismissed-as-bad-faith reports in 90 days have their report weight halved
- All moderation actions emit `mod.moderation_action { mod_id, action, reason, moderator_id }` for audit (replay-bundle inclusion)

### Mod-of-the-month curation pipeline

Every 30 days (1st of month), `cf-mod-curation` runs the curation pipeline against the Workshop catalog snapshot.

- **Community-voted slot (1)**: highest-rated mod with ≥500 unique reviews + ≥4.5 stars + ≥7-day-old + no open `malicious_or_unsafe` reports
- **Dev-curated slot (1)**: editorial pick written by a Corefall maintainer (rotating; 1 brief paragraph; surfaced via `content/curation/dev_picks_<YYYY-MM>.ron`)
- **Rising stars (3)**: top 3 mods by 30-day-installs growth rate (relative, not absolute) — surfaces newcomers
- **Genre spotlight (1)**: rotates monthly through tags (Mission Pack / Chassis Mod / Faction Mod / Cosmetic / Quality-of-Life / Storyteller / Total Conversion)
- All 6 surfaced on the main menu "This Month" pane + the in-game mod browser "Featured" tab + a `featured_<YYYY-MM>.ron` ledger entry
- Eligibility rules enforce DR-031: paid-mod-with-gameplay-advantage is **NEVER** eligible (auto-rejected from the candidate pool); cosmetic-only paid mods are eligible
- Past months archive accessible via "Past Featured" tab (12-month rolling window)

### Per-player recommendation engine

`cf-mod-recommend` builds a per-player taste model from observable signals (no telemetry beyond profile-local data).

Signals:
- Player's own ratings (5-star) and review-band patterns
- Per-tag time spent (e.g., 12h on Faction Mods, 2h on Cosmetic — preference vector)
- Co-occurrence: which mods this player has installed together
- Author affinity: did the player rate ≥4 stars on other mods by author X
- Storyteller / chassis / faction / loadout style preferences inferred from M27 / M30 / M31 history

Output:
- **Recommended For You (6 mods)** on the mod browser landing tab
- Each row: mod card + per-recommendation "Why we think you'll like this" caption (e.g., "You loved 3 mods tagged `chassis`")
- Collaborative-filtering pass: kNN over players with overlapping high-rated mods; recommend mods popular with that cohort but not yet installed by current player
- Per-tag preference pass: weight recommendations toward tags the player rates highly
- Anti-spam pass: any mod with an open `paid_pay_to_win` or `malicious_or_unsafe` flag is excluded
- Recommendation refresh: lazy on browser open + nightly background recompute when profile is loaded
- "Why this?" tooltip surfaces the top 3 signals that drove the recommendation (transparency; never opaque)
- Player can dismiss recommendations: dismissed mods downweighted for 90 days
- Optional "Recommendations off" toggle in settings → falls back to "Featured" + "Most Popular" tabs only

### Mod-author monetization (DR-031 compliant — cosmetic / tip-jar only)

All monetization is **strictly opt-in for the player** and **strictly cosmetic / appreciation-only**.

| Channel | Player-facing UX | DR-031 compliance |
|---|---|---|
| **Tip jar** | Per-mod "Tip the author" button → external storefront URL (author-provided Ko-fi / Patreon / PayPal / Stripe link) | Compliant: gameplay unaffected; no in-game advantage |
| **Paid optional cosmetic mod** | Author flags mod as `paid_cosmetic`; Workshop charges player; mod is **gameplay-equivalent to free version** — only visuals / sounds / nameplates / palettes / VFX differ | Compliant: DR-031 cosmetic-only carve-out |
| **Workshop revenue share** | If Steam Workshop offers per-mod revenue share to authors (currently varies by category), authors opt-in via author dashboard; Steam handles payout | Compliant: Steam-mediated; Corefall publisher takes **no cut** of user-authored mods per DR-031 |
| **Author dashboard analytics** | Per-mod installs / ratings / tip-jar clicks / Workshop revenue (when Steam exposes it) | Compliant: discovery + signal; not gated |

- Anti-pay-to-win gate: `cf-mod-trust` refuses load on any mod flagged `paid_*` whose manifest declares any non-cosmetic capability (i.e. anything other than `ui_overlay`, palette/skin asset replacement, audio replacement). Refusal emits `mod.paid_p2w_refused { mod_id, reason }`.
- Anti-clone detection: similarity hash across mod assets (perceptual hash on textures + AST hash on Lua + manifest field overlap); ≥85% similarity to an existing higher-rated mod triggers a "Possible clone of <other_mod>" badge in the browser + flags the clone for moderator review
- Tip-jar URLs validated against a domain allow-list (`content/curation/tip_jar_domains.ron`) to prevent phishing — author can request additions via PR
- Author identity verification: `verified` tier authors only (per M33C signing chain) may flag mods as `paid_*`; community/experimental authors get tip-jar + Workshop revenue share but not paid-cosmetic flag

### Anti-spam + anti-clone detection

Beyond review weighting + manual reports:

- **Mass-upload throttle**: an author publishing >5 mods in 24h triggers rate-limit + maintainer review queue
- **Clone-hash similarity index**: nightly batch over Workshop snapshot; outputs `mod_clone_index.json` consumed by browser badges
- **Review-bombing detection**: any mod receiving >50 1-star reviews within 24h with median word count <10 characters triggers a 7-day review-freeze + auto-flag (reviewer cohort flagged for moderator review; not auto-banned)
- **Bot author detection**: heuristics over publish cadence + manifest stylometry + tip-jar URL similarity across "different" authors → flagged for manual review
- **Self-rating refusal**: an author cannot rate their own mods; `cf-mod-trust` reconciles SteamID against author cert chain at submit time

## Out of scope

- **Paid mods that touch gameplay** — DR-031 forbids; refused at `cf-mod-trust` gate; never in scope.
- **Corefall publisher cut on Workshop revenue** — DR-031 + DR-006 commit to zero publisher cut on user mods; Steam handles payout end-to-end.
- **First-party tip-jar processor** — tip-jar is external-URL surfacing only; no Corefall payment integration (post-launch DR if ever).
- **Cross-Workshop review aggregation** (itch / Mod.io ratings folded into Steam Workshop view) — single source per backend; deep aggregation is M48+ scope.
- **Real-name moderator identity exposure** — moderator IDs are anonymized in audit events; transparency stops at category + action.
- **In-game messaging between players and authors** — direct-message systems are M37/M42 social scope; M33E ships review comments + tip-jar URL only.
- **Auto-removal of mods with low ratings** — low ratings are surfaced, never auto-delisted; only `malicious_or_unsafe` + `tos_violation` + sustained `spam_or_clone` paths can remove a mod.
- **Recommendation engine cross-pollination with non-mod content** (campaign / scenario recs) — M33E recommends mods only; M27/M30 handles in-game content recs.
- **Author payout audit / tax-form support** — Steam handles end-to-end; Corefall surfaces analytics only.

## Notes for the implementer

- **DR-031 is the hard gate.** Any code path that surfaces a paid mod MUST route through `cf-mod-trust::paid_p2w_gate` and emit `mod_paid_p2w_refused` on violation. Do NOT add a "trust me, this is cosmetic" bypass. The capability allow-list is exhaustive: `ui_overlay` + asset replacement (textures / sounds / palettes / nameplates / VFX). Anything else → refused.
- **Recommendation engine determinism**: kNN sort + per-tag preference must be deterministic given the same profile + same Workshop snapshot. Use `BTreeMap` for the per-mod scoring map; tie-break on mod_id lex order. No `HashMap` iteration order in the recommend path.
- **Curation pipeline determinism**: same Workshop snapshot hash + same dev-pick file → same 6 slots. Eligibility filter applied first (deterministic; pure function). Rising-stars uses install-growth ratio over the 30-day window; tie-break on mod_id.
- **Review aggregate computation**: never recompute the 5-star average client-side; trust the server-side rollup from Workshop API + the cf-mod-review cache. The in-game widget displays cached value; staleness ≤24h acceptable.
- **Tip-jar allow-list is content-addressed**: domains in `tip_jar_domains.ron` are validated against an SHA256 list shipped with the engine. Updates require PR + cf-asset-ledger bump (per DR-006).
- **Bad-faith reporter weighting is per-profile**, never global; the halving applies to that reporter's future reports only and never affects past actions retroactively.
- **Anti-clone perceptual hashing** uses pHash for textures + `syn`-parsed AST hashing for Lua + manifest field diff. Pin the hash library version + add a regression test against a curated clone pair to prevent silent hash drift.
- **Author dashboard reads from local profile + Steam Workshop API** — never proxies through Corefall servers; per DR-031 + DR-006 zero-cut posture this stays out-of-band.
- **Review widget overlay uses M11 shell UI primitives** (no bespoke widgets); accessibility per DR-012 (ACC-A): keyboard nav + screen-reader labels free; 5-star slider accepts 1-5 number-key input too.
- **Per-band comment storage**: store `band` enum + `comment` separately so we can re-prompt with the right placeholder when editing; do NOT recompute band from stars at edit time (player may have edited stars + comment independently).
- **Moderation action audit**: every `mod_moderation_action` event includes a moderator_id (anonymized hash per session); reverting an action emits a new event with `action="reverted"` + reference to the prior event_id — never silent-edit prior events.
- **Performance budget**: recommendation refresh on browser open must complete in ≤120ms over a 5,000-mod Workshop snapshot + 1,000-rated profile. Nightly background recompute may take longer but is bounded by 5s budget.
- **Privacy posture**: all signals consumed by the recommendation engine are profile-local; no cross-player data leaves the machine. Collaborative filtering uses the Workshop public review corpus only (already public data; no private signals federated).

## Intent

**M25A is the narrative + codex production milestone** — LLM-driven story bible authoring; 600 codex entries; 8 faction backstories; named-NPC dossiers (24+ NPCs); mission briefings (30+ missions); quest dialog trees (8 quest templates × branches); voyage clue chains (8 voyages × 5-10 clues); achievement descriptions (75+); storyteller event narratives (20+); boss lore unlocks (25 per 5 bosses); per-origin/race lore; per-world lore; per-faction lore; per-material flavor text; tutorial narration text.

**Why after M25 (campaign spine):** by M25 close, the campaign skeleton + factions + storytellers + base + commander all exist. M26 expands factions + NPCs + dialog + quests — but who AUTHORS the actual content? M25A is the LLM-driven content production pipeline that fills every text slot across M25 + M26 + M27 + M28-M32 + M41 + M45.

**Why this is the BACKBONE:** the human does NOT write 80,000 words of narrative. The human writes a 5,000-word story bible (genre, tone, world-history thesis, faction concept seeds, named-character archetypes). M25A LLM expands the bible into the full 80,000 words of codex + dialog + briefings + lore, with per-entry consistency grading.

M25A promise: **"the story bible is a 5,000-word seed; the LLM expands it into 80,000 words of in-game narrative spanning 600 codex entries + 24 named NPCs + 30 missions + 8 factions + 12 worlds + 75 achievements + 20 events + 5 bosses + 10 origins/races — all consistent, all ledgered, all regenerable, all moddable."**

## LLM pipeline algorithm

```text
1. Read story_bible.md (the 5,000-word human-authored seed)
2. Read tone_guide.md + faction_seeds.md + character_archetypes.md + world_seeds.md + race_seeds.md
3. For each content category (codex / NPC / mission / faction / quest / voyage / storyteller / boss / origin / world / material / achievement / tutorial / death_recap):
   a. story_bible_expander.py composes per-entry LLM prompt with:
      - Story bible's relevant section
      - Tone guide constraints
      - Per-entry context (which faction / world / NPC / etc.)
      - Schema fields required to populate
      - Cross-references to existing entries
   b. LLM generates entry (Claude-3-opus / GPT-4 / Llama-3-70B; temperature=0.7 for narrative variance)
   c. consistency_grader.py runs LLM-grader pass:
      - Score: does this entry match the bible's tone? (0.0-1.0)
      - Score: does this entry reference characters/factions consistently?
      - Score: does this entry have plot-coherent logic?
      - If score < 0.7: regenerate with adjusted prompt (max 3 retries)
      - If still < 0.7: flag for human review
   d. branching_validator.py runs for dialog trees:
      - Validates all branches reference valid game state
      - Validates dialog choices don't reference unimplemented features
   e. ledger_writer.py records entry to cf-asset-ledger
   f. Write entry to content/narrative/<category>/<id>.<schema_type>.ron
```

## Notes for the implementer

### Architecture rules

- **Human writes 5,000 words; LLM expands to 80,000** — 16× expansion ratio. Bible is the only human-authored content.
- **Consistency grader runs ALWAYS** — no entry ships without LLM-grader score >= 0.7
- **Branching validator runs for dialog** — quest dialog trees can't reference invalid game state
- **Per-entry seed locked** — same seed + same model + same bible = same output
- **Bible is git-tracked + version-stable** — bumping bible version triggers regen of dependents (per cf-asset-ledger cascade)
- **Schema-versioned** — narrative schemas locked at v1; additive only

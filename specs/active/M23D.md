# M23D — Server-Side GPU AI Compute Path + Per-Tick Inference Budget + Multi-Actor Batched Inference

## Status

`active`

## Intent

**M23D is the GPU server-side AI compute milestone.** The README vision pillar promises "multicore + GPU server-side processing" and lists AI/pathing as a primary beneficiary. M23 + M23B + M23C cover the LLM-API path (per-commander 5s tick, async network round-trip, JSON-RPC proposals, fallback to local heuristics on time-out) but no spec ships the **on-server GPU inference path** — the deterministic, low-latency, multi-actor batched compute that turns "AI is a network dependency" into "AI runs on the same GPU that runs the material kernel."

M23D fills that gap. After M23D, the dedicated server (M36 tier-detected per M36C) can route any `cf-mind` inference call through a **server-resident GPU model** (CPU fallback always present per M36D parity contract) instead of an external network endpoint. The compute graph runs inside the `cf-gpu-scheduler` job system (M36D canonical owner of the GPU job queue), shares the same per-tick budget envelope, respects the same WGSL/CPU-fallback parity rule, and produces deterministic outputs that pass the cross-OS replay parity gate.

M23D promise: **"AI inference is a first-class GPU job — same kernel that runs material CA + atmospherics, same per-tick budget, same determinism contract, no network round-trip, multi-actor batched at 60 Hz."**

## Canonical ownership

This spec is the **canonical owner of server-side GPU AI compute** — the on-server inference path, per-tick batched-inference budget, multi-actor inference graph, model registry, CPU fallback, and replay-determinism contract for AI inference. The async LLM-API path (network round-trip, JSON-RPC, provider adapters) remains owned by **M23 + M23B**; M23D adds the local-GPU path as a peer. The GPU job scheduler + WGSL shader registry + parity matrix is owned by **M36D**; M23D registers AI inference jobs into that scheduler. The CPU fallback contract is owned by **M36D**; M23D supplies the CPU implementation of every inference kernel it ships.

## Player-facing behavior

### Three AI inference paths (selectable at config + auto-routed)

- **`local_heuristic`** — pure-Rust utility scorer per M7; runs every tick; zero GPU/network cost. Floor path; always available.
- **`local_gpu`** (canonical for this spec) — on-server WGSL-compiled inference graph for `cf-mind` tactical proposals + per-actor BotMemory adaptation; batched across all active actors per tick; deterministic on Workstation / Apple Silicon / Linux VPS / Apple Mini Lab tiers (M36C); CPU fallback always paired.
- **`remote_llm`** — async JSON-RPC round-trip per M23/M23B; used for narrative-heavy proposals; never load-bearing for sim determinism.

The router (`cf-mind::inference_router`) picks per call: `remote_llm` if config + budget permit, else `local_gpu` if the tier exposes a GPU, else `local_heuristic`. The router decision is replay-recorded.

### Per-tick AI inference budget

| Server tier | GPU AI budget per tick | CPU AI budget per tick | Routing default |
|---|---|---|---|
| Workstation (9950X3D + RTX 5090) | 1.5 ms (≤ 200 batched inferences) | 4 ms | `local_gpu` |
| Apple Silicon (M2 Ultra + 76-core GPU) | 1.5 ms | 4 ms | `local_gpu` |
| Linux VPS (no GPU; CPU only) | 0 ms | 6 ms | `local_heuristic` (no `local_gpu` available) |
| Apple Mini Lab (M1 + 8-core GPU) | 2.5 ms | 5 ms | `local_gpu` (degraded batch size) |

Budget is enforced by `cf-gpu-scheduler::budget_enforcer` (M36D). Exceeding budget = fall back to `local_heuristic` for the remaining inferences this tick; replay records every fallback.

### Multi-actor batched inference

- Per tick, all actors with a pending `MindTick` request are collected, their `TacticalContext` snapshots are concatenated into a batched input tensor, the inference runs ONCE on the GPU as a single dispatch, and the output tensor is split back into per-actor `TacticalProposal`s.
- Batch size cap = `actors_per_shard / 4` (typical: 50 actors per shard → 12 actors per batch tick; rolling 4-tick coverage of all 50 actors).
- Per-batch deterministic order: actors sorted by `actor_id` ascending; tie-broken by `shard_id` (multi-shard MMO).
- BotMemory adaptation runs on the same GPU pass — pain memory ring updates, weapon-threat ranker increments, doctrine_cache writes all happen in one job-graph dispatch.

### Model registry

Ships 5 inference models at M23D close (all WGSL + CPU-fallback paired):

| Model id | Purpose | Input | Output | Tier required |
|---|---|---|---|---|
| `tactical_proposal_v1` | Per-actor 1-3 tactical proposals (cover / flank / retreat / engage) | TacticalContext (64 features) | TacticalProposal (3× scored actions) | Workstation / Apple Silicon |
| `loadout_optimizer_v1` | Per-actor next-spawn loadout pick | 32-feature loadout signature | LoadoutChoice (1 of 12 archetypes) | Workstation / Apple Silicon / Mini Lab |
| `commander_adaptation_v1` | Per-commander squad-comp adjustment over mission window | 128-feature CommanderDoctrineState | Squad-comp delta vector (8 axes) | Workstation / Apple Silicon |
| `pain_memory_update_v1` | BotMemory ring update on hit (deterministic, no ML; just batched arithmetic) | DamageEvent batch | BotMemoryDelta batch | All tiers (no model; pure GPU compute) |
| `chatter_select_v1` | Per-actor chatter line pick from M37 library | 16-feature actor state | Chatter-line index (per archetype) | All tiers |

All 5 models live in `content/ai_models/<id>.wgsl` + `content/ai_models/<id>.cpu.rs` paired sources. The CPU fallback is byte-equivalent on every supported tier; cross-tier parity is asserted at the M36D 1/15 cadence.

### Deterministic + replay-safe

- Every GPU inference call emits a `mind.inference_dispatched { tick, model_id, batch_size, routing_path, batch_input_hash, batch_output_hash }` event.
- Every fallback emits `mind.inference_fallback { tick, model_id, from_path, to_path, reason }` (budget-exceeded / GPU-unavailable / parity-mismatch).
- Replay parity gate (M36D) verifies that on the same seed + same input batch hash, every supported tier produces the same output batch hash.
- Cross-OS gate (M8A) verifies x86_64-linux + aarch64-darwin + x86_64-windows produce byte-identical inference output for all 5 models.

## Acceptance criteria

```gherkin
Scenario: GPU-tier server routes inference to local_gpu by default
  Given a dedicated server detected as Workstation tier (per M36C)
  And tactical_proposal_v1 model is loaded

  Then cf-mind::inference_router routes them to local_gpu (default for Workstation)
  And the batched dispatch runs in ≤ 1.5 ms wall-clock per M36C budget
  And mind.inference_dispatched fires once with batch_size in range 12..=50

Scenario: VPS tier with no GPU falls back to local_heuristic

  And mind.inference_router_decision fires with reason = "tier_has_no_gpu"

  And per-tick GPU AI budget = 1.5 ms
  When the first 50 inferences consume 1.4 ms
  Then the next inference is rejected by cf-gpu-scheduler::budget_enforcer
  And remaining 150 actors fall back to local_heuristic for this tick
  And mind.inference_fallback fires per dropped inference with reason = "budget_exceeded"

Scenario: Cross-tier GPU/CPU parity check at 1/15 cadence
  Given local_gpu path is active on Workstation tier

  Then batch_output_hash matches byte-for-byte
  And no mind.inference_parity_mismatch event fires
```

## Out of scope

- Training new models in-game (M23D ships pre-trained models; training pipeline is post-launch / mod-author territory).
- LLM API path (M23/M23B own); M23D never blocks on a network round-trip.
- Non-deterministic ML primitives (dropout, stochastic layers); only deterministic forward passes ship.
- GPU AI for narrative generation (M25B owns the LLM narrative bake; M23D is sim-only).
- Per-actor 1:1 inference (always batched; per-actor only via debug override).

## Dependencies

- M23 (cf-mind crate + JSON-RPC scaffold) — must close.
- M23B (BotMemory + commander_doctrine + tactical_planner) — must close; M23D modifies its read-path.
- M36C (server tier detection + per-tick budget) — must close; M23D consumes tier table + budget envelope.

- M36 (server mode framework) — required for tier-aware routing defaults.

## Notes for the implementer

- Start with the CPU fallback for all 5 models (proves the math + replay determinism before any GPU code). Add the WGSL pair second; assert byte-identical output on a fixed corpus of 1000 inputs.
- The batch sort order (`actor_id` ASC, `shard_id` ASC) MUST be applied BEFORE the input tensor is built. Any permutation invariance is a determinism bug.
- Use `cf-control/src/m23d_actions.rs` for the new cfctl methods (follow the per-spec cfctl write-merge convention from M33B/C/D/E).
- The `tactical_proposal_v1` model can be a tiny MLP (16 hidden units × 2 layers); it doesn't need to be deep — the value is the deterministic batch path, not the model expressiveness. Mod authors can ship larger models post-launch.
- WGSL shader compilation must be reproducible across drivers; use `wgpu::naga` with a pinned version.
- The 5 launch models are deliberately small + simple. Sophistication belongs to mod-authored models on Workstation tier where they fit the budget.

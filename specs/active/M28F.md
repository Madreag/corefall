# M28F — Blueprints + Zoning + Pre-fabricated Modules + Drop-In Bunkers

## Status

`active`

## Intent

Closes three M28A gaps: (a) blueprints are in-memory only — no export/import/sharing/Workshop fetch; (b) rooms have no zoning layer for per-faction access control or per-room category (security/quarantine/medical/storage/work); (c) base construction is fully manual, with no orbital drop-in fallback for crash-landed players. M28F adds shareable `.blueprint.ron` files + Steam Workshop integration, a paint-on zoning layer with per-faction permissions + IC10 readouts, and 6 drop-in pre-fab modules that a dropship deploys in 30s + auto-pressurizes + auto-powers.

## Player-facing behavior

### Blueprint export, import, Workshop sharing

- **Save blueprint** from M28A → writes `.blueprint.ron` to `~/.corefall/blueprints/<name>.blueprint.ron` with author + dimensions + per-tile module manifest + atmospheric/power/thermal topology hints + zone overlay + material cost + build time.
- **Import blueprint** from filesystem or Workshop ID → loads into M28A paste mode; player ghosts at cursor and confirms.
- **Steam Workshop**: subscribe via Workshop ID → synced to `~/.corefall/blueprints/workshop/<id>/`; appears in M28A browser with author + rating + thumbnail.
- **Validation on import**: missing module IDs / missing materials / dimension overlap highlighted red; player chooses skip-missing or cancel.
- **Auto-build**: queue blueprint for AI bots (M22 path-aware); bots fetch materials → place ghost → build per `build_time_seconds`; emits `blueprint.auto_build_step` per module; pause/resume supported.

### Per-base zoning + per-faction permissions

- **Zone painter** ([Z] from build mode): cursor paints zones over rooms detected by M28; zone fills entire sealed volume.
- **Zone types** (8 launch): `security_clearance_1/2/3`, `no_actor`, `restricted_access` (per-actor whitelist), `quarantine` (M16A hazard-locked), `medical`, `storage`, `work`.
- **Per-faction permissions**: per-zone allow-list per faction (DR-031); default to author-faction-only; editable via multi-select.
- **Enforcement**: unauthorized entry fires `zone.access_denied`; policy per zone: door auto-close (default), turret target, alarm, warning-only.
- **F8 zone overlay**: per-type color (red/yellow/blue/gray); floating zone label.
- **IC10 readout per zone**: `zone.occupancy_count`, `zone.unauthorized_count`, `zone.last_breach_tick` — drives automated lockdown.

### Pre-fabricated drop-in modules

Six launch pre-fabs dropshipped from M44 orbital pool; deploy in 30s (parachute 10s + landing 5s + auto-expand 10s + auto-pressurize/power 5s).

| Pre-fab | Footprint | Rooms | Includes | Cost | Use case |
|---|---|---|---|---|---|
| `bunker_t1` | 24×12 | 4 | T1 walls, 1 airlock, 1 RTG (0.5 kW), 1 scrubber, stove, 4 bunks | 200 iron + 80 plastic + 1 RTG | Emergency colony (30 days solo) |
| `bunker_t2` | 36×16 | 8 | T2 insulated walls, 2 airlocks, 1 nuclear reactor (100 kW), coolant loop, vacuum radiator, 4 scrubbers, full HVAC | 800 steel + 300 plastic + reactor + 10 uranium rods | Mid-game permanent outpost |
| `observation_post` | 8×8 + 16-mast | 1 | Long-range radar, 4 optics, 1 RTG, atmospheric scoop | 80 steel + 40 electronics + RTG + dish | Recon (M22 observer doctrine) |
| `hospital_module` | 16×8 | 2 | 4 hospital beds, 2 medical fabricators, surgical robot dock, M28E sterile-air, pre-painted quarantine zone | 300 steel + 200 plastic + 80 electronics + 4 surgical kits | Field hospital (4 actors parallel) |
| `atmospheric_module` | 12×12 | 1 | 4 industrial scrubbers, 2 condensers, 2 gas-fill stations, 4 refrigerant tanks, sprinkler+halon, M28E filter loop | 250 steel + 150 plastic + 8 filters + 4 refrigerant | 30-actor base atmosphere overhaul |
| `mining_outpost` | 24×16 | 3 | T2 smelter, T1 fabricator, ore conveyor port, 6 bunks, RTG + solar array | 400 iron + 200 plastic + smelter + 4 panels | Forward mining base (drop near M30 deposit) |

- **Dropship request**: `act.player.request_prefab_drop { prefab_id, target_hex, dropship_id }` → fires `prefab.deploy_complete` at T+30s with new base handle.
- **Deploy validation**: flat ground (M30 query) + no enemy within 4 tiles + dropship cargo + unlock; failure fires `prefab.deploy_rejected { reason }`.
- **Pre-fab as blueprint**: internally a `.blueprint.ron`; modders override via `content/prefabs/<id>.prefab.ron` — same export/import path.

## Acceptance criteria

```gherkin
Scenario: Blueprint round-trips through export → import → paste
  Given a 6-room base built in M28A blueprint mode
  When the player presses [Export Blueprint] and names it "first_outpost"
  Then a file ~/.corefall/blueprints/first_outpost.blueprint.ron is written
  And blueprint_exported event fires with author + dimensions + material_total
  When the player starts a fresh world and imports "first_outpost"
  Then blueprint_imported event fires
  And the M28A paste-mode ghost shows the identical 6-room layout
  And per-module material cost matches the exported manifest exactly

Scenario: Workshop blueprint subscription downloads + caches
  Given the player has Steam Workshop linked
  When the player subscribes to blueprint Workshop ID 1234567
  Then cf-net workshop_client fetches the .blueprint.ron and thumbnail
  And blueprint_subscribed event fires with workshop_id + author + sha256
  And the blueprint appears in the M28A blueprint browser with rating + download_count
  And subsequent re-subscription is a cache hit (no re-download)

Scenario: Auto-build executes blueprint via AI bots
  Given an imported "first_outpost" blueprint in paste mode
  And 2 construction bots available with 600 iron + 200 plastic in storage
  When the player confirms "Auto-Build"
  Then blueprint_auto_build_step events fire per-module in dependency order
  And bots fetch materials → place ghost → wait build_time_seconds → activate module
  And the entire 6-room base completes deterministically across two engines with same seed

Scenario: Zone painter assigns medical zone to closed room
  Given a sealed 4×4 room with one airlock
  When the player enters zone painter [Z] and paints "medical" on the room
  Then zone_painted event fires with zone_type=medical + room_id
  And the M28A HUD F8 overlay shows the room in blue with "Medical" label
  And M14 / M16A healing-doctrine AI prioritizes this room for wound treatment

Scenario: Per-faction zone permission denies traders from clearance_3
  Given a reactor room painted "security_clearance_3" with player-faction only
  And a trader NPC actor approaches the reactor door
  When the trader attempts to enter
  Then zone_access_denied event fires with actor_id + zone_id + reason="faction_not_whitelisted"
  And the airlock interior door auto-closes (policy=auto_close)
  And the trader's M22 pathfinding re-routes to the trade depot zone

Scenario: Zone permission IC10 readout drives automated lockdown
  Given a reactor zone "security_clearance_3" wired to an IC10 chip
  When 2 unauthorized actors enter the zone simultaneously
  Then zone.unauthorized_count reads 2 on the IC10 chip
  And the IC10 program triggers `alarm_klaxon` + `auto_close_all_doors`
  And cf-replay records both the cause (unauthorized_count > 0) and the effect (door closures)

Scenario: Pre-fab bunker_t1 drops from orbit in 30 seconds
  Given a player on Mimas with 4 minutes of suit O2 remaining
  And a dropship in orbit with 1 bunker_t1 prefab cargo slot
  When the player calls `act.player.request_prefab_drop { prefab_id: "bunker_t1", target_hex: H }`
  Then prefab_deploy_requested fires
  And the dropship descends + parachutes the prefab over 10s
  And the prefab lands + auto-deploys over 5s
  And the prefab auto-pressurizes + powers from the included RTG over 5s
  And prefab_deploy_complete fires at tick T+30s with a new base_id
  And the player can enter the airlock and breathe at tick T+30s

Scenario: Pre-fab deploy rejected on hazardous terrain
  Given a target hex with active lava flow (M30 terrain query)
  When the player requests bunker_t2 drop
  Then prefab_deploy_rejected fires with reason="terrain_unsafe_lava"
  And the dropship aborts descent; cargo retained
  And no materials or currency are consumed

Scenario: Determinism across blueprint + zone + prefab pipeline
  Given two engines running m28f_blueprint_roundtrip and m28f_prefab_drop_bunker_t1 with same seed
  When 1200 ticks elapse covering export + import + paste + zone paint + prefab drop
  Then identical event sequence (blueprint_exported, _imported, zone_painted, prefab_deploy_complete)
  And identical SaveBlob.checksum at tick 1200
```

## Out of scope

- Blueprint diff / merge tooling (compare two blueprints, merge layouts) — modder + community-tool territory.
- Workshop comment threads / ratings authored from in-game UI — Steam-overlay flow only.
- Per-zone temperature override (zones drive HVAC setpoints automatically) — M28D owns thermostat logic; M28F only exposes the zone metadata.
- Cross-server blueprint sync (e.g., MMO shared blueprint library) — M48+ networking ambition.
- Procedurally generated pre-fab variants — M48+; M28F ships 6 fixed designs.
- Pre-fab destruction by enemy fire reverts to blueprint-restorable rubble — covered by M28B breach-repair flow.

## Notes for the implementer

- `.blueprint.ron` schema carries `format_version: u32`; legacy versions converted on load.
- `cf-net::workshop_client` wraps steamworks-rs; if Steam unavailable, fall back to filesystem-only + warning event.
- Zone painter consumes M28 closed-volume detection; breach (M28B) auto-suspends zone with event; re-seal re-enables.
- Auto-build doctrine soft-locks reserved materials; `act.player.cancel_auto_build` releases.
- Unknown modded faction defaults to `deny` + warning event.
- Pre-fab deploy reuses M44 dropship cargo-unload animation; 30s timer configurable via `prefab_deploy_seconds` server setting for tests.
- IC10 zone read via `db dz <zone_id>` per M29A ABI.

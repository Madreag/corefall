# M40 — LAN Co-op

## Status

`active`

## Intent

**M40 is the LAN Co-op milestone**. Two to four clients on a local network can play one Breach Contract together via `cf-server --mode lan_room` with replicated state, authority resolution, anti-cheat foundation enabled, and replay parity.

M40 promise: **"two to four friends on the same LAN play a co-op mission with bit-identical replay parity across all clients."**

## Player-facing behavior

### LAN co-op session flow

- Player 1 launches `cf-server --mode lan_room` on host machine
- Other players' clients open LAN browser → auto-discover server via mDNS / UDP broadcast
- Lobby UI appears with ready-up flow
- All players ready up → mission starts
- Server-authoritative simulation; clients send inputs via `cf-control` envelope; receive snapshots + events

### LAN discovery

- mDNS / UDP broadcast for local network discovery
- No NAT punch-through yet (M41 adds for online co-op)
- Auto-discovery within ~3 seconds
- Lobby filters: scenario + mod compatibility + player count

### Authority model

Per DR-005 + DR-052:
- Server is 100% authoritative for sim
- Clients send inputs only (via `cf-control` envelope from M36)
- Server sends snapshots + events to all clients per tick
- Clients use prediction + reconciliation for player-driven actor (smooth feel)
- Pure replication for AI bots (no prediction)

### Replicated state

- Actors (per-tick snapshots + delta events)
- Terrain (M3 chunk dirty + per-chunk checksum)
- Inventory (per-actor with weight + slots)
- Objective state (per M7 mission director)
- Base modules (per M25 base)

### Co-op friendly fire policy

- Configurable per scenario (default: per DR-018 consequence ladder)
- Player can toggle on / off in lobby
- Per-mode default: `casual` friendly-fire-off; `competitive` friendly-fire-on

### Per-client replay bundles

- Each client emits own run bundle with per-client perspective
- `cf-headless replay-compare <bundle_A> <bundle_B>` aligns tick-for-tick
- Bandwidth budget within target (per T-PERF)

### Anti-cheat profile `casual`

- Default for LAN co-op
- Logs anomalies but does NOT kick (LAN trust assumed)
- Per DR-052 anti-cheat tiers

### Mod hash sync

- Server checks client mod packages match
- Soft-fail with clean diff UI (NOT crash)
- Per-mod trust tier respected (`vanilla` / `verified` / `community` / `experimental`)

### Co-op session features (2-4 player LAN-specific)

- **Cross-player visibility (full)** — all players see each other always
- **Shared loadout** — combined squad inventory pool
- **Per-player role assignment** — assign squad role at lobby (rifleman / sniper / engineer / medic / heavy / recon / tech)
- **Voice chat (LAN proximity-based)** — same as in-game voice via M37; LAN has zero latency
- **Text chat** — lobby + in-game keyboard text chat
- **Death cam** — player can spectate other living players when dead (M41 extends with full spectator)
- **Revive mechanic** — player can revive downed teammate within window
- **Shared mission objectives** — all players see same objective state
- **Per-player run bundle** — each client emits own bundle; align tick-for-tick

### LAN-specific tooling

- **LAN scanner**: client tool to list discovered cf-server LAN instances + ping + scenario
- **Quick-host wizard**: streamlined `cf-server --mode lan_room` flow for non-technical users (single command)
- **Bandwidth budget verification**: client UI shows current bandwidth usage

## Acceptance criteria

```gherkin
Scenario: Two clients survive 5-minute Breach Contract
  Given cf-server --mode lan_room on host
  When two clients join via LAN discovery
  Then session starts; both players visible in mission
  When mission completes after 5 minutes:
    Then both clients see same outcome
    And each client's run bundle aligns tick-for-tick

Scenario: cf-headless replay-compare aligns bundles
  Given two per-client bundles from same session
  When cf-headless replay-compare <bundle_A> <bundle_B>:
    Then output: result=ok with all checksums matching

Scenario: Bandwidth budget within target
  Given LAN session with 4 players
  When T-PERF measures bandwidth:
    Then per-client bandwidth < target (per T-PERF gate)

Scenario: Mod hash mismatch produces clean diff UI
  Given server with mod_pack_A; client with mod_pack_A_v2
  When client connects:
    Then mod_hash_mismatch fires
    And clean diff UI shown
    And NO crash

Scenario: Friendly fire toggleable
  Given lobby with friendly_fire=on
  When player kills teammate:
    Then friendly_fire_dealt event fires; teammate takes damage
  When friendly_fire=off:
    Then friendly fire ignored; no damage to teammate

Scenario: 2-4 player range supported
  Given LAN room
  When 2, 3, or 4 players join:
    Then session supports all; lobby UI scales

Scenario: Anti-cheat casual profile
  Given casual profile active
  When client sends slightly anomalous input (e.g. spike):
    Then anomaly logged
    But client NOT kicked (LAN trust)
```

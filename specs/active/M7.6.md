# M7.6 — Power & Electrical Engineering Kernel

## Status

`active`

## Intent

**M7.6 is the deep electrical-power simulation milestone** — the central nervous system of every base, vehicle, chassis, and PvE-survival scenario. After M7.6, power is a **first-class simulation** with generation sources (solar / wind / chemical / RTG / nuclear / kinetic / geothermal / hand-crank), transmission (cables with amperage caps + voltage tiers + transmission loss), storage (batteries with charge/discharge curves + capacitors + thermal mass), demand profiling (peak vs sustained load), protection (fuses + breakers + ground-fault + surge), failure modes (brown-out + black-out + over-volt + arc-fault), and IC10 logic-driven priority load shedding.

Per [[spec/command-core-base-power]] + DR-027: the brain / command core is **both a power consumer AND a power amplifier when rooted**. The avatar mechanic creates a hard strategic choice: keep the core in the bunker for +30% generator efficiency + grid smoothing + emergency reserve, OR uproot it into a chassis avatar for personal buffs (per-origin: humans = command aura; androids = battery passthrough; robots = core overclock) at the cost of base power collapse.

M7.6 promise: **"every watt matters; players who learn the load curve defeat players who don't; the brain IS the grid."**

### Power transmission — cables, voltage tiers, transmission loss

Per Stationeers + ONI cable hierarchy + real-world electrical engineering:

| Cable tier | Voltage class | Max amperage | Transmission loss / 10m | Cost / 10m | Use case |
|---|---|---|---|---|---|
| **`bare_copper`** | Low-voltage (24V) | 0.5 kW | 5% | 2 iron | Hand-crank / RTG / single-light circuits |
| **`insulated_copper`** | Low (120V) | 2 kW | 3% | 4 iron + 1 plastic | Solar panels / basic turret circuits |
| **`shielded_cable`** | Medium (480V) | 5 kW | 2% | 6 iron + 2 plastic + 1 copper | Standard base power transmission |
| **`industrial_cable`** | High (4 kV) | 25 kW | 1% | 10 iron + 4 plastic + 4 copper | Reactor backbone; heavy machinery |
| **`hv_transmission`** | High-Voltage (35 kV) | 100 kW | 0.5% | 20 iron + 10 plastic + 8 copper + 2 silver | Long-distance backbone; high-throughput cluster |
| **`superconductor_cable`** (T4 tier; Material Lab unlock M8.5) | Critical (any) | 1 MW | 0% | exotic materials | Endgame; cryogenic-only (Mimas / Europa native) |

**Voltage tiers + transformers:**

- Equipment runs at one of 4 voltage classes (`low_voltage`, `medium`, `high`, `critical`)
- **Transformer** modules step voltage up/down between circuits; required where voltage classes meet; lossy at boundary (3% transformation loss)
- Voltage mismatch = no power transmission (visible "VOLTAGE MISMATCH" warning + amber cable highlight)
- HV equipment connected to LV cable = breaker trips immediately (red highlight + cap event)
- Per Stationeers "Step transformer" + ONI "Power Transformer" pattern

**Cable severance / damage:**

- Cables route through terrain per M2 path-cost
- Damaged terrain breaks cables; player sees red break point
- Sparks at break (cosmetic; can ignite combustible atm per M5.9; can short-circuit via wet material)
- Arc fault → high heat at break → secondary fire risk

**Events:**
- `power.cable_placed` / `power.cable_removed` / `power.cable_damaged` / `power.cable_severed`
- `power.transmission_loss_calculated { from, to, loss_pct, length_m }`
- `power.voltage_mismatch { cable_id, expected_voltage, source_voltage }`
- `power.arc_fault { cable_id, position, heat_released_j, ignition_risk_pct }`

### Energy storage — batteries, capacitors, thermal mass, chemical reservoirs

Storage decouples generation from consumption:

| Storage type | Capacity | Charge/discharge profile | Self-discharge rate | Failure mode |
|---|---|---|---|---|
| **Lithium-Ion Battery Bank** | 50-1000 kWh (configurable per bank size) | Lithium-curve: fast charge 0-80%, slow trickle 80-100%; constant discharge until cutoff; 90% round-trip efficiency | 0.5% / day | Overcharge → swelling → thermal runaway risk (M5.9 atmospherics integration); puncture → electrolyte leak (per M2.5 fluid system) |
| **Lead-Acid Battery** | 100-500 kWh | Simpler curve; 70% efficiency; cheaper but heavier; can deep-discharge with degradation | 1% / day | Acid leak (M5.6 reaction with iron → rust); long-life if maintained |
| **Capacitor Bank** | 0.1-5 kWh (small) | Instant discharge (single-tick burst); fast recharge | 1% / second | Designed for spike loads (railgun fire / shield burst / EMP recovery) |
| **Thermal Mass (Heat Battery)** | Variable | Heat storage via molten salt / phase-change material; converts back via Stirling engine OR thermocouple | Slow decay (insulation-dependent) | Solid-state; long lifespan; lower round-trip efficiency (~40%) |
| **Chemical Reservoir** | Fuel-as-energy stored | Burn rate determines discharge; high energy density | 0% (chemical) | Pumping required; combustion risk |
| **Compressed-Air Storage (CAES)** | Variable | Air compressed during surplus; released through turbine | 2% / hour leak | Requires pressurized vessel; rupture risk |

**Battery state visible in HUD:**
- Charge % + voltage + current draw (in/out)
- Temperature (overheating warning at 60°C; thermal runaway at 80°C)
- Cycle count (lifetime usage)
- Health % (degrades with each full cycle; 80% = end-of-life warning)

### Demand profiling — peak vs sustained load

Every powered device declares:

```rust
pub struct PowerDraw {
    pub idle_w: f32,            // sustained baseline power
    pub active_w: f32,          // power during active operation
    pub peak_w: f32,            // instantaneous spike (e.g. weapon fire)
    pub peak_duration_ms: u32,  // how long peak holds
    pub inrush_factor: f32,     // startup spike multiplier (motors typically 3-6×)
    pub voltage_class: VoltageClass,
    pub priority_band: PriorityBand,  // critical / important / utility / luxury
}
```

**Priority bands (load shedding order on brown-out):**

1. **`critical`** — life support / shield / reactor cooling / command core / sealed doors. **NEVER** shed automatically; brown-out at this level = mission failure cascade.
2. **`important`** — turrets / sensors / pumps / repair stations / charging pads. Shed second-to-last.
3. **`utility`** — lighting / heaters / HVAC / non-essential pumps. Shed first.
4. **`luxury`** — cosmetic lighting / decorative panels / non-mission systems. Shed before any other.

### Brown-out / black-out / surge — failure cascade

When `total_demand > total_supply + battery_discharge`:

| Severity | Trigger | Effect | Visual cue |
|---|---|---|---|
| **Normal** | demand ≤ supply | All systems run | Green grid overlay |
| **Surge-warning** | demand 90-100% of supply | All systems run; load slow | Yellow grid overlay; HUD banner "POWER LOAD HIGH" |
| **Brown-out (mild)** | demand 100-120% of supply | `luxury` shed first; lights dim; cosmetic systems off | Amber overlay; banner "BROWN-OUT — LUXURY OFFLINE"; HUD shows shed devices |
| **Brown-out (moderate)** | demand 120-150% | `utility` shed; turrets aim wobble; non-essential pumps off | Orange overlay; banner "BROWN-OUT — UTILITY OFFLINE"; sensor confidence reduced |
| **Brown-out (severe)** | demand 150-200% | `important` shed; shields drop; turrets offline; doors require manual; sensors blind | Red overlay; banner "BROWN-OUT — IMPORTANT OFFLINE"; **commander AI escalates: "REINFORCEMENTS REQUIRED"** |
| **Black-out (full)** | total supply = 0 OR `critical` failure | Local battery-powered emergency lighting only; command core on reserve; everything else offline | Black overlay with red emergency LEDs; banner "BLACK-OUT — EMERGENCY POWER" |
| **Over-volt (surge)** | generator inrush + no protection | Equipment damaged per inrush_factor; cascading breaker trips | Red flash on affected nodes; equipment HP drops |
| **Cascading failure** | breaker trips → load redistributes → next breaker trips → ... | Stationeers-style brown-out spiral; chain reaction across grid | Sequential red flashes; HUD shows cascade visualization |

**Per-tick load shedding algorithm (deterministic + replay-stable):**

```text
1. Sum all generation (solar curve + wind curve + chemical + RTG + nuclear)
2. Sum battery discharge capability
3. Total supply = generation + battery_discharge
4. Sort all consumers by (priority_band, device_id) for deterministic ordering
5. Allocate supply to consumers in priority order
6. When supply exhausted at boundary:
   - If priority = critical: enter black-out (mission cascade)
   - Else: shed remaining lower-priority consumers
7. Update each consumer's state (powered / shed / dimmed)
8. Emit `power.grid_state_changed` event with full payload
```

**IC10 chip integration:** server admins / players can write IC10 programs to override load shedding (per Stationeers MIPS pattern):

```
# Example: Custom load priority - shed lights before turrets in defensive mode
lb r0 d_defense_mode # 1 = defensive
beq r0 1 prioritize_turrets
# default priority
yield
prioritize_turrets:
  s d_lights_circuit On 0  # turn lights off
  s d_turret_circuit On 1  # ensure turrets on
  yield
```

### Personal-power layer — per-actor power grid (mirrors base grid at smaller scale)

Per M5.8 personal-power contract — M7.6 implements the **actor-side** of the electrical sim. Each actor with powered equipment runs its own miniature grid:

**Personal grid components per actor:**

- **Battery pack(s)**: 1 primary + 1 backup slot (per M2.2A inventory); T1..T4 tiers (per M7.8 crafting)
- **Charging port**: connector on actor body for plug-in charging at base
- **Solar trickle** (robot-only by default): small panel on body that generates ~50 W in daylight
- **Equipment power list**: every powered item declares idle/active/peak draw + voltage class
- **Personal priority chain**: same priority bands as base (critical / important / utility / luxury); player-configurable
- **Auto-shed**: at low battery threshold (default 30%), lowest-priority equipment shed first
- **Heat accumulator** (robot-only): equipment use generates heat; dissipates per M5.9 atmospherics

**Per-tick personal load shedding** (deterministic + replay-stable):

```text
1. Read actor.equipment list + power_priority_chain
2. Sum total demand
3. Read battery discharge capability
4. If demand <= battery_discharge AND charge_rate_inbound:
   → all equipment powered; battery slowly drains OR charges per net
5. If demand > battery_discharge:
   → shed lowest-priority equipment until demand fits
   → emit `power.actor_equipment_shedded` event
6. Update each equipment's powered state
7. Update battery charge
8. Emit `power.actor_battery_changed` if delta > threshold
```

**Origin-specific personal grid behaviors:**

- **Human**: body has no power need; battery only fuels equipment. Battery empty = all equipment offline; body unchanged. Player must walk to base to recharge.
- **Robot**: body itself draws constant `critical` power (CPU + sensor + locomotion); battery empty = INERT state (per M5.8). Solar panel on body trickle-charges in daylight (~50 W). Robot in vacuum: must manage heat dissipation as well as power.
- **Android (organic_fraction = 0.5)**: synthetic side draws power; organic side independent. Battery empty = synthetic abilities offline; organic side keeps function.
- **Hybrid (heavy_biomech, powered_organic)**: per organic_fraction; equipment-only power needs.

**Charging modes:**

1. **Charging pad at base** (M7.6 base module + M7.5 placement):
   - Actor stands on pad → press [E] → battery charges at pad's wattage (2 kW T1; 10 kW T2; 25 kW T3)
   - HUD shows charge rate + time-to-full
   - Actor can leave; battery charges over time even with actor absent (player retrieves later)

2. **Hot-swap station at base**:
   - Stores 4-8 charged batteries in queue
   - Actor approaches → press [E] → drop dead battery → instant new battery seated (1-3s animation per tier)
   - Dead battery auto-routes to attached charging pad

3. **Direct cable plug-in**:
   - Plug actor's charging port into cable connected to grid
   - Same as pad but no positioning constraint
   - Limited to T1/T2 batteries (HV cables require pad)

4. **Solar charging (robot-only):**
   - Robot has small body-mounted solar panel (+50 W in daylight)
   - Doesn't fully charge battery alone but extends runtime significantly
   - Affected by M7.7 weather + M7.7 day/night cycle
   - On Vulcan: 2× output; on Mimas: negligible

**Battery hot-swap UX (deep dive):**

| Step | Player action | HUD feedback |
|---|---|---|
| 1 | Press [B] (Battery hot-swap hotkey, remappable) | Pie menu opens with battery slot options |
| 2 | Select "swap primary" | Animation begins; equipment briefly offline |
| 3 | Battery seats (1-3s per tier) | Equipment powers up; HUD shows new charge level |
| 4 | Dead battery auto-stowed in backpack (if room) OR dropped | Caption: "Battery swapped; old battery in inventory" |

**Battery health degradation:**

- Each full cycle (100% → 0% → 100%) degrades health by 0.1%
- Health < 80% = "End-of-life" warning
- Health < 50% = capacity reduced (e.g. T1 1.0 kWh → 0.5 kWh effective)
- Recycle option: bring degraded battery to fabricator → recover 50% materials

**Failure modes:**

- **Battery rupture** (puncture damage per M5.5 + M2.5 fluid system): electrolyte leak → slippery hazard tile + acid burn risk per M5.6 reactions
- **Thermal runaway** (overcharge + heat from M5.9): fire hazard at battery + adjacent terrain
- **Voltage mismatch** (LV battery + HV equipment): equipment refuses; clear error UI
- **Cable break**: charging mid-session interrupted; battery retains current charge

**Events:**
- `power.actor_battery_changed { actor_id, from_kwh, to_kwh, reason }`

- `power.actor_battery_empty { actor_id }`
- `power.actor_battery_swapped { actor_id, old_pack_id, new_pack_id }`

### Deep simulation — circuit physics + protection devices + cascade math

The user demand: **"I'm a big fan of power generation and usage balancing — I live electricity!"**. M7.6 ships the electrical-engineering depth as a **first-class simulation** — not gameplay abstractions.

#### Real-world circuit equations applied per tick

Every cable segment in the grid graph is modeled as a discrete electrical element:

```rust
pub struct CableSegment {
    pub id: SegmentId,
    pub from_node: NodeId,
    pub to_node: NodeId,
    pub length_m: f32,
    pub voltage_class: VoltageClass,
    pub material: CableMaterial,                    // copper / aluminum / silver / superconductor / etc.
    pub cross_section_mm2: f32,                     // wire gauge
    pub temperature_k: f32,                         // affects resistance + breakdown risk
    pub damage_pct: f32,                            // 0=intact; 100=severed
    pub insulation_pct: f32,                        // 0=bare exposed; 100=full insulation
}

// Per-tick power flow per cable:
// Resistance = (resistivity[material] × length_m) / cross_section_mm2 × temperature_modifier
// Voltage_drop = current × resistance
// Power_loss = current² × resistance  (I²R heating)
// Cable_temp_delta = (power_loss × dt) / (specific_heat × cable_mass) - dissipation_to_ambient
// If cable_temp > insulation_melt_temp: insulation degrades + arc risk + ignition cascade
```

**Per-material resistivity table (Ω·mm²/m at 20°C):**

| Material | Resistivity | Temp coeff /°C | Melt temp K | Cost / kg | Notes |
|---|---|---|---|---|---|
| Copper | 0.0168 | +0.00393 | 1357 | 8 iron | Standard launch tier |
| Aluminum | 0.0282 | +0.00403 | 933 | 4 iron | Cheaper but higher loss |
| Silver | 0.0159 | +0.00380 | 1234 | 25 iron + 10 silver | Premium; lowest resistance |
| Gold | 0.0244 | +0.00340 | 1337 | 50 iron + 5 gold | Specialty; corrosion-resistant for hostile atmospheres |
| Superconductor (YBCO) | 0.000001 (below T_c=92K) | 0 | 1900 | exotic + cryogenic | Zero loss below critical temperature; M8.5 Material Lab unlock |
| Tungsten | 0.0560 | +0.00450 | 3695 | 30 iron + 8 tungsten | High temperature; used in heating elements + reactor components |

#### Heat dissipation per cable (real thermodynamics; M5.9 + M7.5 integration)

- Cable runs through atmosphere → convective heat loss
- Cable in vacuum → only radiative heat loss (much slower)
- Cable through liquid (coolant pipe routing) → much faster heat removal
- Cable buried in terrain → conducts to terrain temperature
- Cable in fire (M5.7 hazard) → heat gain from fire; insulation degrades faster

**Cable failure modes (10 distinct):**

1. **Overcurrent** — `current > rated_amperage` → I²R heating → insulation melt → fault
2. **Overvoltage** — `voltage > insulation_breakdown_voltage` → arc-over → ground fault
3. **Insulation breakdown** — temp-driven over time; insulation_pct drops slowly
4. **Mechanical severance** — terrain collapse / explosion / digging through cable → open circuit
5. **Corrosion** (M5.6 reactions) — acid pool / saltwater / atmospheric corrosion → resistance climbs over time
6. **Animal/microbe damage** — rats chew bare cables (PvE survival flavor; M11.5)
7. **Lightning strike** (M7.7 storm) — direct or induced surge → cable + connected equipment damage
8. **EMP pulse** (M2.2A EMP grenade) — temporary disruption + permanent at high energy
9. **Solar flare induced surge** (M11.5 world event) — long-cable pickup; cascading equipment damage
10. **Phase imbalance** — three-phase systems (T3+) with uneven loading → harmonic damage

#### Protection device hierarchy

Power grid uses real-world protection hierarchy:

| Device | Function | Response time | Reset method | Tier |
|---|---|---|---|---|
| **Fuse (one-shot)** | Melts at over-current threshold; physical | 1 tick (instantaneous) | Replace fuse | T1 |
| **Circuit Breaker** | Trips at over-current; mechanical reset | 1-3 ticks | Manual reset OR IC10 auto-reset | T1 |
| **GFCI (Ground Fault)** | Detects current imbalance → leakage to ground | 1 tick | Auto-reset after 5s if fault clears | T2 |
| **Arc-Fault (AFCI)** | Detects arc waveform | 2-5 ticks | Auto-reset | T2 |
| **Surge Protector (TVS/MOV)** | Clamps over-voltage spikes | sub-tick (clamping) | Auto-recovery; degrades over use | T1 |
| **Differential Protection** | Compares input/output current of generator | per tick | Auto-recovery | T3 reactor-tier |
| **Lockout-Tagout System** | Player-initiated full shutdown for maintenance | instant | Manual unlock | T1 (player tool) |
| **SCADA Watchdog** | IC10 monitoring program | configurable | Reset script | T2 (IC10-only) |

**Cascading failure mathematics:**

When a breaker trips:
```text
1. Affected segment loses power (current=0)
2. Connected loads' power_pct drops to 0
3. Other generators in network must redistribute load
4. If redistribution exceeds their breaker thresholds:
   → ADJACENT BREAKER TRIPS
   → cascade propagates through grid
5. Cascade halts when:
   a. Load fits within remaining capacity
   b. Generators down to 0
   c. Grid fully isolated
```

Per-tick cascade visualization in HUD:
- Live red flash sequence on affected nodes
- Banner: "CASCADING FAILURE — 4 segments tripped"
- Player can see cascade graph in power overlay

#### Three-phase power (T3+ endgame)

Heavy industrial equipment (reactor coolant pumps, plasma forges, large fabricators) uses three-phase AC:

- 3 separate phase circuits (red / yellow / blue) at 120° phase offset
- Balanced load = no neutral current
- Imbalanced load → harmonic distortion → equipment vibration damage
- Three-phase motors run smoother + more efficient than single-phase
- Voltage class: medium (480V three-phase) and high (4kV three-phase)
- Player must balance loads across phases (UI shows per-phase load)
- Misconfigured phases → motor rotates backward; pumps reverse-flow (visible bug player can debug)

#### Power factor + reactive power (T4 exotic)

Endgame equipment introduces inductive vs capacitive load:

- **Real power (P)** — actual work done; watts
- **Reactive power (Q)** — magnetic field maintenance; vars
- **Apparent power (S)** — vector sum of P + Q; volt-amps

Most equipment has power_factor < 1.0 (motors, transformers, fluorescent lights at PF ~ 0.7)
Adding capacitor banks corrects power factor → reduces apparent_power → more available real_power
Endgame optimization: max P at minimum S

UI shows per-circuit power factor; player can add capacitor banks to optimize.

#### Capacitor bank — instant discharge for railguns / shield burst

Per Stationeers + Defcon Tunes capacitor patterns:

```rust
pub struct CapacitorBank {
    pub id: BankId,
    pub capacity_joules: f32,
    pub current_charge_joules: f32,
    pub max_discharge_w: f32,           // instantaneous burst max
```

**Capacitor discharge pattern:**
- Charges over time from grid (limited by ESR)
- On trigger (e.g. railgun fire): discharges in 50ms burst at max_discharge_w
- Lower voltage during discharge → gradually slower as charge drops
- Re-charge to full in 3-30s depending on grid availability
- ESR loss = heat (M5.9 integration)

UI shows bank charge as filled bar; pulsing when at full charge; dim red when below min_voltage.

#### Battery aging + cycle life (Stationeers + ONI parity)

Every battery has cycle life tracking:

- **Full cycle** = 100% → 0% → 100% counts as 1 cycle
- **Partial cycle** = 50% → 80% counts as 0.3 cycles
- **Cycle life** by tier: T1 = 500 cycles; T2 = 1000; T3 = 2000; T4 = 5000
- **Aging effect**: capacity drops linearly to 80% at cycle life threshold
- **Beyond threshold**: capacity drops faster + thermal runaway risk increases
- **Recommendation HUD**: when health < 80%, banner "Replace soon"
- **Recycle option**: bring degraded battery to fabricator → recover 50% materials

#### IC10 chip — complete instruction set for power management

Per Stationeers IC10/MIPS subset. Each IC10 chip has 16 registers (r0..r15), 128 lines of 90 chars each, 5 device pins (d0..d4).

**Launch IC10 instructions for power:**

| Instruction | Format | Effect |
|---|---|---|
| `lb` | `lb r0 d_device r0_param` | Load battery current_charge |
| `lbn` | `lbn r1 d_grid current_load` | Load grid current_load |
| `s` | `s d_breaker On 1` | Set device state (turn on) |
| `add` | `add r2 r0 r1` | r2 = r0 + r1 |
| `mul` | `mul r3 r0 0.5` | r3 = r0 × 0.5 |
| `bgt` | `bgt r0 90 trip_warning` | branch if r0 > 90 |
| `blt` | `blt r0 10 emergency` | branch if r0 < 10 |
| `j` | `j label` | unconditional jump |
| `yield` | `yield` | end of tick; resume next tick |
| `sleep` | `sleep 30` | wait 30 ticks |
| `slot` | `slot r4 d_chip d_pin_0` | access chip slot |
| `move` | `move r5 r4` | copy register |

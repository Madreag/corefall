# M1 — Actor Controller And Sim Core

## Status

`active`

## Intent

One human-piloted actor is fully playable on the native engine: moves, jumps, aims, fires, reloads, digs, swaps inventory, takes damage through a body-status state machine, and emits the full input → intent → sim → event ladder so every action is reachable from `cfctl` and verifiable in the run bundle.

## Player-facing behavior

- WASD moves the actor, mouse aims, click fires, R reloads, Space jumps, G digs, 1-4 select inventory slot, Backspace resets to spawn.
- The actor has a body-status state machine: STABLE → UNSTABLE → DOWNED → DEAD with cause labels for every transition.
- HUD shows ammo, status, selected item, last important event.
- Stability scalar (0.0-1.0) decreases on recoil and hard landings; recovers when grounded; below 10% the actor enters a knockdown stun.
- All inputs produce structured `input.intent_received` events with edge-trigger flags; the same sim path runs whether input came from human or `cfctl`.
- The actor can be played for at least 5 minutes without crashes, and the resulting run bundle replays headlessly with identical checksums.

## Acceptance criteria

```gherkin
Scenario: Solo play for 5 minutes without crash
  Given a fresh m1_actor_range scenario
  When the player moves, jumps, fires, reloads, digs, and swaps items continuously for 5 minutes (18000 ticks at 60Hz)
  Then no panic occurs
  And the run bundle's events.jsonl is well-formed
  And system.run_finished outcome=clean

Scenario: All control inputs emit input.intent_received with edge flags
  Given a running scenario
  When the player presses any of move/aim/fire/reload/jump/dig/select_item/reset
  Then an input.intent_received event fires within 1 tick
  And the event payload includes the edge-trigger flag for that action
  And clear_edges() runs after consumption so a press+release within one tick is not dropped

Scenario: Same sim path for human input and cfctl
  Given a scenario running under cf-app with a connected cfctl session
  When the player fires via mouse click
  And cfctl invokes act.player.fire
  Then both invocations route through cf-control's act.player.fire dispatch
  And both produce equivalent equipment.weapon_fired events
  And the recoil impulse + ammo decrement are identical

Scenario: Body status state machine with cause labels
  Given an actor at full HP
  When projectile damage drops HP below the UNSTABLE threshold
  Then actor.actor_status_changed fires with from=STABLE, to=UNSTABLE, cause="projectile_hit"
  When HP drops below the DOWNED threshold
  Then actor.actor_status_changed fires with to=DOWNED and a cause label
  When HP reaches 0
  Then actor.actor_status_changed fires with to=DEAD and a cause label

Scenario: Stability decreases on recoil, recovers on ground
  Given an actor with stability=1.0
  When the player fires the rifle
  Then stability drops by ~0.06 per shot
  When the player stops firing and stays grounded for 60 ticks
  Then stability recovers toward 1.0 at stability_recovery_rate per tick

Scenario: Knockdown stuns the actor
  Given stability < 0.1
  When the actor takes another destabilizing hit (recoil or landing impulse > 100)
  Then the actor enters Stance::KnockedDown for 18 ticks
  And during knockdown all input is rejected
  And the HUD STANCE line reads "KNOCKED_DOWN"
  And after 18 ticks control returns

Scenario: NaN/Inf input rejected with reason
  Given a running scenario
  When cfctl sends act.player.move with x=Infinity
  Then the engine rejects the command
  And emits control.command_rejected with reason="non_finite"
  And the actor does not move

Scenario: Edge-triggered jump within one tick is not dropped
  Given a grounded actor
  When act.player.jump is dispatched and consumed in the same tick
  Then exactly one jump impulse fires
  And clear_edges() does not drop the press

Scenario: 5-minute run bundle replays headlessly with matching checksums
  Given a 5-minute m1_actor_range run bundle
  When `cf-headless replay <bundle>` runs
  Then result=ok
  And every recorded checksum matches the live re-run
  And no first_divergence event fires

Scenario: HUD shows current state
  Given the player is firing
  Then HUD ammo line decrements per shot
  And the STANCE line shows current stance + stability label
  And the ITEM line shows the selected slot
```

## Notes for the implementer

- `IntentSource::Ai` exists as an enum variant but is not emitted at M1 (M1.5 introduces ReactiveGuard which uses a separate `EnemyTickReport` path). That's intentional.
- Stability quantizes into checksum bytes; do NOT change quantization granularity without bumping the checksum schema.
- `cf-app` keyboard binding goes through `cf-control` JSON-RPC even for local input (no shortcut path) — this is what makes the same sim path claim true.
- The 5-minute literal must actually be run + bundled. 60-second runs are not equivalent for the run-bundle checker (tick count + checksum cadence are real numbers in the manifest).

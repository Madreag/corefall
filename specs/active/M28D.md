# M28D — Per-Room HVAC + Climate Control + Multi-Zone Comfort Loop

## Status

`active`

## Intent

Stationeers-deep per-room HVAC kernel: ductwork + dampers + diffusers + intake/exhaust grilles + per-room thermostat setpoints + multi-zone climate management. Turns the M28B thermal modules (heaters / coolers / radiators) from standalone devices into a coherent climate-control system where the player assigns rooms to thermal zones with independent setpoints (server room -10°C, living quarters 20°C, reactor room tolerating 60°C, greenhouse 28°C with humidity 70%).

## Player-facing behavior

- **Per-room thermostat**: place a thermostat module in each room → assign target temperature + tolerance (e.g., living quarters 20°C ±2°C). System auto-cycles heaters/coolers to maintain.
- **Ductwork**: insulated air ducts route conditioned air between rooms; modular segments + bends + tees + reducers. Per-Stationeers segment connection rules.
- **Dampers**: motorized dampers in ducts can open/close to control flow to specific rooms — set via thermostat OR IC10 (M29A).
- **Diffusers + grilles**: room-side terminals where conditioned air enters (diffuser) or returns (grille). Per-tile placement.
- **Multi-zone presets**: "Combat Mode" (drops AC to save power), "Cryo Mode" (deep cold all rooms), "Hot Spring" (humidity + warmth). Templates saved/loaded per base.
- **Per-room HUD**: F7 toggle shows per-room temperature + humidity + CO2 + occupancy + thermal load + setpoint.
- **Comfort affliction tie-in**: actors outside their comfort zone for >5 min accumulate heatstroke/hypothermia (M16A producer).
- **Zone-aware AI**: bots respect zone setpoints; server-bot remains in cold room; medic bot warmer area; combat bots are zone-agnostic.

## Acceptance criteria

```gherkin
Scenario: Thermostat cycles heater to maintain setpoint
  Given a sealed living quarters with thermostat setpoint 20°C ±2°C
  And ambient 5°C; one electric heater connected
  When the room temp drops to 17°C (outside tolerance)
  Then thermostat triggers heater on
  And heater runs until temp reaches 22°C
  And thermostat shuts heater off
  And the cycle repeats with hysteresis

Scenario: Multi-zone setpoints maintained independently
  Given a base with 3 rooms: server (-10°C), living (20°C), reactor (50°C tolerance)
  And each room has its own thermostat + heaters/coolers
  When 600 ticks elapse
  Then all 3 rooms hold setpoint independently
  And zone interactions don't bleed (per ductwork isolation + insulated walls)
  And HUD F7 dashboard shows all 3 zones with green checkmarks

Scenario: Damper closes to isolate a room from system
  Given a base with conditioned air ducted to 4 rooms
  When player closes a damper to one specific room
  Then conditioned air bypasses that room
  And room temp drifts toward ambient (no climate input)
  And damper_actuated event fires
  And player must manually open damper or use IC10 chip

Scenario: Climate preset applies to entire base
  Given a player triggers "Combat Mode" preset
  When the preset applies
  Then all rooms drop their setpoints by 5°C (save power for combat)
  And HUD shows per-room "POWER SAVING — climate reduced"
  And climate_preset_applied fires
  And player can revert via "Standard Living" preset

Scenario: Duct segment blocked alerts player
  Given a duct segment damaged by combat or terrain shift
  When airflow through segment drops below threshold
  Then duct_segment_blocked fires
  And HUD overlay shows broken segment in red
  And downstream rooms lose climate control
  And player must repair (M28B breach_repair_tool variant)

Scenario: Room outside comfort triggers affliction tie-in
  Given an actor in a room at 45°C (above human comfort)
  When 5 in-game minutes elapse without leaving
  Then room_outside_comfort fires per actor
  And M16A heatstroke affliction starts accumulating
  And HUD shows actor warning "HEAT STRESS — leave room"
  And the same loop runs for cold rooms (hypothermia)

Scenario: Greenhouse zone with humidity setpoint
  Given a greenhouse zone with thermostat 28°C + humidity setpoint 70%
  When humidity drops below 60% (insufficient water in atmosphere)
  Then humidity_sensor triggers humidifier device
  And humidifier consumes water from base reservoir
  And humidity rises back to setpoint
  And plants in greenhouse benefit (M19 algae/plant farming output +20%)

Scenario: AI bot respects zone setpoints
  Given a server-room (-10°C) + a server-bot AI in the room
  When the bot considers its next action
  Then it does NOT leave the server room (zone-required AI behavior)
  And if temp drifts above -5°C, bot signals "ZONE FAILURE — request repair"
  And M22 squad doctrine can dispatch repair

Scenario: Determinism across multi-zone simulation
  Given two engines running m28d_multi_zone_drill with same seed
  When 600 ticks elapse with all 3 zones cycling
  Then identical thermostat_setpoint_changed event sequence
  And identical SaveBlob.checksum at tick 600
```

## Out of scope

- VFD (variable-frequency drive) heater/cooler modulation — M48+ realism (only on/off control in M28D).
- Per-tile micro-climate (heat conduction with neighbor-tile precision) — M28B owns that math; M28D reads it.
- Per-occupant body-heat output (humans contribute ~100W warming a small room) — M19F owns this.
- Air filter clogging in HVAC ducts — M28E owns base filter maintenance.

## Notes for the implementer

- Thermostat cycle uses hysteresis (default ±2°C) to avoid relay chatter; configurable per thermostat module.
- Duct flow rate calculations: per-segment area + length + roughness; per-Stationeers reference numbers (insulated duct = 90% throughput; uninsulated = 70%).
- Damper actuation has a 2s motor delay; deterministic on the same seed.
- Climate presets are RON-authored; modders extend; preset switching emits one event + cascades to per-room thermostat updates.
- Per-room thermostat IC10-controllable (per M29A IC10 chip editor); programmable schedules + multi-condition logic.

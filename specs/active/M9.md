
## Status

`active`

## Intent

**M9 is the Dedicated Server App + Determinism Islands milestone**. `cf-server` is a working dedicated server binary anyone can host. It runs core lifecycle and mode-selection paths against the same sim path the client uses. Determinism islands are real and testable. Replays from events alone reconstruct identical state. The M9 server-core subset from `spec/server-app-architecture` passes; M12 owns PvP/MMO scale acceptance.

M9 promise: **"the server is community property; anyone can host any mode; same sim path; no proprietary cloud lock-in."**

## Player-facing behavior

### `cf-server` binary

Per `spec/server-app-architecture` + DR-034:

- Thin entry point pulling `cf-sim-core` / `cf-terrain` / `cf-physics` / `cf-actor` / `cf-chassis` / `cf-equipment` / `cf-ai` / `cf-mission` / `cf-replay` / `cf-net` / `cf-control` / `cf-save` / `cf-mod`
- NO render / UI / audio crates (headless on Linux/Windows; macOS optional)
- 5 launch modes via `--mode`:
  - `coop_room` — 2-4 player private/public co-op
  - `pvp_arena` — 2-8 player server-authoritative PvP
  - `lan_room` — LAN-discovered co-op
  - `mmo_shard` — persistent long-running world (50-200 concurrent)
  - `lobby_directory` — public registry aggregating community-hosted shards

### `cf-server-ops` (operations layer)

- Config loader (RON; validated by `cf-mod validate`)
- Mode selector
- `/health` endpoint (liveness)
- `/ready` endpoint (readiness)
- Prometheus-compatible metrics endpoint
- Structured JSON logs
- Drain shutdown (graceful)
- Restart hooks

### `cf-server-persistence` (M9 minimum; M12 fills full MMO)

- Snapshot writer + event journal + restore loop
- Schema-versioned save format
- Migration handlers registered (per DR-029)

### `cf-server-anti-cheat` foundation

- Server-authoritative input validation
- Rate-limit hooks per input type
- Capability gates per action
- Audit log skeleton
- 3 launch anti-cheat profiles: `casual`, `competitive`, `tournament_strict`

### `cf-server-admin`

- Capability-gated `cfctl`-shape admin endpoints:
  - `kick <player_id>` — remove from session
  - `save <slot>` — manual save trigger
  - `restart` — graceful restart
  - `hot_load <scenario>` — load new scenario without full restart
  - `ban <player_id> <reason> <duration>` — add to ban list
- Per-server ban list (persisted across restarts)
- Server log streaming (replay events + chat + admin actions)
- Cheater outlier alerts streamed to admin via `cfctl observe.admin.alerts`

### Mod whitelist / blacklist (server policy)

- Server admin can whitelist OR blacklist mods per server config
- Trust tier policy: server can accept only `vanilla`, `verified`, `community`, `experimental` per its policy
- Per-mod-hash check on client connect
- Mismatch → clean diff UI shown to client; NO crash

### Per-server persistence (M9 minimum; M12 fills full MMO)

- Per-server scenario state save/load (M5+ save format)
- Per-server mod packs (loaded at startup; sync'd on client connect)
- Player progression sync across sessions on same server (level, perks, achievements)
- 5 launch server config templates:
  - `deathmatch` — pure combat (M12 PvP forward-compat)
  - `coop_campaign` — sequential mission progression
  - `pvp_arena` — competitive arena (M12 forward-compat)
  - `endless_wave` — wave survival (M11 endgame mode)
  - `sandbox` — open-ended mod / scenario testing

### Determinism islands

Per DR-052:
- Documented contract: which subsystems are bit-deterministic; which are stochastic-but-replayable; which are cosmetic only
- Validated via DET-A acceptance suite
- Replay verification: same seed + same inputs = byte-identical event stream

### Networking transport library

Decision LOCKED at M9 close: **`lightyear` vs `renet` vs `quinn`** (per DR-052 open gate).

- Worker presents transport options + perf evidence + adapter-trait shape to user BEFORE locking
- Adapter pattern allows future migration

### Reference Docker image

- Minimal `cf-server` Docker image for community deployments
- Documented in `docs/server-hosting.md`
- Tested on Linux + Windows
- macOS server build optional

### CLI Reference

`cf-server`:
- `--mode <mode>` — select mode
- `--config <path>` — RON config file
- `--bind <addr>` — listen address
- `--tick-rate-hz <N>` — sim tick rate
- `--seed <N>` — RNG seed
- `--mod-pack <id>` — load mod package

`cf-server-ops`:
- `--validate-config <path>` — pre-flight check

`cf-server-admin`:
- `--kick <player>` / `--ban <player>` / `--save` / `--restart` / `--hot-load <scenario>`

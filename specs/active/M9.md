# M9 — Micro Reactor Defense Fun Slice

## Status

`active`

## Intent

**M9 is the reactor defense scenario milestone** — a playable 60-90 second `micro_reactor_defense` scenario proving M3 chunked terrain is fun in the player's hands. After M9, players can dig a trench around a reactor, hold position while one reactive enemy attacks, win if the reactor survives 60s timer, lose if it explodes.

**M5 is its sister milestone** — it locks the canonical event surfaces for the deep damage / hazard / affliction / armor / internal / fluid / origin / atmospherics / shield / environment / thermal kernels that ladder up at M13/M14/M15/M16/M17/M19/M20. M9 ships the scenario; M5 ships the schemas.

Both close in BP3 alongside M6 + M7 + M8 + M4 + M10 + M11. BP3 closure gate runs across all 7 milestones.

M9 promise: **"defend the reactor for 60 seconds; the trench you dig matters."**

## Player-facing behavior

M9 is **the closure milestone for the live destruction loop**: terrain has visible per-pixel integrity, the reactor takes layered damage (External / Internal / Core armor), shields placeholder, hazard spawn surface, atmospheric venting surface, affliction surface. Every damage event from M9 forward emits the structured `combat.*` / `terrain.*` / `hazard.*` / `affliction.*` / `atmos.*` / `shield.*` event families so M4's taxonomy + M10's cause chains + M11's HUD readability all consume one truth. Event schema details live in `specs/done/M5.md`.

### Player narrative flow (60-90 seconds)

- Player spawns near a **generator core / reactor**. An **objective banner** reads "Defend the reactor for 60 seconds."
- The **reactor** is a single non-player static actor: HP, position fixed, no movement, no AI, **mission_critical=true** (per CCCP `m_MissionCritical`; cannot be gibbed instantly). It is the **predecessor of the future command-core** (DR-027 / DR-015) — the simplest defendable static actor we will ever ship. Its state surface is forward-compatible with M13+ chassis (armor layers, modules), M25+ command-core (power grid, shields), and DR-029 base-power identity (uproot/reroot, avatar core). At M9 `hp`, `max_hp`, `pressure_state`, `armor_layers` (3 layers: External / Internal / Core), `heat_signature_k`, and `mission_critical` are LIVE; `shields`, `modules`, `power_grid`, `uprooted_avatar`, and `affliction_overlay` are `serde(default)` placeholders.
- A **countdown timer** (default 60s = 3600 ticks at 60Hz; configurable) ticks down. The HUD timer changes color: green >30s, yellow 10-30s, red <10s. **Caption + banner warnings** fire at 30s, 15s, 5s ("30 SECONDS — HOLD" / "15 SECONDS — REACTOR STRESSED" / "5 SECONDS — HOLD THE LINE").
- One **reactive enemy guard** (reused from M2, unchanged) spawns and attacks. The guard picks its target (reactor vs player) using **utility scoring per DR-008**: weighted by proximity × line_of_sight × threat (player) + value (reactor). Player-aggressive guards target the player when in LOS; defensive guards target the reactor.
- **The player can dig a trench** around the reactor for cover/defense using M3's chunked terrain. The trench changes the guard's **path-cost lookups** — guard reroutes around the trench or fires over it depending on geometry. AI emits `ai.path_invalidated` when the player carves, then `ai.recovery_action` with reroute decision.
- **Reactor visual feedback** (per DR-055 + DR-003 hooks): bullet-impact **sparks** on the reactor's surface when hit; **sprite deterioration** as HP drops (5 visual states: pristine / scratched / cracked / critical / destroyed); **pressure-state HUD line** ("REACTOR: NOMINAL / STRESSED / CRITICAL / VENTING / DESTROYED"); **explosion VFX** on destruction (debris scatter, flash, screen shake scaled by player distance + accessibility's `reduce_camera_shake_pct`); **wound emitter pattern** per CCCP `MOSRotating::AddWoundExt` — every hit spawns an emitter at entry point (sparks/spall) AND exit point if projectile passes through, with state persisting on the sprite until repair.

### Destructible terrain — 5-tier HP color states + per-pixel integrity

Destruction is the simulation backbone players see directly. Every terrain pixel has integrity 0..1 tied to its `MaterialId`; visible decay is the readability surface for `try_carve` + `try_penetrate` decisions.

| Integrity band | Tint state | Visual cue | Material overlay color (in integrity mode) | Trigger event |
|---|---|---|---|---|
| **`Pristine`** (1.0) | Material's base color | Smooth | Full saturation | (no event — default) |
| **`Scratched`** (0.75-1.0) | Slight darkening + faint hairline crack overlay | 1-2 hairline cracks at impact origin | 80% saturation | `terrain.material_state_changed { from: Pristine, to: Scratched }` |
| **`Cracked`** (0.50-0.75) | Color shifted toward gray + branching crack texture | 3-5 cracks, debris dust on impact | 60% saturation | `terrain.material_state_changed` |
| **`Critical`** (0.25-0.50) | Gray tone + visible structural holes + spalling | Tile-edge holes, falling pebbles, dust cloud | 30% saturation + RED HALO | `terrain.material_state_changed { to: Critical }` + `ux.banner_raised` (warning) if mission-critical |
| **`Destroyed`** (0.0-0.25) | Tile removed (replaced by air/empty + falling debris) | Tile gone; nearby tiles shed pebbles via cascade rule | (no tile to color — material removed) | `terrain.pixel_removed { pos, was_material, cascade_cause? }` + `terrain.debris_spawned` |

**Per-pixel integrity is a `f32` field on `terrain.pixel_meta_grid` keyed by (chunk_id, local_pos)**. Damage from `try_penetrate` decrements integrity by `(impact_energy * material.softness_factor / material.hardness)`. When integrity crosses tier thresholds, a `terrain.material_state_changed` event fires. When integrity reaches 0, `terrain.pixel_removed` fires + the pixel becomes air. **Adjacent pixels of low-hardness materials may cascade** (M9 cascade default: `cascade_threshold=0.6`; `cascade_depth=1` — only direct neighbors checked); cascade events carry `cause: "neighbor_destroyed"` for full attribution.

**Per-material color signatures** (8 launch materials per DR-007 hybrid recommendation):

| Material | Pristine color | Hardness | Tier-crossing visual cue | Anchorable | Diggable |
|---|---|---|---|---|---|
| `dirt` | Brown #6b4226 | Low (0.2) | Crack to gray crumble; fast decay to Destroyed | Yes | Yes (fast) |
| `sand` | Tan #d4a373 | Very low (0.1) | Almost instant decay; tiles slough | No | Yes (fastest) |
| `concrete` | Light gray #b8b8b8 | High (0.7) | Hairline → branching cracks → rebar exposed at Critical | Yes | Slow |
| `metal` | Steel #707080 | Very high (0.9) | Scratched → dented → glowing edge at Critical | Yes | No (refuse_metal) |
| `basalt` | Dark gray #2c2c30 | Very high (0.95) | Pristine → flaked → cracked at Critical | Yes | No (nohook) |
| `glass` | Pale cyan #b0e0e0 | Low (0.15) | Pristine → cracked instantly → shattered (no intermediate tier) | No | No |
| `wood` | Brown-tan #8b6f47 | Medium-low (0.3) | Scratched → splintered → broken planks → burnable | Yes | Yes |
| `ice` | Pale blue #c0d8e0 | Medium (0.4) | Scratched → cracked → melting (heat coupling forward-compat) | No (slippery) | Yes (with heat) |

### 9 affordance flags per material (DR-007 launch set)

Per terrain pixel material, these flags govern interaction. Material overlay surfaces each via icon + text label:

| Flag | Meaning | Player-facing |
|---|---|---|
| `actor_passable` | Actors can walk through | Air, broken-tile, scaffold |
| `projectile_passable` | Projectiles can pass through | Air, glass (partial), thin material |
| `diggable` | Tool can carve (M3 `try_carve`) | Dirt, sand, concrete (slow), wood; opposite of `refuse_metal` |
| `anchorable` | Grapple/jet anchor allowed | Dirt, concrete, metal; opposite of `nohook` basalt |
| `blocks_light` | Vision obstruction | Solid + opaque tiles; glass=false |
| `contact_damage` | Damages actors on touch | Hot/cold/electric tiles; lava (M16+) |
| `path_cost` | AI pathfinding cost weight (1=easy, 10=hard) | Dirt=1, concrete=5, basalt=∞ (blocked) |
| `produces_debris` | Spawns debris pebble particles on damage | All materials except sand (which sloughs) |
| `produces_sound` | Plays material-specific impact sound | Metal=clang; concrete=thud; dirt=muffled |

These flags are exposed via `cfctl observe.terrain.material_at { x, y }` and surface to the HUD as a brief tooltip when the player hovers terrain with their reticle.

### Trench gameplay depth — partial cover + erosion

Trench mechanics get the **gradient cover** treatment M11's accessibility-friendly cover system requires:

- **Trench-depth indicator** (HUD): when player is inside a trench, a small chevron shows depth (1 pixel ≤ Shallow, 2-3 = Medium, 4+ = Deep) + caption "COVER: <state>"
- **Partial cover absorption**: projectiles passing through the trench wall lose energy based on remaining wall integrity at that pixel column (NOT binary; gradient absorption per `try_penetrate.energy_loss = impact_energy * (1 - (integrity * material.absorption_factor))`)
- **Trench wall erodes** as more rounds hit: integrity decay visible via terrain HP color cascade (Pristine → Scratched → Cracked → Critical → Destroyed); event `terrain.material_state_changed` per cross
- **Trench-floor moisture** (forward-compat M16): trench dug below water table fills with water (wet hazard tile); future surface
- **Trench-cover banner**: `TRENCH_INTEGRITY_LOW` warning when adjacent terrain reaches Critical (visible "cover failing" cue)

### Layered reactor armor — External / Internal / Core (CCCP forward-compat)

Even at M9 the reactor uses the **3-layer armor model** that M13 chassis inherits without renaming. Damage cascades through layers; HUD shows each layer's HP independently.

```text
External armor (60% of total HP, 0.9 hardness) — first to absorb
  ↓ when External HP = 0, breach event fires; damage routes to Internal
Internal armor (30% of total HP, 0.7 hardness) — secondary buffer
  ↓ when Internal HP = 0, breach event fires; damage routes to Core
Core (10% of total HP, 0.5 hardness) — the actual reactor; when 0 → Destroyed
```

**HUD shows 3 armor pip indicators** under the reactor HP bar: each pip filled to its layer's remaining HP %. Pips transition Pristine → Scratched → Cracked → Critical → Destroyed using the same 5-tier color signature as terrain (the player learns ONE damage grammar).

Per-layer event schemas (`armor.layer_hp_changed`, `armor.layer_critical`, `armor.layer_destroyed`, etc.) live canonically in `specs/done/M5.md` § armor.* family. This 3-layer model is the forward-compat surface for M13 chassis (CCCP-style 15-zone graph × 3 layers per zone) and M25+ base modules (each module is one logical zone × 3 layers).

### Outcomes — win / lose / abort / tutorial

- **HUD** shows: reactor HP bar (current/max + percent + 3 armor-layer pips), time-remaining timer with color, player HP, guard HP (when in sight), selected item, last-event ticker, **reactor pressure** line, **objective banner** with "0/60s elapsed", **affliction strip** (forward-compat empty at M9 baseline), **shield bar** (forward-compat None at M9), **atmospheric pressure indicator** (▲/▼ when delta), **trench-depth chevron** (when player in trench), **material overlay legend** (5-mode integration with M3).
- **Win** = reactor alive when 60s timer expires AND player alive. **Lose** = reactor HP reaches 0 (`loss_reason=ReactorDestroyed`) OR player dies (`loss_reason=PlayerDead`) OR player aborts (`Aborted`).
- Both outcomes emit a structured `mission.mission_resolved` event with full `parent_event_id` cause chain (loss: reactor_destroyed → reactor_hp_changed → wound_added → projectile_hit_mo → projectile_spawned → guard's weapon_fired → ai.target_acquired (reactor) → ai.tactic_chosen).
- **Tutorial-safety** (per DR-018 + DR-023): scenarios with `tutorial_safety=true` cap reactor HP at 1 with `pressure_state=Critical` instead of destroying — gives the player a save-the-day moment without restart. M9 defaults to `false`.
- On loss, the HUD offers a **"show me why" prompt** that hands off to M10 replay viewer at the divergence event (the projectile that landed the killing reactor hit).
- **Difficulty presets** (inherited from M2): `cakewalk` / `tough_crowd` (default) / `veteran`. Veteran has a faster-firing guard + lower reactor HP.

## Acceptance criteria

### Win + loss + abort + tutorial paths

```gherkin
Scenario: Win path with trench — terrain matters
  Given a fresh micro_reactor_defense scenario at tough_crowd difficulty
  When the cfctl script micro_reactor_defense_win.cfctl.json runs
  Then the player digs a trench around the reactor (terrain.terrain_carved.count >= 100 within the trench bbox)
  And the guard fires at the reactor but the trench breaks line-of-sight intermittently
  And ai.path_invalidated fires at least 2 times (proving the AI noticed the carve)
  And the reactor survives the 60-second timer (reactor.hp > 0)
  And mission.objective_completed fires for "defend_reactor"
  And mission.mission_resolved fires with result=won, parent_event_id=<objective_completed>
  And cf-e2e --expect mission.result=won, terrain.terrain_carved.count>=100, mission.reactor_alive=true passes

Scenario: Loss path — reactor destroyed with full cause chain
  Given a fresh micro_reactor_defense scenario
  When the cfctl script micro_reactor_defense_loss.cfctl.json runs (player provides no defense)
  Then the guard fires at the reactor (no LOS-breaking cover)
```

## Notes for the implementer

### Architecture rules

- **Reactor is a static actor**: no movement, no AI, no ControlIntent. Use the existing `ActorState` with `ActorKind::Reactor` so cf-replay's actor snapshot path covers it — do NOT invent a parallel reactor snapshot. The reactor's `mass = f32::INFINITY` so impulses never move it; HP-only damage routing per CCCP `m_MissionCritical` pattern.
- **mission_critical=true blocks instant gib**: per CCCP `Actor.cpp` mission-critical flag, the reactor cannot be one-shot. HP only drops through accumulated normal damage; pressure_state ladder steps through Nominal → Stressed → Critical → Venting → Destroyed.
- **Reuse ReactiveGuard unchanged**: per M2 spec rule. Add target_selection.rs that uses utility scoring (per DR-008 lean) — NOT a new AI variant. Target switching reactor↔player happens within the existing ReactiveGuard's Engaged state.
- **Single source of truth for trench-shape threshold**: document the threshold in `content/scenarios/micro_reactor_defense.ron` as a scenario-level constant. The cfctl scripts + cf-e2e expects all reference it by name (not literal).
- **Per CCCP BunkerBreach.lua proof-mission lessons**: scene-area contracts (Reactor Zone, Player Spawn, Guard Spawn, optional Extraction Zone) live in the scenario .ron; cf-mod validate enforces presence. Brain placement, attacker AI setup, win checks, objective arrows are all wired through cf-mission's typed manifest, NOT free-form script.

### Pitfalls / things that have bitten us before

- **Reactor as duck-typed actor**: don't add `if actor.kind == Reactor` branches everywhere. Use `mission_critical` flag + standard apply_damage path.
- **Trench threshold hardcoded**: must be a scenario-level constant.
- **Timer at 60Hz only**: at 120Hz the tick count doubles. Use seconds (real time) for the timer math, not ticks.
- **Forgetting parent_event_id for reactor_hp_changed**: M10's cause-chain walker returns ParentMissingFromBundle. Every damage event MUST link to the projectile_hit_mo that caused it.
- **Sparks/explosion not flagged cosmetic=true**: replay determinism breaks because cosmetic particle RNG drifts cross-platform.
- **Reactor never gibs**: if mission_critical=true is forgotten in the .ron, an explosion at M14+ could instant-gib the reactor.
- **AI ignores trench**: ai.path_invalidated must fire when terrain.terrain_dirty_region_batch intersects guard's path.
- **Reactor HP bar lags HUD at 120Hz**: HUD reads observation AFTER sim tick, never mid-tick.
- **No emoji in any HUD or replay text** (project rule).

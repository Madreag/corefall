`active`

## Intent

**M2.2C** is the **third (final) bridge slice** between M2.2B (AI + mission director) and M2.5 (reactor defense). It closes the **camera + UX + debug + localization + accessibility-extras + basic photo/replay/killcam** gap. After M2.2C, M2.2 ladder is complete and the game has production-quality UX polish before M2.5 ships reactor defense.

M2.2C's player-facing promise: **"the production-quality UX feels polished and accessible to everyone."**

### Pie menu — context-sensitive radial actions (M1 reserves; M2.2C fills baseline)

Per CCCP `Controller.cpp:280` + `AHuman.cpp:2962-3020`. M1 reserved the **CONTROLS CAPTURED HUD label** surface; M2.2C fills the **full ring UI**.

- Press `T` (default; remappable) → radial 8-slice menu opens; sim transitions to slowdown75 OR full pause (per Settings)
- 8 slices per default (M2.2C baseline; M5+ extends with chassis-specific slices):
  1. **Pickup** (E action)
  2. **Drop** (Q action)
  3. **Switch Weapon** (1-8 cycle)
  4. **Throw Grenade** (T action)
  5. **Melee Bash** (M action)
  6. **Deploy Bipod** (B action, when crouched/prone with bipod-compatible weapon)
  7. **Signal Squad** (signal_friendly + mark_waypoint)
  8. **Use Medkit** (heal self; M5+ chassis extends with chassis-specific repair)
- Per-slice **reason labels** for disabled actions (per CCCP `:2962-3020`):
  - "No Arm" — pickup disabled when arm destroyed
  - "Not Holding Anything" — drop disabled when slot empty
  - "Needs Digger" — context tool refusal
  - "Out of Range" — context proximity refusal
  - "No Grenade Equipped" — grenade throw disabled when no grenade in inventory
  - "Standing — Requires Crouch/Prone" — bipod disabled when stance prevents
- Reachable via keyboard (Tab through slices + Enter) + controller (D-pad rotation + South button)
- Visual: ASCII glyph + text label per slice (DR-012 monochrome readable)
- Events: `ux.pie_menu_opened`, `ux.pie_menu_slice_chosen`, `ux.pie_menu_closed`, `ux.pie_menu_slice_rejected { slice, reason }`

M5+ extends with chassis-specific slices (eject pilot / repair chassis / overclock / cockpit camera anchor / ability slots / brain_hop).

## Acceptance criteria

### Camera + game feel

```gherkin
Scenario: Smooth follow with lookahead
  Given player sprint right
  Then camera offset shifts forward (lookahead)
  And lerps to position over 200ms

Scenario: Hit-stop on impact
  Given melee hit OR AP round hit
  When hit lands
  Then camera.hit_stop fires for 100ms
  And per-frame time pauses (rendering continues)
  When Settings.hit_stop_enabled=false: no hit-stop

Scenario: Scope zoom (sniper ADS)
  Given sniper weapon equipped
  When act.player.scope_zoom fires
  Then camera.mode=Scope, FOV=30°
  And HUD shows scope reticle overlay

Scenario: Free-look (RMB hold)
  Given any actor
  When act.player.free_look_toggle fires
  Then camera.mode=FreeLook
  And camera follows mouse cursor
  Release: returns to Follow

Scenario: Slow-motion (game_speed_assist)
  Given Settings.game_speed_assist=Slowdown75
  Then sim runs at 75% speed
  And all events deterministic (replay-compatible)
  Slowdown25: 25% speed
  FullPause: 0% (menu only)
```

### HUD widgets

```gherkin
Scenario: 8-slot hotbar
  Given 8 items equipped
  When player presses 1-8 keys
  Then active slot cycles + HUD highlights

Scenario: Mini-map widget
  Given player at position (X, Y)
  Then HUD shows mini-map (256×256) top-right
  And player icon centered + enemies visible + waypoints marked

Scenario: Compass widget
  Given player facing direction X
  Then HUD shows compass top-center with cardinal letters
  And waypoint bearings shown

Scenario: Damage direction indicator
  Given hit from direction θ
  Then HUD shows red arrow on screen edge pointing toward θ
  And arrow fades after 1s
  When reduce_motion=true: no fade animation

Scenario: Stealth meter eye icon
  Given perception_overlay_enabled=true
  Then HUD shows eye icon with detection %
  When detection > 50%: caption "Spotted" surfaces

Scenario: Grenade arc preview
  Given frag grenade + player aiming
  Then translucent arc shown from hand to predicted impact

Scenario: Action prompt
  Given player near dropped item
  Then HUD shows "PRESS E TO PICK UP"

Scenario: Phase strip + branching banner
  Given mission running
  Then phase strip top of HUD (1=Setup, 2=Buildup, 3=Climax, 4=Debrief)
  Given branching trigger
  Then banner appears with options ("KILL or SNEAK")
```

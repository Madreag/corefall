# M38B — Localization Runtime Deep + RTL/LTR + Font Fallback + Dynamic Text Expansion + Voice-Line Sync

## Status

`active`

## Intent

M38B ships the **runtime authority layer** beneath M38A's production pipeline: deterministic right-to-left layout for Arabic + Hebrew, a per-language font fallback chain wired to the M9A asset pipeline, dynamic text expansion budgeting per UI widget so German (~1.3× English) and Japanese (~0.8× English) lay out cleanly with auto-truncation + ellipsis when over budget, full ICU MessageFormat resolver depth (plural rules + gender + culture-specific number/date/currency/list formatters), voice-line synchronization across 19 languages with per-language audio asset routing keyed off the active locale, per-language UI scale recommendations, locale-aware sort/collation order for in-game lists, and per-language string-injection sanitization that prevents player-supplied text from injecting markup or control codes into translated frames. M38A populated the keyed-string corpus; M38B is the resolver, layout, and runtime sync that turns those strings into a shippable user experience.

## Canonical ownership

Owns the runtime locale resolver, the bidirectional layout engine, the per-language font fallback chain, the text-expansion budget enforcer, the ICU MessageFormat runtime, the voice-line locale router, the locale-aware collator, and the per-language sanitizer. M38A defined the translation production pipeline (offline LLM batch translate + grader + community PRs); M38B defines the runtime contract (how those strings render, how voice routes per locale, how widgets cope with expansion). M37A multilingual voice synthesis produces per-language `.wav` per dialog line; M38B routes the player's selected locale to the correct asset bundle.

## Player-facing behavior

After M38B, the player experiences:

- **RTL layout for Arabic, Hebrew, and any locale flagged `bidi: rtl`** — HUD mirrors (action bar flips, ammo readout right-aligns, minimap rotates 180° optionally per-config); text direction reverses; bullet-time arrow keys map to logical (not visual) directions.
- **Per-language font fallback** — primary font missing a glyph cascades to fallback chain (e.g. Latin → Noto Sans → CJK → Arabic → Devanagari → Emoji) without a visible tofu box; M9A asset pipeline bakes per-language font subsets at install time.
- **Auto-fit text in fixed-size widgets** — when a translated string exceeds the widget's expansion budget (German ≤ 1.3×, Japanese ≤ 0.8×, Russian ≤ 1.25×, etc.), the engine applies (1) shrink-to-fit ≤ 90%, (2) ellipsis-truncate with hover-tooltip showing full text, (3) wrap-to-two-lines if widget allows; player never sees clipped text mid-word.
- **ICU plural + gender + culture formatting** — "1 enemigo herido" vs "3 enemigos heridos"; German "ein Soldat" / "eine Soldatin" / "drei Soldaten"; date `12/25/2027` (US) vs `25.12.2027` (DE) vs `2027/12/25` (JA); currency / number / list formatting per locale.
- **Voice-line plays in player's locale** — selecting `ja` routes Sgt. Reyes's bark to `voice/ja/sgt_reyes_advance.wav`; missing locale falls back to next-tier per `voice_fallback_chain` (ja → en) with audit event.
- **Per-language UI scale recommendation** — first-run wizard suggests CJK locales bump default UI scale by +10% (denser glyphs); Arabic suggests +5% for clearer letter-form discrimination; player can override.
- **Locale-aware sorting** — inventory + codex + leaderboard sort by ICU collation (Spanish ñ between n and o, Swedish ä after z, Chinese pinyin alphabetical) not byte order.
- **Player chat + mod-supplied text sanitized** — ICU placeholder syntax, markup, and control codes in player text are escaped before injecting into translated frames; a player named `{count, plural, one {pwn}}` cannot break the kill feed for other players.
- **Live locale switch is instant** — changing `locale` from `en` to `ja` re-resolves every visible string, re-routes the voice channel, re-binds the font chain, re-applies expansion budgets, and rebuilds RTL/LTR layout — within one frame, no restart.

## Acceptance criteria

```gherkin
Scenario: Live locale switch re-renders within one frame
  Given the player is in-mission with locale=en
  When the player runs `act.settings.set locale=ja`
  Then within one frame: every visible string re-resolves from ja.json
  And the voice channel rebinds to voice/ja/
  And the font chain rebinds to ja.chain.ron
  And the expansion budget reapplies (0.8× for ja)
  And `locale_changed` fires with from=en to=ja tick=<n>
  And no panic, no asset reload screen, no perceived stutter

Scenario: Arabic RTL layout mirrors HUD widgets
  Given the player switches locale to ar
  When the HUD renders the next frame
  Then the action bar mirrors left-to-right → right-to-left
  And the ammo readout right-anchors instead of left
  And bidi-aware text runs render with Arabic letterforms shaped correctly (initial / medial / final / isolated)
  And LTR-embedded English brand tokens ("Steam", "Discord") render in correct visual order via UAX-9
  And widgets flagged `mirror: never` (compass, minimap if so-configured) remain unmirrored

Scenario: Font fallback engages on missing glyph
  Given locale=ja and a UI string containing an emoji or rare CJK glyph absent from the primary ja font subset
  When the renderer requests glyph for codepoint U+1F525
  Then the font_chain probes ja → NotoSansCJK → NotoColorEmoji
  And the glyph renders from the first font in the chain that covers it
  And `font_fallback_engaged` fires with codepoint=<n> primary=<font> resolved=<font>
  And no tofu box (.notdef) appears on screen

Scenario: German overflow auto-shrinks then ellipsizes
  Given a 120-px-wide HUD label "AMMO" (en) translated to "MUNITIONSVORRAT" (de)
  And the widget's expansion budget is 1.3× (de)
  When the renderer measures the translated string
  Then if the rendered width is within 1.3× of "AMMO", render at full size
  Else shrink to 90% font scale once
  Else ellipsis-truncate at the widget edge and attach a hover-tooltip with full text
  And `text_expansion_truncated` fires only when truncation actually occurs
  And the user never sees mid-word clipping

Scenario: Japanese contracts within budget
  Given a settings tooltip "Reduce camera shake during explosions" (en, ~200 px)
  When translated to ja "爆発中のカメラの揺れを軽減します" (~160 px)
  Then the widget renders at native size (within 0.8× expansion budget)
  And no truncation event fires
  And vertical writing mode is NOT engaged (LTR horizontal by default per ui_scale_recommendations.ron)

Scenario: ICU plural + gender resolve per locale
  Given key "ui.enemy.spotted" with ICU template "{count, plural, one {1 enemy} other {# enemies}}"
  When count=1 with locale=en → resolves "1 enemy"
  When count=3 with locale=en → resolves "3 enemies"
  When count=3 with locale=ru → resolves "3 врага" (one / few / many / other Russian plural categories)
  When count=1 with locale=de + gender=feminine → resolves "1 Soldatin" via gender-aware variant
  And ICU MessageFormat parse errors raise `localization::Error::InvalidIcuTemplate` at content-bake time, not at render time

Scenario: Culture-specific date + number + currency format
  Given a settings panel rendering tick "1234567" and date "2027-12-25T08:30:00Z" and price "1234.50 USD"
  When locale=en-US → renders "1,234,567" / "12/25/2027 8:30 AM" / "$1,234.50"
  When locale=de-DE → renders "1.234.567" / "25.12.2027 08:30" / "1.234,50 $"
  When locale=ja → renders "1,234,567" / "2027/12/25 8:30" / "$1,234.50"
  And ICU NumberFormat + DateFormat + CurrencyFormat are the single source of truth (no custom parsers)

Scenario: Voice-line routes to per-locale asset, falls back deterministically
  Given a barked dialog event id="sgt_reyes.advance"
  When locale=ja and voice/ja/sgt_reyes/advance.wav exists
  Then `cf-audio::voice_locale_router` plays voice/ja/sgt_reyes/advance.wav
  When locale=ko and voice/ko/sgt_reyes/advance.wav does NOT exist
  Then the router walks voice_fallback_chains.ron (ko → ja → en) and plays the first present asset
  And `voice_locale_fallback` fires with dialog_id=<id> requested=ko resolved=en
  And the subtitle still renders in the requested locale (ko) regardless of audio fallback

Scenario: Locale-aware collation sorts inventory + codex
  Given an inventory containing items "ñandú", "noche", "naranja" with locale=es
  When the inventory list sorts
  Then the order is "naranja", "noche", "ñandú" (Spanish ñ collates between n and o)
  When locale=sv and items "ärlig", "äpple", "zebra"
  Then the order is "zebra", "äpple", "ärlig" (Swedish ä after z)
  And the sort key is stable across runs (deterministic)

Scenario: Player-supplied text is sanitized before ICU resolution
  Given a chat-message frame with template "[{player_name}] joined the squad"
  And player_name = "{count, plural, one {pwn}}<img src=x>"
  When the kill-feed renders the frame
  Then `cf-localization::sanitizer` escapes ICU control chars + HTML markup + ASCII control codes in player_name
  And the rendered text reads "[{count, plural, one {pwn}}<img src=x>] joined the squad" with all metasyntax neutralized
  And no second-pass ICU resolution treats player text as a template
  And the kill feed is identical for every other player regardless of the attacker's name

Scenario: First-run wizard suggests locale-appropriate UI scale
  Given the player selects locale=ja in the M33A first-run wizard
  When the wizard reaches the "UI scale" step
  Then the recommended default is 110% (per ui_scale_recommendations.ron)
  And the slider preview shows live ja-localized HUD at the suggested scale
  When the player selects locale=ar
  Then the recommendation is 105% AND the preview renders mirrored RTL HUD

Scenario: Determinism — locale change does not break replay
  Given a replay recorded with locale=en
  When the same replay is played back with locale=ja
  Then sim state (positions, events, checksums) remains byte-identical to the en playback
  And only the rendered strings + voice routing differ
  And `m38b_locale_runtime_matrix.sh` confirms replay determinism across all 19 locales

Scenario: Overflow audit CI gate catches clipped widgets
  Given a PR that adds a new HUD label "ENGAGE_RANGEFINDER_OPTICAL"
  When `m38b_expansion_overflow_audit.sh` renders the label in every locale at every supported UI scale
  Then if any locale exceeds its widget budget AND would truncate visible content (not tooltip-elided), the script FAILS the PR
  And the failing locale + widget + measured-width + budget-width are reported in machine-readable JSON
```

## Out of scope

- New translation content (owned by M38A).
- Voice synthesis production (owned by M37A); M38B only routes existing assets.
- Right-to-left game world geometry (no mirrored level layouts; only HUD + UI).
- Vertical writing mode for CJK (deferred; M38B keeps horizontal LTR for ja/zh/ko).
- Hebrew translation strings (engine RTL is ready; locale gated until M38A adds Hebrew batch).
- In-game keyboard IME hosting beyond Steam Input native CJK input (Steam Input is the contract per M38A).
- LLM-driven dynamic translation of player chat (chat sanitization only; no auto-translate).

## Notes for the implementer

- Use `icu` crate (ICU4X pure-Rust port) for plural rules, formatters, and collation; do NOT pull in any C++ ICU dependency.
- Bidi must implement the UAX-9 algorithm including isolate / embed / override markers (LRE, RLE, LRO, RLO, PDF, LRI, RLI, FSI, PDI); test against Unicode bidi conformance test vectors.
- Font chain probe must be lazy — do not iterate the entire chain on every glyph lookup; cache the resolved font per (codepoint, primary_font) pair with a `BTreeMap` (NOT `HashMap` with default hasher — sim determinism rule).
- Expansion budget enforcement runs at layout time, not at translation-bake time; this is so font scaling + UI scale interact correctly.
- Voice locale fallback chain MUST be ordered deterministically; round-robin or random fallback is forbidden.
- Sanitizer must run on **every** template-substituted variable, not just visible chat. Killfeed, achievement banners, tooltip-injected names, all of them.
- Locale switch hot-swap path must call `cf-render-2d::text_layout::invalidate_glyph_cache()` once; do not re-bake font subsets on the fly (that is install-time work).
- RTL mirroring is a transform on widget anchor + child layout order; it does NOT mirror raster sprites or scene geometry. Sprites that depict directional content (arrows, weapons) declare `mirror_with_locale: true` opt-in.
- Player-chat sanitization is the security boundary; treat any failure to escape as a P0 (kill-feed injection has been a real exploit class in shipping games).
- `m38b_locale_runtime_matrix.sh` is the canonical CI gate; runs per-PR; under 10 minutes for the 19 × 4 matrix using snapshot-image diff.

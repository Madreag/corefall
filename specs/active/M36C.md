# M36C — Server GPU Compute Path + Multi-Core Threading Model + Performance Budget Enforcement

## Status

`active`

## Intent

Lock the server-side GPU compute path + multi-core threading model + per-tick performance budget enforcement. Server minimum requirements include GPU + powerful CPU. Determinism preserved across multicore + GPU. CI gates enforce per-tick budget allocations across actor sim + AI sim + projectile sim + terrain + atmospherics + materials + render.

## Canonical ownership

Owns server hardware requirements, GPU compute integration, multi-core threading patterns, per-tick budget enforcement, performance regression CI gates. M8A baseline parallel determinism already in done; M36C extends to server-tier GPU + larger shard sizes.

## Player-facing behavior

- Server minimum specifications declared explicitly.
- GPU compute used for: M15B material kernel CA + M19 atmospheric kernel + cosmetic VFX particles + decals + per-pixel terrain damage + spalling fragments + smoke/dust simulation.
- CPU multi-core used for: actor sim + AI sim + projectile sim + atmospherics PV=nRT + per-tile heat transfer + collision detection.
- Per-shard simulation budget enforced; servers reject mod content that exceeds budget.
- Performance monitoring exposed via M36B telemetry.

### Per-tick performance budget (60 Hz wall clock = 16.6 ms total)

| Subsystem | p99 budget | Hot path |
|---|---:|---|
| Actor sim | 1.5 ms | `par_iter` over actor entities; pre-rolled RNG |
| AI sim | 2.0 ms | `par_iter` over guard entities; pre-rolled RNG |
| Projectile sim | 1.0 ms | `par_iter` with snapshotted terrain reads |
| Terrain mutation + dirty batch | 2.5 ms | per-chunk `par_iter`; deterministic (cx,cy)-sorted boundary post-pass |
| Atmospherics tick (M19) | 1.5 ms | `par_iter` over rooms; chunk-aware per-cell heat pass |
| Material CA (M15) | 4.0 ms (CPU) / 1.5 ms (GPU) | per-chunk `par_iter`; GPU dispatch on M15B path |
| Mission director | 0.2 ms | ECS resource tick |
| Recorder + checksum + merge | 0.5 ms | per-thread `RecorderShard` + canonical merge |
| Render dispatch (GPU offload) | 4.0 ms | WGSL compute particles + fragment-shader overlay + Texture2DArray |
| Rollback resimulation (when triggered; NOT per-tick) | ≤ 8.0 ms p99 | full 6-frame rollback resimulation budget, canonical per M8B. This is the wall-clock cap on a rollback event itself — it is rollback-resimulation-only, NOT a whole-tick allocation. M8B owns the algorithm + budget; M36C consumes the contract. |
| **Non-rollback per-tick total** | **≤ 15.5 ms** | sum of all non-rollback subsystems above; fits the 16.6 ms 60 Hz wall-clock for steady-state ticks |
| Headroom envelope for rollback within wall-clock | ≥ 7 ms | within the 16.6 ms wall-clock, after the 8 ms rollback resim budget is consumed, ≥ 7 ms remains for the steady-state subsystems that must still progress that frame |

### Determinism preservation (hard rules)

1. No `f64` in sim crates — `f32` only.
2. No `thread_rng()` in sim crates — engine's seeded RNG only.
3. No `HashMap` with default `RandomState` in sim state — `BTreeMap` or `FxHashMap`.
4. No FMA / wide AVX-512 intrinsics — stable `f32` path only.
5. No `Instant::now()` / `SystemTime::now()` in sim code — `Clock::tick().0`.
6. No `Vec::new()` / `HashMap::new()` per tick in hot paths — pre-allocate, clear-and-reuse.
7. Cross-thread state mutation MUST be per-worker buffer + deterministic merge, OR explicit single-threaded post-pass. Atomic-CAS loops forbidden.
8. GPU compute kernels MUST have CPU fallback path + per-tick parity validation (1/15 cadence).

### Multi-core threading model (Factorio pattern)

- **Snapshot phase** (single-threaded): snapshot read-only state.
- **Compute phase** (parallel via `rayon::par_iter`): per-entity / per-chunk work.
- **Commit phase** (single-threaded, deterministic order): merge changes back.

Per-subsystem parallelization:
- Actor sim: per-actor parallel (no inter-actor deps in compute phase)
- AI sim: per-bot parallel (snapshot world; commit deferred actions)
- Projectile sim: per-projectile parallel
- Terrain mutation: per-chunk parallel; deterministic boundary post-pass (cx,cy order)
- Atmospherics: per-room parallel; per-cell pass also parallelizable

## Acceptance criteria

```gherkin
Scenario: Server auto-detects tier on startup
  Given cf-server starts on reference platform (Ryzen 9 9950X3D + RTX 5090)
  Then tier_detection reports "Workstation"
  And GPU compute path enabled
  And perf_budget loaded for Workstation tier

Scenario: Per-tick budget enforcement
  Given a simulation tick at 200 actors + 500 projectiles
  When the per-tick pipeline runs
  Then per-subsystem times measured + p99 logged
  And total tick time ≤ 15.5 ms (p99)

Scenario: Budget exceedance triggers warning
  Given a stress test exceeding actor budget (1.5 ms)
  When the tick runs
  Then perf_budget_exceeded fires with subsystem=actor_sim duration=1.8ms
  And mod content flagged for removal

Scenario: GPU/CPU parity validated periodically
  Given GPU compute path active
  When the 1/15 parity check runs
  Then per-chunk material checksums match byte-for-byte (CPU vs GPU)
  And drift triggers cpu_fallback_engaged + halt

Scenario: Multi-core scaling
  Given 8-core CPU
  When actor sim runs with 200 actors
  Then `par_iter` distributes work across 7 worker threads (leaving 1 for OS)
  And total compute time scales near-linearly

Scenario: Determinism across servers
  Given same seed + same input run on 3 servers (Workstation / Apple Silicon / Linux VPS)
  When 1000 ticks elapse
  Then byte-identical event stream
  And SaveBlob.checksum identical

Scenario: Cosmetic backpressure under load
  Given GPU compute saturated (>100% load)
  When the per-tick render dispatch runs
  Then cosmetic VFX particles drop per backpressure rule
  And sim state unaffected
  And cosmetic_dropped event fires with reason="backpressure"
```

## Out of scope

- Multi-host server federation — M48+ scale.
- Cross-platform GPU compute (CUDA / ROCm / Metal abstraction) — wgpu handles.
- Per-mod resource throttling — M33 modding workbench.

## Notes for the implementer

- Tier detection uses CPU brand + GPU vendor + memory size; deterministic.
- Per-subsystem budget enforcement uses `Instant::now()` in tier detection ONLY (not in sim hot path); reported via cf-replay.
- GPU/CPU parity check uses per-chunk blake3 hash; deterministic.
- Cosmetic backpressure is opt-in via M8A cosmetic flag (already done).

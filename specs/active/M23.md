# M23 — AI MIND Layer

## Status

`active`

## Intent

**M23 is the AI MIND layer** — optional async LLM "mind" layer that proposes doctrine without blocking local AI per DR-008 hybrid model. After M23, AI agents can receive doctrine proposals from a remote/local LLM via JSON-RPC (cf-mind crate; sandboxed; non-blocking). Local AI always executes; LLM proposals are *advisory* and replay-recorded for analysis.

M23 promise: **"AI bots feel like they have a mind — they explain their decisions in plain language and propose tactical doctrine — without ever blocking the simulation."**

## Player-facing behavior

### MIND layer architecture

- `cf-mind` crate: async LLM client (configurable provider; OpenAI / Anthropic / local Ollama / etc.)
- Per-actor MIND ticks **every 5 seconds** (not every frame); fully async
- Local AI never waits for MIND response (rendered as advisory)
- MIND proposals: doctrine shift, tactical tactic, retreat decision, target priority, formation
- Local AI evaluates: high-confidence proposals accepted; low-confidence vetoed
- All proposals + outcomes recorded in replay (`mind.proposal_received`, `mind.proposal_accepted`, `mind.proposal_vetoed`)

### Interface pre-locked at M7 (cf-mind ships full impl at M23)

M7 lands the 5-layer AI thinking stack including a **Layer 5 LLM-prior interface** that feeds the M7 utility scorer. The interface is:

```rust
// in cf-ai (M7); cf-mind (M23) implements the producer side
pub struct DoctrineString(pub String);  // e.g. "defensive", "press_attack_north_wall", "retreat_and_regroup"

// Stored in BotMemory.doctrine_cache: Option<DoctrineString> (locked at M8A)
// Updated out-of-band by cf-llm-host (M23) at 5s per-bot tick
// Read by M7 utility scorer as a strong prior (boosts tasks matching the doctrine)
```

At M7, `doctrine_cache` defaults to `None` (LLM mind disabled). M7's utility scorer treats `None` as no prior. Players who enable LLM mind via `cfctl srv.set_cvar ai.mind.enabled true` get richer doctrine drift; players who don't see no perf hit. This means M7 ships **doctrine-aware bots without requiring the LLM** — the field exists, the utility scorer respects it, but cf-mind doesn't ship until M23.

M23 then ships the full `cf-mind` crate: producer process, configurable LLM provider, replay-recorded proposals, sandbox safety, no-API-key-required local Ollama path. M7 → M23 carry-forward is clean: no interface re-design.

### Doctrine proposal format

```json
{
  "actor_id": 42,
  "proposed_doctrine": "Defensive",
  "reason_label": "Player squad outnumbers us 3:2; recommend hold cover positions",
  "confidence": 0.85,
  "tactic_chain": ["seek_cover", "suppression_fire", "wait_for_reinforcements"]
}
```

### Sandbox + safety

- No file I/O, no network shell, no OS execute
- Rate-limited per actor (max 1 proposal per 5 ticks)
- Quota-aware (per-LLM-provider token budget tracked)
- Fallback to local AI when LLM unavailable / timeout / over quota

### AI Self-Test grading via MIND

- BP closure gate: AI-Agent Self-Test Report consumes MIND outputs to grade scenarios
- LLM grades replay bundles (debrief.md → MIND verdict)
- Verdict = Accept / Reject / Needs-Review

## Acceptance criteria

```gherkin
Scenario: MIND proposes doctrine
  Given AI with cf-mind enabled
  When per-actor MIND tick fires (every 5s)
  Then mind.proposal_received fires async
  And local AI continues without waiting

Scenario: Local AI accepts high-confidence proposal
  Given mind proposal with confidence=0.85
  Then local AI evaluates
  And if accept: ai.doctrine_changed fires with reason="mind_proposal_accepted"
  And mind.proposal_accepted fires

Scenario: Local AI vetoes low-confidence proposal
  Given proposal with confidence=0.3
  Then local AI vetoes
  And mind.proposal_vetoed fires with reason="low_confidence"

Scenario: Local AI when LLM unavailable
  Given cf-mind provider offline
  Then local AI continues normally
  And mind.unavailable_fallback fires

Scenario: AI Self-Test grades replay
  Given run bundle + MIND grader enabled
  When AI-Agent Self-Test runs:
    Then mind.report_generated fires
    And LLM verdict = Accept|Reject|Needs-Review
```

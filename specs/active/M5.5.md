
## Status

`active`

## Intent

**M5.5 is the full-collision + impulse-routing milestone** — the simulation backbone that turns M1-M5's surface contracts into real physical consequences. After M5.5, projectiles trace swept-volume collisions through actors + chassis + terrain + atmospherics; impulses route deterministically through joints; limbs detach via joint-strength thresholds; gib particles spawn with authored data; ragdoll-on-death feels physical; per-organ internal damage routing fires per the M2.5 contract.

M5.5's player-facing promise: **"the physics is real; the death animations are physical; the impact feels meaningful."**

## Player-facing behavior

### 2D side-view hit zone determination (consumes M5 zone AABB table)

When a projectile sweep-collides with an actor (per CCCP `Atom::Travel`), M5.5 determines WHICH zone takes damage via M5's per-stance zone AABB table.

**Pipeline:**

```text
1. Sweep collision (per M5.5): projectile path vs actor's overall AABB
2. Compute entry_point: where projectile first intersects actor body (world space)
3. Transform entry_point → actor local space (origin = actor.position)
4. Mirror local_x by Actor::facing (per M5 facing direction)
5. Iterate stance-specific zone AABB table (Standing/Crouching/Prone/Crawl per M5):
   - For each zone, test if (local_x, local_y) is within AABB
   - Use Y-position as primary cue (vertical zoning in side-view)
   - Use X-position to disambiguate near/far arms/legs
6. Multiple-zone hit: if ray continues past entry zone:
   - First zone takes primary damage
   - Reduced energy continues to next zone in ray path
   - Apply M2.5 armor + M5.5 ray traversal for each zone in order
7. Per zone, compute armor angle (M2.5) per zone's mount angle vs incoming direction
8. Apply per-zone damage routing per M2.5 + organ damage cascade per M5.5
```

**Multi-zone passthrough handling:**

When projectile penetrates entry zone and continues:

- Ray direction = projectile's velocity vector at penetration
- Energy reduces per absorbed_damage at entry zone
- Ray hits next zone behind first zone (along velocity)
- Per CCCP `Atom::Travel` extended for chassis: ray continues until energy = 0 OR exit through actor's backstop armor

**Stance-specific routing:**

- **Standing**: vertical Y-zoning primary (head=top, torso=middle, legs=bottom)
- **Crouching**: head harder to hit; torso primary target
- **Prone**: head/torso side-exposed in body's "front-direction"; legs at back
- **Crawl**: face-down; everything exposed from above; minimal from side

**Determinism:**

ALL zone hit determination is deterministic — no RNG. Per-stance AABB tables are FIXED per actor. Replay reproduces the exact zone hit pattern from seed + actor positions + projectile velocity.

### Full swept-collision pipeline (per CCCP `Atom::Travel` + `MovableObject::CollideAtPoint`)

- Projectiles trace swept-volume paths each tick (not snap-to-frame)
- Multi-actor hits routed via priority queue (closer hits resolved first)
- Per-tile penetration math: `impulse_squared > integrity_squared` (per CCCP `SceneMan::TryPenetrate`)
- Bullet sharpness decay per `MOPixel::Update` lethality range
- Stickiness check per material: projectile can become embedded in terrain
- Entry + exit wound positions tracked per CCCP `MOSRotating::AddWoundExt`

### Limb detachment via joint impulse (per CCCP `Attachable::Update`)

- Each joint has `joint_strength: f32` (force needed to break attachment)
- Each attachment has `gib_impulse_limit: f32` (force at which the attachable gibs instead of detaching cleanly)
- Damage propagates upward through `m_DamageMultiplier` weighting
- Joint failure path: when `joint_impulse > joint_strength` → `Attachable::GibThis` → spawn gib particles + scattered attachment + cleanup

**Visible consequences per CCCP body damage:**
- Arm lost: weapon dropped + grip invalidated + AI bot switches doctrine
- Leg lost: limp / crawl / jet failure
- Head destroyed: instant kill (mission_critical actors blocked by `mission_critical=true`)
- Multiple limbs lost: bleed-out timer (6 HP/sec per CCCP)

### Gib spawning with authored data (per CCCP `MOSRotating::CreateGibsWhenGibbing`)

- Each `Gib` entry has:
  - `m_GibParticle: Preset` — particle to clone
  - `m_Count` — number of clones spawned
  - `m_Spread` — angular spread in radians
  - `m_MinVelocity` / `m_MaxVelocity` — speed range
  - `m_LifeVariation` — lifetime jitter
  - `m_InheritsVel` + `m_InheritsAngularVel` — motion inheritance
  - `m_IgnoresTeamHits` — friendly-fire safety
  - `m_SpreadMode: SpreadRandom | SpreadEven | SpreadSpiral`
- Gib cascade per CCCP `RemoveAttachablesWhenGibbing`: when parent gibs, each child attachable gibs independently
- Gibs affect terrain (carve on impact), trigger alarm events (per CCCP `MovableMan::RegisterAlarmEvent`), apply screen shake (camera punch scaled by gib mass)

### Physics-driven limb damage scenarios (Cortex-Command-style limb loss)

The user demand: **"Physics, simulation, etc... is very important. falling can hurt legs, ramming can hurt limbs and parts, etc..."**. M5.5 ships the **full physics-driven limb damage simulation** complementing M5's functional consequences.

**Falling damage → leg joint impulse → potential severance:**

```text
1. Actor falls from height h
2. Landing velocity v = sqrt(2 * g * h)
3. Per-foot impulse on landing = mass * v (split between feet if standing)
4. Impulse propagates upward: foot → shin → leg
5. Each joint absorbs: joint_absorption = joint_strength * 0.7 (typical)
6. If joint_impulse > joint_strength after absorption:
   - foot first (lowest threshold ~500 N)
   - shin next (~1500 N)
   - leg next (~2500 N)
7. Severance triggers Attachable::Detached event chain
```

Per actor mass (humans 60-80 kg; powered armor 200 kg; light mech 4000 kg) → falling damage scales with mass.

**Falling onto hazardous terrain:**

- Spike trap → +50% impulse to landing foot
- Broken metal → +30% impulse  
- Soft material → -50% impulse (absorbs)
- Water → reduced impulse but drowning risk

**Ramming damage scenarios:**

- Chassis-to-chassis collision (e.g. mech-walking-into-wall):
  - Impact velocity × mass = impulse
  - Impulse routes to forward-facing zones (per Actor::facing)
  - Forward arm + forward leg take primary impulse
  - If impulse > joint_strength → severance

- Vehicle ramming infantry (M7+ vehicles):
  - Vehicle mass × velocity = high impulse
  - Multiple zones can sever simultaneously
  - Crew of rammed vehicle may also take impulse (cascade)

- Animal/melee ramming (M7+ creatures):
  - Bear/wolf charge → impulse on forward chest + arms
  - Heavy creature → potential severance

**Explosion proximity severance:**

- Explosion at distance d → impulse on actor ∝ 1/d²
- Multiple zones can be affected:
  - Closest zone takes biggest impulse
  - Per CCCP `DetachAttachablesFromImpulse`: nearest attachable severs first
  - Spread can sever multiple limbs simultaneously
- Per ammo type (M2.5):
  - Frag grenade: severance possible at 1-2m
  - Heavy explosive: severance at 3-5m
  - HE shell (M5+ chassis weapons): severance at 5-10m

**High-velocity projectile severance (sniper / APFSDS):**

- Kinetic energy = 0.5 × mass × velocity²
- If energy passing through joint > joint_strength
  - Joint severance + visible separation
  - Common for sniper round to sever arm at shoulder (with sufficient bullet mass)

**Heavy melee severance (chainsaw / katana / hatchet):**

- Per weapon, `severance_chance` field (0-1)
- Chainsaw: 0.4 chance per heavy hit (cutting damage_kind)
- Katana: 0.3 chance per heavy hit
- Hatchet: 0.15 chance per heavy hit
- Light weapons (knife / baton): 0 severance chance

Severance roll:
- `cutting_factor = weapon.severance_chance * (1 - joint_strength_normalized)`
- Roll vs cutting_factor; if pass → severance event fires
- Engine RNG (deterministic per seed)

**Side-view facing direction × hit routing:**

When projectile hits actor (per M5's side-view layout):

1. Compute `hit_direction = normalize(projectile_pos - actor_pos)` (vector toward actor)
2. Compute `relative_direction = hit_direction relative to Actor::facing`
3. Determine exposed zones:
   - If front-facing hit: front_arm, front_leg, torso_front
   - If back-facing hit: back_arm (was hidden), back_leg, torso_back, backpack
   - If top-down hit: head_top, torso_top, shoulders
   - If bottom-up hit: feet, legs, abdomen
4. Apply M2.5 angle math: `effective_thickness_mm = nominal / cos(impact_angle)`
5. Higher chance of armor angling defending if actor faces threat

**Limb-loss state machine:**

Per actor, track per-zone state:

```rust
pub enum ZoneState {
  Intact,      // full HP; functional
  Damaged,     // HP < threshold; partial function
  Critical,    // near severance; high bleed rate
  Severed,     // detached; visible at ground; functional consequence active
  Destroyed,   // gibbed beyond recovery (M5+)
}
```

Per zone, `zone.functional_consequence_active: bool` triggers based on state.

### Limb-loss visual feedback (side-view sprite update)

When limb severs:
1. Sprite removes the limb from current render
2. Limb spawns as physical debris with stable RecordId (M5.5 ragdoll)
3. Limb has its own motion (gravity + impulse from severance)
4. Visible blood spray (for organic limbs) at severance point — per CCCP `MOSRotating::AddWoundExt`
5. Per origin: red blood (human), oil (robot), synth-blood (android), bio-fluid (biomech)
6. M5.7 affliction.bleeding from severed limbs at high rate
7. Severed limb is salvageable (M5+ chassis salvage; can be picked up)

### Travel-impulse damage (UNSTABLE actors only; per CCCP `Actor::Update`)

- Formula: `damage = max((|impulse| - m_TravelImpulseDamage) / (m_GibImpulseLimit - m_TravelImpulseDamage) * m_MaxHealth, 0)`
- Triggers when actor velocity > `m_StableVel` AND another impulse is applied
- Stability state machine: STABLE → UNSTABLE → KNOCKED_DOWN → DYING → DEAD
- Recovery: `m_StableRecoverTimer > m_StableRecoverDelay` AND speed back below threshold

### Ragdoll-on-death (per CCCP physics-authority transition)

- DYING state triggers `physics.authority_changed` (animation → ragdoll)
- Body becomes physical debris (subject to gravity + terrain collisions)
- DEAD state: full ragdoll
- Drops carried items at hand position with toss velocity
- Drops gold pixels per CCCP `Actor::DropAllInventory`
- Ragdoll respects `reduce_motion` (skip ragdoll → static collapse)

### War Thunder-style penetration ray + spalling (M2.5 surface; M5.5 full impl)

Per M2.5's reserved penetration ray surface — M5.5 fills full ray traversal physics:

**Full penetration ray flow:**

```text
1. Projectile achieves penetration through outer armor (per M2.5 angled armor math)
2. Compute remaining_energy = projectile_energy × (1 - armor_absorption × angle_compensation)
3. Cast ray from impact_point along velocity_vector through chassis interior
4. For each module AABB intersected (in ray-order; per M5 chassis modules):
   a. Compute module damage = remaining_energy × module_damage_multiplier × (1 - module_armor_absorption)
   b. Apply damage to module
   c. remaining_energy -= damage_absorbed
   d. If remaining_energy ≤ 0: projectile stops at module
5. If projectile exits chassis backstop:
   a. Apply backstop armor check (re-run M2.5 angled armor math from inside-out)
   b. If penetrates: emerges from chassis other side
   c. If absorbed: stops at backstop
6. Spalling fragments spawn at impact point (if M2.5 spalling threshold met)
7. Each fragment: simplified ray (damage = 20-50% of original) hitting 1-2 modules
```

Events: `armor.penetration_ray_traversed { ray_origin, ray_direction, modules_hit: Vec<(module_id, damage, distance_traveled)>, final_resting_point, energy_remaining }`, `armor.spalling_fragment_spawned { fragment_id, direction, damage }`, `armor.spalling_fragment_hit_module { fragment_id, module_id, damage }`.

**Module ray-order priority:**

When multiple modules occupy the projectile's path:
- Damage applied first-hit-first
- Each module absorbs energy per `module_damage_multiplier × module_armor_absorption`
- Total energy budget conserves (no infinite penetration)
- Ammo rack hit → critical event firing chain (potential catastrophic detonation)

**HE round overpressure model (M5.5 addition):**

HE rounds don't only penetrate; they damage by radial overpressure:
- HE impact creates a pressure_wave centered on impact point
- Pressure wave applies damage radially (per material registry's `he_resistance_factor`)
- Internal modules within radius take fractional damage (no penetration needed)
- HE bypasses thin armor via overpressure; ineffective against thick / sloped armor
- Per CCCP `MOSRotating::GibThis` with HE-style cascade

Events: `armor.he_overpressure_wave { center, radius, damage_at_zero_distance, falloff_curve }`.

**HEAT (shaped charge) jet model (M5.5 addition):**

HEAT rounds create a focused jet that penetrates regardless of angle:
- Jet pierces armor at impact point with fixed penetration depth (per round's `heat_pen_mm`)
- Jet ignores ricochet (mostly; very steep angles still glance)
- Spaced Armor + Schurzen + Reactive Armor counter HEAT (pre-detonation + standoff distance)
- Jet damage falls off rapidly after impact (~5cm effective)

Events: `armor.heat_jet_penetrated { depth_mm, modules_hit }`, `armor.heat_jet_pre_detonated_by_era { era_panel_id }`.

**APFSDS (long-rod penetrator) model (M5.5 addition; M7+ chassis weapons):**

APFSDS rounds have:
- Long rod (high mass × high velocity = high kinetic energy)
- Minimum ricochet (designed for steep impacts)
- Penetrates RHA via long-rod momentum
- Damage path: long, narrow ray through modules
- Sabot petals discard before impact (cosmetic)

Events: `armor.apfsds_penetrated { rod_length, energy_remaining }`.

### Per-organ internal damage routing (M2.5 contract)

- When projectile passthrough_damage > heavy_damage_threshold (5 HP):
  - Roll internal_shock_probability based on (passthrough, impulse, ap_factor)
  - Select random organ/circuit weighted by hit_zone proximity to organ's mount_point
  - Apply (passthrough * internal_damage_modifier) to selected organ
  - Emit `internal.organ_damaged` (humans/androids) OR `internal.circuit_damaged` (robots)
- Explosion variant: route damage to 3 random organs in radius
- Per-organ failure cascade applies afflictions

### Hit-stop + camera punch + impact frame (per DR-055)

- Hit-stop on impact (50-200ms frame freeze; per-weapon configurable)
- Camera punch magnitude = recoil_impulse × (1 - reduce_shake_pct)
- Impact frame: brief 1-frame freeze on heavy hits (M4A reserves; M5.5 fills)
- All juice respects `reduce_motion / reduce_shake / reduce_flash` settings

## Acceptance criteria

### Full swept-collision

```gherkin
Scenario: Projectile traces swept path
  Given a projectile fired with high velocity
  When the projectile crosses multiple actors in one tick
  Then combat.swept_collision fires for each hit in priority order (closest first)
  And per-tile penetration evaluated for terrain crossings

Scenario: Bullet sharpness decay over distance
  Given a rifle shot at 100m (within effective range)
  Then damage_amount = base * (1 - distance/effective_range)
  And combat.bullet_sharpness_decay fires
  When the shot reaches 500m (past effective range)
  Then damage = 0; projectile despawns

Scenario: Bullet embedded in stickiness material
  Given a projectile hits a material with stickiness=0.8
  When the random roll < stickiness
  Then combat.embedded_in_terrain fires
  And the projectile becomes part of the terrain (no longer moves)
```


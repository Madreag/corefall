## Player-facing behavior

### Atmospheric modules (60+ base objects integrated)

Per `spec/atmospherics-and-chemistry-model`:
- **Pumps**: move gas/liquid between atmospheres (volumetric flow per power input)
- **Valves**: 1-way flow gates (closed/open)
- **Regulators**: maintain target pressure
- **Filters**: separate gas mixtures (route specific gas)
- **Condensers**: phase change (gas → liquid storage)
- **Airlocks**: pressure-gated transit (player passes; gas doesn't)
- **Vents**: open/close to ambient
- **Oxygen generators**: produce O2 from water electrolysis
- **Atmospheric scrubbers**: remove CO2
- **Life support panels**: monitor + display per-room state

### Pipe network construction

- Place pipes connecting modules
- Branch / merge / loop topology
- Network validated at place time (no broken connections)
- Per-pipe pressure + flow rate visible (debug overlay F6)

### Per-room state HUD

- Room overlay shows: composition (per-gas %) + temperature + pressure + occupants + connected modules
- Color-coded: green safe, yellow degraded, red dangerous

### Base damage scenarios

- Penetrating shot → aperture in wall
- Explosive → larger aperture
- Pipe rupture → atmospheric loss + spread to adjacent rooms
- Coolant leak → temperature equilibration
- Combustion in base → fire spread per material rules

### Base AI

- Per-base AI manages atmospheric subsystems
- Auto-shutdown of damaged systems
- Auto-airlock during breach detection
- Emergency reserve power activation
- Repair priority queue for damaged modules

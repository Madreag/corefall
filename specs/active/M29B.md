# M29B — Personal Equipment Power Datasheet

## Status

`active`

## Intent

Locked numeric per-equipment power-draw table for every actor-side powered item — turns M29's theoretical personal-grid into a real Stationeers-deep gameplay budget that the player can reason about and the AI can plan against.

## Player-facing behavior

- NVG draws 12W idle / 25W active — depletes a T1 1.0 kWh battery in ~40 hours of active use OR ~50 hours of mixed.
- Comm radio (M37) draws 8W idle / 80W transmitting — burst-talky players burn batteries faster.
- Jetpack (M14A) draws 0 W standby + spike per second of thrust scaled to fuel_drain × throttle (links to M14A `MIN_TIME_TO_BEGIN_THRUSTING_MS`).
- Heated suit draws 200W in -20°C ambient, 0W in 20°C ambient (auto-modulates per M19 thermal contact).
- Powered exoskeleton draws 50W idle / 150W during sprint / 300W during heavy lift — heavy weapons becomes battery-budget-limited.
- HUD widget shows per-equipment power consumption with priority drag-drop (M29A already wired the UX).
- Player + AI both observe the budget. A medic AI prioritizes carrying a charged spare battery if the squad's NVG cluster is < 30%.

## Acceptance criteria

```gherkin
Scenario: NVG + radio + heated suit drain a T1 battery in expected time
  Given a human actor on Mimas (-50°C) with NVG + radio + heated suit + T1 battery (1.0 kWh)
  When the actor walks for sustained operation (NVG 25W + radio 8W idle + suit 700W active for -50°C below 20°C)
  Then total draw = 733 W steady-state
  And battery time-to-empty ≈ 1000 Wh / 733 W ≈ 1.36 hours of game time
  And power.actor_battery_low fires at 30% threshold

Scenario: Auto-shed drops headlamp + helmet HUD first
  Given an actor at battery 28% with all equipment active
  When auto-shed triggers (default 30%)
  Then power.equipment_shed_due_to_battery fires for headlamp (luxury) first
  And helmet_hud (luxury) second
  And no `critical` equipment is shed
  And caption shows "Auto-shed: headlamp + HUD offline; reserve for combat"

Scenario: Sealed-suit life support cannot be auto-shed
  Given an actor in vacuum with sealed_suit_life_support active
  When battery drops to 5% (deep depletion)
  Then auto-shed CANNOT shed sealed_suit_life_support (priority=critical)
  And HUD shows "EMERGENCY POWER — critical only"
  And other systems offline
  And the actor must reach charging station before total empty

Scenario: Heated suit modulates power per ambient temperature
  Given an actor with heated_suit equipped
  And ambient temperature = 20°C
  When power.personal_grid_updated fires
  Then heated_suit draw = 0 W (auto-off; in comfort range)
  Given ambient drops to -10°C (ΔT = 30°C)
  When power.personal_grid_updated fires
  Then heated_suit draw = 300 W (10 W per °C below comfort)

Scenario: AI medic doctrine carries spare battery for low-charge squadmate
  Given a squad with NVG cluster at 28% battery + medic_ai_actor at full battery
  When the medic AI doctrine ticks (per M22 + M7)
  Then doctrine adds "carry_spare_battery_to_squadmate" to task queue
  And the medic walks to squadmate within proximity radius
  And initiates hot-swap on arrival

Scenario: Player observes per-equipment power draw via observe.actor
  Given an active actor with 5 powered equipment items
  When cfctl observe.once is called
  Then observe.actor.personal_grid contains:
    - total_draw_w (live sum)
    - battery_remaining_kwh
    - time_to_empty_minutes (estimated at current draw rate)
    - per_equipment_breakdown: list of (item_id, draw_w, priority_band, powered_state)

Scenario: Modder adds new equipment SKU with power draw
  Given content/equipment/power_draw_table.ron has 25 launch rows
  When a mod adds row { id: "thermal_sniper_scope", idle: 30, active: 100, peak: 200, peak_ms: 500, voltage: MV, priority: important }
  When cf-mod validate runs
  Then validation passes (all required fields present)
  And new equipment SKU loads at scenario start
  And per-actor mini-grid sums the new draw correctly
```

## Out of scope

- Per-equipment battery durability degradation per use (M29 already covers per-battery cycle count; not per-equipment).
- Per-shot weapon power consumption (rifle bolt cycling = mechanical, not electric; energy weapons handled separately by M14C).
- Solar panel placement on individual actor armor (mod-extension via M33).
- Mid-tick draw changes (changes apply at tick boundary for determinism).

## Dependencies

- M29 power kernel (active): personal grid algorithm + battery ladder + charging modes
- M29A power grid UX (active): personal power widget + hot-swap radial
- M17 origin reaction (active): per-origin behavior (human battery feeds equipment only; robot battery feeds body too)
- M14A walking sim (active): mass aggregation reads battery weight
- M19 atmospherics (active): per-cell temperature drives heated_suit / cooled_suit power
- M6 inventory (done): battery occupies 1 inventory slot

## Notes for the implementer

- Per-tick personal grid step runs ONCE per actor, ONCE per tick. NOT per-equipment-per-tick (that's quadratic). Sum first, then shed.
- The locked table above is the SHIP table — values can be tuned via balance pass post-M29B close, but the SCHEMA must be stable from M29B onward (modders rely on it).
- Cold/hot modulation for heated_suit / cooled_suit reads `cf-atmos::sample_cell(actor_pos).temperature_k` via the M14A sim-overlay stub then real M19 producer.
- AI doctrine `carry_spare_battery_to_squadmate` is M7 + M22 integration; M29B ships the trigger + reason label; the planner side is M7/M22 implementation territory.
- HUD widget for per-equipment draw extends M29A's `cf-ui-personal-power` (already NEW in M29A); M29B fills in the data binding.

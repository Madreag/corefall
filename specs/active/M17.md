## Player-facing behavior

### Cortex-Command-style "no HP bar" survival model (CANONICAL)

The user demand: **"actors don't have HP, they either have blood (human) or oil and energy (robot) or blood and energy (android)"**. Per CCCP body-damage-wound-gib-lifecycle research: Cortex uses `m_Health` but death triggers via wound emitters draining blood + decapitation + limb loss bleed-out. M17 makes this **fully explicit** — no abstract "HP bar"; instead, **per-origin survival resources** are the actual death triggers.

**Resource model — replaces master HP bar with per-origin survival resources:**

```rust
pub struct ActorResources {
  // SURVIVAL resources (depletion = death/inert)
  pub blood: Option<f32>,         // ml volume (humans / androids / heavy_biomech via bio_fluid variant)
  pub bio_fluid: Option<f32>,     // heavy_biomech variant; slow clot
  pub oil: Option<f32>,           // ml / liters (robots / androids' synthetic side)
  pub power: Option<f32>,         // joules / kWh (robots / androids' battery)
  
  // ACTION resources (low = ability degradation, NOT death)
  pub caloric_energy: Option<f32>, // 0-100 (humans / androids organic side)
  pub stamina: Option<f32>,        // 0-1 (M6 baseline)
  
  // ENVIRONMENTAL resources
  pub oxygen_supply: Option<f32>,  // seconds remaining (humans/androids in vacuum)
}
```

### Death triggers per origin (no abstract HP)

**Humans (blood-only survival):**

| Trigger | Condition | Result |
|---|---|---|
| `blood < 30% (1500 mL)` | bleeding wounds drain blood | actor.actor_status_changed STABLE → UNSTABLE; vision blur, slow movement |
| `blood < 10% (500 mL)` | continued blood loss | UNSTABLE → DYING; HUD vignette to 60%; can be saved by medikit |
| `blood = 0` | total blood loss | DYING → DEAD (per CCCP 1000ms dwell) |
| `brain destroyed` (M14 ray hit) | direct brain hit | instant DEAD (decapitation-equivalent per CCCP `AHuman.cpp:2620`) |
| `head destroyed` (M13 zone) | no head | instant DEAD per CCCP |
| `spine destroyed` (M14 organ) | paralysis cascade | UNSTABLE permanent; cannot recover |
| `both lungs destroyed` | respiratory failure | bleed-out 60s timer |
| `heart destroyed` | instant DYING (no recovery) | DEAD after 30s without intervention |
| `arms+legs all destroyed` | limbless | bleed-out at 6 HP/sec equivalent (per CCCP `AHuman.cpp:2620`) |

**Robots (power + oil dual survival):**

| Trigger | Condition | Result |
|---|---|---|
| `power < 30% (30 kWh)` | power drain | action cost increase: weapons fire 50% slower; mobility 75% |
| `power < 10% (10 kWh)` | severe drain | reserve mode: cannot fire heavy weapons; mobility 50% |
| `power = 0` | total depletion | INERT — cannot move/fire; NOT dead; repair tool revives |
| `oil < 30%` | joint degradation | mobility -25% per zone; joints stiffen |
| `oil = 0` | total depletion | joints seized; mobility = 0; cannot turn |
| `CPU destroyed` (M14 circuit hit) | core processor | instant INERT (with optional cascade to detonation) |
| `power_core destroyed` (M14 circuit) | core power | instant INERT; reactor venting cascade |
| `comm_relay destroyed` | communications | comms blackout; AI fallback to last orders |
| `oil_reservoir + heat critical` | fluid + heat cascade | engine ignition; chassis fire |

**Androids (hybrid; blood + power; either depletes = offline):**

| Trigger | Condition | Result |
|---|---|---|
| `blood < 20% AND power < 20%` | hybrid critical | DYING |
| `blood = 0` (organic side total) | bleed-out | offline (organic side dead); robot side still has limited function |
| `power = 0` (synthetic side total) | power empty | offline (synthetic side dead); organic side can still bleed |
| `BOTH blood = 0 AND power = 0` | full destruction | DEAD |
| `brain OR CPU destroyed` | core hit | instant DEAD (per origin) |

**Heavy biomech (bio_fluid + bio-energy):**

| Trigger | Condition | Result |
|---|---|---|
| `bio_fluid < 20%` | slow clot | UNSTABLE; self-repair starts |
| `bio_fluid = 0` | total | DYING (slow death over 60s; bio-regeneration possible) |

### Resource depletion mechanics

**Blood drain (humans / androids):**

- Per-wound `bleed_rate_ml_per_s` (per affliction.bleeding severity; M9 surface)
- Heart wound → +5 ml/s per second
- Femoral artery wound → +10 ml/s
- Light wound → +0.5 ml/s
- Clot rate per origin: human (1 ml/s natural; +5 from medikit); android (0.7 ml/s; needs synth-blood transfusion)
- Total blood drain rate = sum of all active bleeds - clot rate
- Per-tick: `blood -= max(0, total_drain_rate * tick_dt)`

**Oil drain (robots / androids synthetic side):**

- Per-fluid-leak `leak_rate_ml_per_s` (per M9 fluid system)
- Punctured fluid reservoir → +2 ml/s per hole
- Severed line → +5 ml/s
- Clot rate: 0 (oil doesn't clot; only repair tool stops leaks)
- Per-tick: `oil -= leak_rate * tick_dt`

**Power drain (robots / androids battery):**

- Base drain: action-cost per tick (fire weapon = 0.1 kWh; move = 0.02 kWh/s; sustain = 0.005 kWh/s)
- Damaged power_core drains additional 0.5 kWh/s + reduced regen
- Overclock drain: +2 kWh/s
- Per-tick: `power -= total_drain_rate * tick_dt`
- Recharge: at base station (kWh/s positive); battery swap at base (instant + full refill)

**Caloric depletion (humans / androids organic side):**

- Base drain: 0.1 caloric/s sustained (~5 hours per full 100 caloric stack)
- Action drain: +0.5 caloric/s during sprint; +0.1 during fight
- Hunger affliction at <20 caloric; -0.1 HP/s + slow recovery
- Restored by eating food (+10 caloric per food item)

### Caloric energy + battery + power resources

**Humans:**
- `caloric_energy: f32 (0-100)` — depletes via action + over time
- Hunger affliction at low levels
- Restored by eating food
- Affects: aim, sprint, attention

**Androids (hybrid):**
- `caloric_energy: f32` (organic side)
- `battery_charge: f32` (synthetic side; for installed modules)
- When battery empties: modules slow / lose abilities; basic mobility from organic side persists

**Robots:**
- `power: f32 (0-100)` — gates every action (move, aim, fire, observe)
- Recharged via base power, generators, salvage
- No power = inert
- Action cost rejection (cannot fire / cannot move at full speed) → eventually full inert

Resources visible in HUD (per origin-specific bar layout). Resource depletion triggers afflictions per origin matrix.

### Helmet + oxygen tank — vacuum scenarios

- Humans + androids in vacuum: REQUIRE sealed helmet + oxygen tank
- `oxygen_supply: f32` (seconds remaining) drains over time in vacuum
- Drain rate × consumption_modifier (running, combat, breathing rate)
- Penetrating round to sealed helmet → `helmet_breach` event → oxygen drains at 3× normal rate
- Vacuum without seal/tank → `affliction.hypoxia` stacks → unconsciousness → death
- Robots: vacuum-immune (sealed by design)

Equipment-side per `spec/equipment-loadout`:
- Helmets have `provides_seal: bool`
- Tanks have `oxygen_capacity_seconds: u32`
- `origin_compatibility` field rejects robot tanks (rejected at slot-assign)

### Robot internal shock + downclock + overclock

**Internal shock** (robot-only; M9 contract; M17 fills full mechanics):
- Each impact > impulse_threshold rolls damage onto random un-armored internal module
- Module damage independent of armor HP
- Module-failed cascades per CCCP `chassis_module_damaged{cause=internal_shock}`

**Overclock (voluntary boost):**
- Player or AI requests overclock tier (1-3)
- Boost: +action_speed (move, aim, fire, reload) per tier
- Cost: per-module heat + power drain
- HUD shows "Boosting" pip + heat ring
- Sustained heat damages modules at critical heat

**Downclock (involuntary throttle):**
- When `heat` crosses throttle band passively (ambient, sustained fire, friction)
- Action speeds reduced
- HUD shows "Throttling" pip (different from Boosting pip)
- AI doctrine: bot under involuntary downclock retreats from heat source

Both share the `heat: f32` accumulator + `chassis_module_damaged{cause=overheat}` path.

### Leak channels (M9 fluid system filling)

- Humans/androids: blood leak channel (already in M9)
- Robots: coolant + oil leak channels per M9 fluid system
- Heavy_biomech: bio_fluid leak (custom; slower clot)
- All ignition risk for combustibles
- Leak rate scaled by puncture severity

### Robot heat dissipation in vacuum

Per M19 atmospherics — vacuum body work:

- **Atmosphere** = robot heat dissipates naturally to ambient gas (heat transfer per ideal gas thermodynamics)
- **Vacuum** = no convection / conduction to ambient (only radiation; very slow)
- **Robot in vacuum without active cooling** → heat accumulates per active power use
- **Active cooling options**:
  - **Heat radiator surface** (large panels on robot back; passive radiation cooling; works in vacuum but slow)
  - **Cryogenic coolant loop** (Mimas/Europa native bonus; consumes coolant per M9 fluid system)
  - **Heat sink reservoir** (absorbs heat for limited time; full = throttle)
  - **Atmospheric cooling jacket** (small sealed coolant chamber)
- **If heat > 90% capacity** → **downclock** (involuntary action speed × 0.5)
- **If heat > 100%** → **meltdown risk** (per M14 ammo rack pattern; can chain-detonate)

### Per-origin death cascades — power + oxygen failure modes

**Human:**
- Battery empty → equipment offline (servo armor heavy; reticle disabled; etc.)
- Body still alive; can walk to base manually
- O2 empty → hypoxia (M19 affliction.hypoxic); 1-2 minutes to recover OR die
- Vacuum + helmet breached = decompression damage (per M17 helmet_breach event)

**Android (organic_fraction = 0.5):**
- Battery empty → synthetic parts offline; organic side functional (per organic_fraction)
- Can walk; can fire weapons (organic side); cannot use cybernetic enhancements
- O2 empty → organic side hypoxia; synthetic side keeps function
- Both empty → death (per M17 hybrid death model)

**Robot:**
- Battery empty → **INERT** (not dead; recoverable via repair tool + new battery)
- INERT state: robot slumps; vulnerable; can be salvaged by enemy
- Recovery: another actor brings new battery; repair tool brings robot to <50% health; robot fires up
- Vacuum heat overflow → throttle → meltdown if sustained

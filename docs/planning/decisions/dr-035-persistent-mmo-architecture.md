# DR-035: Persistent MMO Architecture

> [!success] Status: CLOSED-DIRECTION (project owner committed 2026-05-05)
> Persistent MMO shards are a full-product target mode of `cx-server` (DR-034), not a bolted-on afterthought. A shard is a long-running world hosting 50-200 concurrent players in a contract-and-base sandbox with persistent terrain, bases, faction state, named actors, salvage, and AI commander memory. Multiple shards run independently; cross-shard travel is via lobby/portal at v1, NOT seamless world. Anyone can host a shard. **Not subscription-funded.** M12 proves readiness; if the evidence fails, this DR reopens.

## Decision

**MMO is a `cx-server --mode mmo_shard` deployment with community-hostable persistent shards. Bounded scope: shard-with-portal, not seamless single-world.**

This DR replaces the prior "MMO experiment R&D only, post-launch" posture. The user's commitment on 2026-05-05 promotes MMO capability to a first-class architecture and roadmap target. M12 acceptance decides whether it is ready for public release; earlier milestones are not blocked on 50-100 client MMO proof.

## What This Locks In

| Aspect | Commitment |
|---|---|
| Scope | Shard-with-portal model. Multiple independent shards; cross-shard travel via lobby/portal; **NOT** seamless single-world MMO. |
| Player count target | 50-100 concurrent (`community` + `regional` tiers); 100-200 (`flagship`) is stretch; 200+ (`experimental`) is moonshot. |
| Persistence | Snapshot store (compressed binary) + append-only event journal per shard tick. Recovery = snapshot + journal replay. |
| Persistence cadence | Default snapshot every 10 minutes; journal flushed on every objective change and at minimum once per second. Operator-tunable. |
| World scope | Per-region chunk persistence; carved/repaired terrain persists. Bases persist (DR-027). Veterans + faction state + commander memory persist. |
| Account model | Required for **public** shards; **NOT** required for private LAN/co-op rooms. Token-based; pluggable provider; never written to run bundles. |
| Identity scope | Account id resolves across shards a player has been admitted to. Per-shard veteran rosters; no cross-shard veteran transfer at v1. |
| Mission director in MMO | Per-faction contract pool generated by mission director (DR-017). Players accept contracts; persistence resumes them across sessions within configurable timeout. |
| Anti-cheat profile | Default `competitive` (between `casual` and `tournament_strict`). Operator-tunable per shard. |
| Modding | Operator declares per-shard package set + trust tier ceiling; clients see manifest before join; mod hash mismatch produces actionable diff. Server-only mods allowed. |
| LLM mind | Workers run server-side per DR-032; clients see reason labels only; redacted in client-visible event stream. |
| Storage | Local filesystem default (`./shard-state/<shard-id>/`); S3-compatible / network filesystem / durable journal adapters available. **No** hard cloud database dependency. |
| Hosting cost model | Operators host (community / company / partner). First-party first-party hosting is **optional, post-launch**. |
| Subscription | **Forbidden** for the base game. Operator-charged hosting fees are an operator decision, not the base SKU. |
| Cross-shard combat | **Forbidden** at v1. Reopens via DR amendment if a future direction warrants it. |
| Seamless world | **Forbidden** at v1. Multi-shard with portal is enough. |
| Auto-population (server bots dressed as players) | **Forbidden.** NPCs/AI are visibly AI; player count metric is humans only. |

## What This Does NOT Lock

- Specific concurrent-player ceiling for `flagship` and `experimental` tiers (TBD per M12 perf evidence).
- Specific snapshot/journal storage format (RON vs bincode vs CBOR; decided in M9/M12).
- Specific account-provider order (local + lobby_directory token are required; Steam/EOS/PlayFab adapters are post-launch shapes).
- Cross-shard *travel* details (UI/UX flow) — open within the lobby/portal model.
- Whether long-term first-party hosting eventually launches (post-launch business decision).
- Specific cosmetic/DLC strategy for MMO content (DR-031 still applies; expansions are separate from operator-hosted shards).

## What This Explicitly REJECTS

| Rejected Pattern | Why |
|---|---|
| Seamless single-shard world | Sim cost; out of scope for v1. Multi-shard is enough. |
| Cross-shard live combat | Latency / authority complexity; explicit anti-goal. |
| Subscription-funded MMO | Conflicts with DR-031 content economy. |
| Live cash shop / pay-to-win | Conflicts with DR-031. |
| Mandatory account at all multiplayer modes | Private LAN/co-op rooms must work without accounts. |
| Operator-imposed publisher hosting | Architecture must support community-hosted shards by default. |
| Real-money trading of in-game items | Out of scope for v1; future business decision, not technical. |
| Auto-population (bots dressed as players) | Forbidden; player counts are humans only. |
| Cross-shard veteran transfer at v1 | Open research; not a launch promise. |

## Why Not The Alternatives

| Alternative | Why Rejected |
|---|---|
| EVE-style single-shard universe | Sim cost; latency; way out of scope for v1. |
| WoW-style sharded continents with cross-realm | Operator cost; needs first-party hosting at scale. |
| Realms-style instance-only (no persistence) | Loses the contract/base/persistence promise. |
| Subscription MMO | DR-031 forbids. |
| MMO as moonshot-only / post-launch-only architecture | Prior posture; user's 2026-05-05 commitment elevates MMO to a first-class `cx-server` mode with M12 evidence gates. |

## Evidence Trail

- Project owner verbatim (2026-05-05): "...as well as the persistent MMO mode."
- Source patterns: Project Zomboid dedicated server (community hosting), Space Station 13/14 round-based persistence (local-shard model), EVE Online single-shard architecture (anti-pattern reference), WoW realm sharding (anti-pattern at our scale), Realms vs Bukkit (community hosting precedent), Star Citizen persistent universe (anti-pattern; over-scope).
- Cross-DR coherence: DR-027 base scope already commits to persistent base layouts; DR-022 humanlike AI commits to cross-mission commander memory; DR-018 consequence ladder commits to persistent named-actor state; DR-029 save model commits to versioned migration-safe persistence. All four feed naturally into MMO persistence.
- DR-031 economy posture: premium + free modding without subscription means MMO must be community-hostable.
- DR-026 team model: AI-augmented-solo team can't run a publisher-scale MMO ops; community hosting is the default.

## Risks And Mitigations

| Risk | Mitigation |
|---|---|
| Persistence corruption | Atomic snapshot writes (temp + rename); journal replay validates on restore; rolling backups; recovery test in MMO-002/003. |
| Sim cost at 100+ concurrent | Interest management; sub-region tick budgets; offload AI/LLM to background; degrade to 30 Hz; test in MMO-004/005. |
| Mod mismatch hell | Pinned package set per shard; clear diff UI; trust tiers; version migrations. |
| Bot / cheater wave | Anti-cheat profiles; input-rate limits; replay drift detection; ban list with appeal-out-of-game. |
| Operator burnout | Reference Docker images; minimal config requirements; community templates. |
| Account compromise | Token-based auth; rotation; rate limits on join; never log raw tokens. |
| MMO scope creep (toward seamless world / cross-shard combat) | Anti-goals enforced via this DR; cross-shard combat / seamless world require explicit DR-035 amendment. |
| Cost spirals for big shards | First-party hosting optional; operator-funded model preserved; reference deployments only. |
| Persistence schema drift | DR-029 migration handlers required; shard refuses to load incompatible schema without registered migration. |

| M12 MMO-007 | Mod hash mismatch produces diff; auto-download disabled by default. |
| M12 MMO-008 | Anti-cheat profile `competitive` rejects rate-spike client; ban list persists. |
| M12 MMO-009 | Interest management: client only receives in-range events. |
| M12 MMO-010 | LLM mind workers run server-side; clients never see prompts. |
| M12 MMO-011 | Schema migration: v0.1 shard state loads on v0.2 with declared handlers. |
| M12 MMO-012 | Operator runs shard with no proprietary cloud dependency. |

## Revisit Trigger

- MMO mode cannot meet 50-100 concurrent floor on community hardware after M12 evidence.
- Persistence corruption proves intractable across crashes.
- Cross-shard live combat becomes a strategic priority (would amend this DR).
- DR-031 economy posture changes to allow subscription funding (would amend this DR + DR-031).
- A future first-party MMO hosting business decision elevates first-party hosting from "optional" to "required."
- Seamless single-shard world becomes feasible (would amend this DR; very high bar).
